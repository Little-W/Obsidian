# 01. 版本基准与学习准备

> [!abstract] 本章内容
> 解释 v0.24.0 与旧教程的差异，建立可复现环境，并给出阅读源码的方法。

## 一句话理解

把 TVM 看成一组可组合的 IR 变换与运行时模块，而不是一个只能按固定命令使用的黑盒工具。

## 核心要点

1. 主线 IR 是 Relax 与 TensorIR；v0.24.0 将旧 `tir` 代码组织拆成 `tirx` 与 `s_tir`。
2. Python 用于组织编译流程，C++ 实现大量核心数据结构、变换、代码生成与运行时。
3. 编译主机与执行设备可以不同，因此所有硬件特征都应由 Target 或编译配置显式提供。
4. 版本号、提交号、LLVM 版本、构建开关和 Python 环境必须一起记录。

## 逐项解析

### 1. 主线 IR 是 Relax 与 TensorIR；v0.24.0 将旧 `tir` 代码组织拆成 `tirx` 与 `s_tir`。

主线 IR 是 Relax 与 TensorIR；v0.24.0 将旧 `tir` 代码组织拆成 `tirx` 与 `s_tir`。 这一点之所以重要，是因为 TVM 的信息会在多个 IR 层次之间逐步变得具体。上一层没有保留下来的信息，下一层通常无法可靠恢复；下一层过早写死的选择，也会限制后续优化。初学时应在每次变换前后打印模块，找出函数、调用、属性、形状和 dtype 的变化。

实现时可执行的动作是：固定 TVM tag 或 commit，不在同一项目中混用 main 分支与发布版二进制。 建议同时保存输入 IR、输出 IR、Pass 配置、Target 和日志。若出现结果差异，先找到第一次发生结构变化的阶段，再向下检查，而不是从最终设备结果反推全部过程。

> [!warning] 本小节常见问题
> 旧文章常用 `relay.build`、旧 Pass 名称或旧目录，不能据此判断当前源码缺少功能。

### 2. Python 用于组织编译流程

Python 用于组织编译流程，C++ 实现大量核心数据结构、变换、代码生成与运行时。 这一点之所以重要，是因为 TVM 的信息会在多个 IR 层次之间逐步变得具体。上一层没有保留下来的信息，下一层通常无法可靠恢复；下一层过早写死的选择，也会限制后续优化。初学时应在每次变换前后打印模块，找出函数、调用、属性、形状和 dtype 的变化。

实现时可执行的动作是：保存 `tvm.support.libinfo()` 输出，确认 Python 包加载的是预期的动态库。 建议同时保存输入 IR、输出 IR、Pass 配置、Target 和日志。若出现结果差异，先找到第一次发生结构变化的阶段，再向下检查，而不是从最终设备结果反推全部过程。

> [!warning] 本小节常见问题
> 只记录 `pip freeze` 不足以复现本地构建，CMake 开关和本机 LLVM 同样重要。

### 3. 编译主机与执行设备可以不同

编译主机与执行设备可以不同，因此所有硬件特征都应由 Target 或编译配置显式提供。 这一点之所以重要，是因为 TVM 的信息会在多个 IR 层次之间逐步变得具体。上一层没有保留下来的信息，下一层通常无法可靠恢复；下一层过早写死的选择，也会限制后续优化。初学时应在每次变换前后打印模块，找出函数、调用、属性、形状和 dtype 的变化。

实现时可执行的动作是：阅读 API 时先看当前版本文档，再用 `rg` 找注册名和测试。 建议同时保存输入 IR、输出 IR、Pass 配置、Target 和日志。若出现结果差异，先找到第一次发生结构变化的阶段，再向下检查，而不是从最终设备结果反推全部过程。

> [!warning] 本小节常见问题
> 编译成功不等于运行设备可见；设备探测属于运行时检查。

### 4. 版本号、提交号、LLVM 版本、构建开关和 Python 环境必须一起记录。

版本号、提交号、LLVM 版本、构建开关和 Python 环境必须一起记录。 这一点之所以重要，是因为 TVM 的信息会在多个 IR 层次之间逐步变得具体。上一层没有保留下来的信息，下一层通常无法可靠恢复；下一层过早写死的选择，也会限制后续优化。初学时应在每次变换前后打印模块，找出函数、调用、属性、形状和 dtype 的变化。

实现时可执行的动作是：为自研后端建立最小模型集，避免首次联调就使用完整大模型。 建议同时保存输入 IR、输出 IR、Pass 配置、Target 和日志。若出现结果差异，先找到第一次发生结构变化的阶段，再向下检查，而不是从最终设备结果反推全部过程。

## 设计评审问题

1. 本阶段接收哪一种 IR，要求哪些属性已经存在？
2. 本阶段产生哪些新函数、属性、常量或模块？
3. 遇到不被支持的输入时，是保留给其他后端、报告编译错误，还是插入转换？
4. 哪些配置属于硬件固定限制，哪些配置允许自动搜索？
5. 如何证明重复执行本阶段不会产生额外变化？
6. 如何在日志中解释每个重要决定？
