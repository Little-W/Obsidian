# 05. TensorIR 程序表示

> [!abstract] 本章内容
> 从 PrimFunc、Buffer、循环、SBlock、归约维度和内存区域理解低层张量程序。

## 一句话理解

TensorIR 把一个算子展开为带有循环与缓冲区访问的程序，并保留足够的结构信息供调度器安全地改变执行次序。

## 核心要点

1. `PrimFunc` 是可独立编译的低层函数，参数通常对应缓冲区或标量。
2. `Buffer` 描述形状、数据类型、步长、偏移和存储区域。
3. `SBlock` 标出读取、写入、迭代维度和归约关系，是调度分析的核心。
4. 初始化块与归约更新必须被正确识别，才能进行归约拆分和局部累加。
5. 动态尺寸可以出现在循环范围和缓冲区形状中，但硬件后端必须说明接受范围。

## 逐项解析

### 1. `PrimFunc` 是可独立编译的低层函数

`PrimFunc` 是可独立编译的低层函数，参数通常对应缓冲区或标量。

阅读时先定位产生该信息的函数，再查找消费它的下一阶段。把两处代码和中间 IR 放在一起观察，比单独记忆类名更容易理解。

**实现建议：** 为矩阵单元先写一个清晰、未优化的 PrimFunc，再逐步施加调度。

> [!warning] 本小节常见问题
> 循环长得相似不表示可随意交换；依赖关系与归约性质必须满足要求。

### 2. `Buffer` 描述形状、数据类型、步长、偏移和存储区域。

`Buffer` 描述形状、数据类型、步长、偏移和存储区域。

把变换前后的 IR 并排比较，重点查看函数参数、调用、属性、StructInfo 和返回值。只记录最终 IR 会丢失变化发生的位置。

**实现建议：** 使用 `reads` 与 `writes` 检查访问区域是否符合预期。

> [!warning] 本小节常见问题
> 缓存区作用域名称必须与代码生成器和运行时对存储区域的理解一致。

### 3. `SBlock` 标出读取、写入、迭代维度和归约关系

`SBlock` 标出读取、写入、迭代维度和归约关系，是调度分析的核心。

实现时将硬件固定限制放入 Target 或能力文件，把用户可选策略放入编译配置；二者发生冲突时应报告具体字段。

**实现建议：** 对非整分块保留保护条件或填充策略，并把选择写入测试。

> [!warning] 本小节常见问题
> 只测试分块整除尺寸会遗漏尾部写越界和累加缺项。

### 4. 初始化块与归约更新必须被正确识别

初始化块与归约更新必须被正确识别，才能进行归约拆分和局部累加。

测试至少包含一个正常样本和一个只改变单一条件的反向样本。这样，结构或结果变化时能直接找到对应规则。

**实现建议：** 在引入硬件内建函数前保存调度 trace，便于复现。

> [!warning] 本小节常见问题
> 循环长得相似不表示可随意交换；依赖关系与归约性质必须满足要求。

### 05.A 本节要解决的具体问题

编写长度为 16 的向量加法，从循环、计算块、读写区域和缓冲区四个角度阅读同一段 TensorIR。

这类小例子的价值在于变量少、输出可直接观察。第一次运行时不要同时加入图改写、外部代码生成和真实设备执行；先确认当前层的输入与输出，再增加下一层。建议为本例新建独立目录，保存命令、标准输出、IR、编译产物摘要和环境信息。

### 05.B 示例一：最小可观察输入

**官方依据：** [TensorIR 抽象](https://tvm.apache.org/docs/deep_dive/tensor_ir/abstraction.html) 与 [TensorIR 创建教程](https://tvm.apache.org/docs/deep_dive/tensor_ir/tutorials/tir_creation.html)。

**v0.24.0 源码位置：** `docs/deep_dive/tensor_ir/abstraction.rst`、`docs/deep_dive/tensor_ir/tutorials/tir_creation.py`、`src/tirx/`。

```python
import tvm
from tvm.script import tirx as T

@T.prim_func
def add16(
    a: T.Buffer((16,), "float32"),
    b: T.Buffer((16,), "float32"),
    c: T.Buffer((16,), "float32"),
):
    T.func_attr({"tirx.noalias": True})
    for i in range(16):
        with T.sblock("add"):
            vi = T.axis.spatial(16, i)
            c[vi] = a[vi] + b[vi]

print(add16.script())
```

按以下顺序执行：

1. 在新进程中确认 `tvm.__file__`、动态库路径和 TVM 提交，避免受到旧进程注册状态影响；
2. 复制示例到单独文件，只补充示例明确要求的输入对象，不先加入额外优化；
3. 执行后保存完整输出；若生成 IR，同时保存 `script(show_meta=True)` 的文本；
4. 把输出与下面的预期现象逐项比较，不以“没有抛出异常”代替功能检查；
5. 重复执行一次并比较主要产物，确认结果没有依赖临时全局状态或未固定的遍历顺序。

> [!success] 预期现象
> 循环变量 `i` 表示执行顺序，块变量 `vi` 描述计算域。块的读写集合可由正文推导，也可显式写出。`noalias` 声明三个缓冲区不重叠，后端可以据此进行更积极的优化。

> [!tip] 如何阅读输出
> 先看对象类型和函数数量，再看属性、调用形式、形状与数据类型，最后看运行结果或编译产物。若前一项不符合预期，先停止后续步骤。这样能把问题限定在最早出现差异的阶段。

### 05.C 示例二：只改变一个条件

去掉 `noalias`，再让输出缓冲区与输入缓冲区共用存储。比较结果正确性和后端生成代码，理解别名信息为何会影响加载、存储和重排。

执行第二个例子时，复制第一个例子的输入与环境，只修改上文指出的一项。把两个输出做结构比较，并写下以下四个答案：

1. 第一次出现差异的是哪一个阶段？
2. 差异表现为函数、属性、形状、数据类型、编译产物还是运行结果？

### 05.D 改造成自研 NPU 示例

如果 NPU 只接收固定长度向量，可把 16 写入能力检查；如果硬件支持任意长度，则需要尾部处理。TensorIR 后端还要把缓冲区存储范围转换为 NPU 地址空间与 DMA 描述。

改造时建议保留三份相互独立的输入：最小 Relax 或 TensorIR、设备编译器输入、运行时调用输入。三份输入使用同一个样本编号，并记录转换前后的关键字段。这样可以分别测试 TVM 变换、NPU 编译器和驱动，不需要每次都运行完整模型。

至少补充以下样本：

- 一个完全满足能力要求的正向样本；
- 一个只改变数据类型的反向样本；
- 一个只改变形状或属性的反向样本；
- 一个包含主机与 NPU 混合执行的样本；
- 一个导出后在新进程加载的样本；
- 若支持动态尺寸，再增加最小值、常用值和最大值附近的样本。
