# 09. PackedFunc Module 与运行时

> [!abstract] 本章内容
> 说明 PackedFunc、runtime.Module、Tensor、DLPack、全局注册和最小部署运行时。

## 一句话理解

PackedFunc 是统一调用接口，Module 是一组可查询函数及其被导入模块，Tensor 是带设备和形状信息的数据容器。

## 核心要点

1. PackedFunc 用类型擦除方式跨 Python、C++ 与其他语言传递常见对象。
2. 编译器 API 与生成后的函数都使用同一注册和调用机制。
3. runtime.Module 可按名称取得函数、导入其他模块、保存并重新加载。
4. DLPack 允许与 PyTorch 等框架共享张量，是否零复制取决于设备与所有权条件。
5. 部署端可只链接较小的 TVM runtime，而不带完整编译器。

## 逐项解析

### 1. PackedFunc 用类型擦除方式跨 Python、C++ 与其他语言传递常见对象。

PackedFunc 用类型擦除方式跨 Python、C++ 与其他语言传递常见对象。 这一点之所以重要，是因为 TVM 的信息会在多个 IR 层次之间逐步变得具体。上一层没有保留下来的信息，下一层通常无法可靠恢复；下一层过早写死的选择，也会限制后续优化。初学时应在每次变换前后打印模块，找出函数、调用、属性、形状和 dtype 的变化。

实现时可执行的动作是：把 NPU 提交接口包装成粗粒度 PackedFunc，避免每个标量运算都跨接口调用。 建议同时保存输入 IR、输出 IR、Pass 配置、Target 和日志。若出现结果差异，先找到第一次发生结构变化的阶段，再向下检查，而不是从最终设备结果反推全部过程。

> [!warning] 本小节常见问题
> 返回指向临时内存的 Tensor 会在异步执行时产生难以复现的错误。

### 2. 编译器 API 与生成后的函数都使用同一注册和调用机制。

实现时可执行的动作是：规定 Tensor 所有权、生命周期、对齐和缓存维护责任。 建议同时保存输入 IR、输出 IR、Pass 配置、Target 和日志。若出现结果差异，先找到第一次发生结构变化的阶段，再向下检查，而不是从最终设备结果反推全部过程。

> [!warning] 本小节常见问题
> 运行时模块未实现保存函数时，内存内执行成功但导出失败。

### 3. runtime.Module 可按名称取得函数、导入其他模块、保存并重新加载。

runtime.Module 可按名称取得函数、导入其他模块、保存并重新加载。 这一点之所以重要，是因为 TVM 的信息会在多个 IR 层次之间逐步变得具体。上一层没有保留下来的信息，下一层通常无法可靠恢复；下一层过早写死的选择，也会限制后续优化。初学时应在每次变换前后打印模块，找出函数、调用、属性、形状和 dtype 的变化。

实现时可执行的动作是：实现模块的二进制保存与加载，并在新进程中测试。 建议同时保存输入 IR、输出 IR、Pass 配置、Target 和日志。若出现结果差异，先找到第一次发生结构变化的阶段，再向下检查，而不是从最终设备结果反推全部过程。

> [!warning] 本小节常见问题
> 函数名注册成功不表示参数协议正确，必须做类型与数量检查。
