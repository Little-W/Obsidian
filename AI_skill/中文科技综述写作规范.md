# 中文科技综述写作规范

本文档用于撰写技术调研报告、科技论文和研发立项材料中的文献综述。综述的任务不是证明查阅过多少文献，而是围绕具体技术问题，说明已有研究解决了什么问题、采用了什么方法、取得了什么结果、结论在什么条件下成立，以及这些结果与当前研究工作的关系。

## 1. 基本原则

1. 以技术问题组织文献，不按作者或发表时间逐篇罗列。可根据研究对象、技术方法、性能指标、应用场景或发展阶段划分段落。
2. 同一段落应具有明确的中心内容。段首说明该组文献共同研究的问题，段中比较各项工作的对象、方法和结果，段末归纳已解决的问题、适用条件或尚未解决的问题。
3. 优先阅读原始文献。涉及研究方法、试验数据和作者结论时，应核对摘要、试验章节和结论，不能依据搜索结果标题或二次转述推断。
4. 述与评必须分开。文献事实使用“提出、建立、测得、验证、表明”等词；报告作者的分析使用“由此可见、上述结果说明、对本项目而言”等词，不能把自己的推断写成原文结论。
5. 数据必须带有必要条件。准确度、带宽、不确定度、改善比例和误差等结果，应同时说明频率、电压、电流、功率、功率因数、样品数量或比较对象中的关键条件。

《上海交通大学学报》刊载的科技论文写作研究指出，综述应具有时间或分类逻辑，并分析文献与当前研究的关系，不能简单堆叠研究内容。南京大学中国社会科学研究评价中心也强调，综述应把既有研究的贡献、观点与当前课题建立明确联系。上述要求同样适用于工程技术调研报告。

## 2. 文献阅读记录

每篇文献至少记录以下内容：

- 研究对象：测量对象、设备、算法、电路或应用场景。
- 待解决问题：原有方法存在的具体误差、带宽、同步、资源或应用限制。
- 研究方法：电路结构、数学方法、校准方法、试验平台及对比方法。
- 关键条件：频率、电压、电流、功率、样品数量、传感器型号和校准条件。
- 主要结果：原文给出的定量结果或明确的定性结果。
- 作者结论：结果能够支持的结论及其适用范围。
- 局限：尚未验证的频段、通道数量、试验对象或工程条件。
- 与当前项目的关系：可直接采用的方法、需要重新验证的内容和不能外推的结果。

如果摘要没有给出足够信息，不应自行补全结论。应进一步查看正文；无法取得正文时，只表述摘要可以支持的内容，并使用“提出”“推导”而不是“验证”“实现”。

### 2.1 与项目的相关性审查

纳入综述的文献必须能够对应当前项目的研究对象、设计参数、测量方法或验证方法。仅有相同关键词，或者只在试验中把目标仪器当作普通测量设备使用，不能视为直接相关。

可采用以下三级分类：

- 直接相关：研究对象就是拟研制的同类仪器、输入单元、外置传感器、同步采样、功率计算、幅相校准或典型应用方法，研究结果能够转化为设计要求或试验项目。
- 方法相关：研究对象不同，但给出的校准、误差修正、同步、传感器评价或不确定度方法可以用于本项目。引用时必须说明可借鉴的方法和不能直接外推的条件。
- 背景相关：只说明行业发展、应用需求或一般原理，不能支撑具体设计决定。此类文献不应为了满足篇数要求列入核心综述。

每篇核心文献至少应回答一个项目问题，例如：需要设计什么电路、补偿什么误差、保存什么参数、验证什么指标或采用什么接线和试验条件。若无法回答其中任何一个问题，应删除或替换。文献篇数是筛选后的结果，不能成为降低相关性要求的理由。

## 3. 作者称谓

正文采用顺序编码制引用时，作者称谓按以下方式处理：

- 单作者文献写“唐仕彪提出……”或“Nakamura 提出……”，不加“等”。
- 两位及以上作者统一写“潘仙林等提出……”“Xin 等归纳……”“Ibuchi 等验证……”。正文不只写首位作者姓名而省略“等”。
- 同一处需要突出两项单作者工作时，可写“张宇和周晓铭分别……”。
- 不使用“有关学者”“国外研究人员”“某研究团队”等无法对应具体文献的称谓。
- 文后参考文献的作者著录仍按 GB/T 7714 执行，不能用正文中的“首位作者等”替代完整著录项。

## 4. 单篇文献的表述结构

介绍一篇实证或工程研究时，优先使用“对象—问题—方法—结果—结论”的结构：

> 作者等针对【对象】中的【具体问题】，采用【方法或装置】，在【关键试验条件】下获得【定量结果】；结果表明【原文能够支持的结论】<sup>[n]</sup>。

介绍方法论文时，应区分设计、推导和验证：

> 作者等提出【方法】，通过【理论推导、仿真或试验】分析【问题】。其中，【已验证内容】；【尚未验证内容】仍需在【条件】下确认<sup>[n]</sup>。

介绍综述论文时，应说明其覆盖范围和归纳结果：

> 作者等比较【技术类别】，从【比较维度】归纳各类方案的特点，并指出【共同限制或发展方向】<sup>[n]</sup>。

不得只写“作者对该问题进行了研究”“取得了良好效果”“为后续研究提供了依据”。这些句子没有说明工作内容，也不能让读者判断结论是否适用于当前项目。

## 5. 多篇文献的组织方式

### 5.1 按技术问题分类

工程技术综述宜优先采用分类写法。例如，功率测量仪相关文献可划分为：

1. 宽动态电压、电流采集；
2. 多通道同步计算与数据存储；
3. 幅值、相位校准与量值溯源；
4. 外置传感器及测量系统修正；
5. 变换器、电机和逆变器应用验证。

分类后应比较同类工作的方法差异，不能在每个分类下继续按“作者甲……作者乙……”机械排列。

### 5.2 按发展过程组织

只有在技术路线具有明确演进关系时才采用时间顺序。每个阶段应说明相对于前一阶段解决了什么问题，而不是只列发表年份。

### 5.3 按测量对象或工作流程组织

当报告面向一台仪器或一套试验系统时，可按照“输入调理—同步采样—数字处理—校准—应用验证”的工作顺序组织文献。这种结构便于把研究进展与产品研发项目对应起来。

## 6. 结论与评价

综述中的评价必须有文献事实支撑，并控制推断范围：

- “测得”“达到”“降至”用于原文给出试验数据的结果。
- “验证”用于原文确有试验、比对或第三方测试的内容。
- “提出”“设计”“推导”不能改写为“实现”“证明有效”。
- “表明”之后的内容必须能由前述结果直接推出。
- 不同论文的测试对象和条件不同时，不能直接比较数值高低，也不能把单通道、四通道或低速采集结果外推为八通道宽频整机性能。
- 段末评价应说明现有成果对当前项目可提供的方法，以及需要重新验证的指标。

推荐的段末写法为：

> 上述研究分别验证了【已有成果】，但试验对象在【通道数量、频率或功率等级】方面存在差异。对当前项目而言，仍需在【目标条件】下统一验证【待验证指标】。

## 7. 语言要求

1. 使用具体动词，避免“赋能、全面提升、形成体系、提供有力支撑、具有重要意义”等缺少事实内容的套话。
2. 不把摘要原句连续拼接为正文，应在保持含义和数据不变的前提下重新组织句子。
3. 一句话只承担一个主要判断。研究对象、方法、结果和评价较多时，应拆分为两句。
4. 数字、单位和符号应符合全文格式；比较数据必须写明比较对象。
5. 不使用“国内外研究较多”“已经取得丰富成果”等无法验证的总括性判断。
6. 第一次出现的专业缩写按项目术语规范处理；FPGA 等行业通用名称直接使用。

## 8. 引用要求

1. 事实、方法、数据和原作者结论后均应标注文献序号。
2. 一组角标只支持其前面能够明确对应的陈述，不将多个段落的全部引文集中放在段末。
3. 顺序编码制按文献第一次出现的次序编号，正文角标与文后参考文献必须一一对应。
4. 转述原文也必须引用。直接引语仅在措辞本身具有分析价值时使用，并控制篇幅。
5. 对同一数据优先引用原始论文，不以产品宣传、新闻报道或二手综述替代。

## 9. 审查清单

- [ ] 每个段落是否只有一个明确的技术主题？
- [ ] 是否说明了研究对象、问题和方法，而不是只列作者与题目？
- [ ] 是否给出了原文支持的结果和适用条件？
- [ ] 是否区分提出、推导、仿真、试验和验证？
- [ ] 多作者文献是否写为“首位作者等”？
- [ ] 单作者文献是否避免误加“等”？
- [ ] 是否比较了同类工作的差异或互补关系？
- [ ] 是否说明已有研究与当前项目的关系？
- [ ] 每篇核心文献是否至少对应一项设计要求或试验项目？
- [ ] 是否删除了只具有关键词联系、不能转化为项目内容的文献？
- [ ] 是否删除了没有事实内容的套话？
- [ ] 引文序号、角标位置和文后著录项是否一致？
