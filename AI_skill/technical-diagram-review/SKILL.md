# 技术插图绘制与检查

交付可读、可追溯且可稳定渲染的技术插图。适用于架构图、状态机、数据流、寄存器字段、接口时序和方案对比图；不用于以美术表现为主的示意插画。

## 图源与输出

- 含中文、寄存器名、指令或精确箭头关系的技术图，优先使用可编辑的 SVG、HTML/CSS 或其他代码原生图源。不要依赖图像生成模型生成文字或关键连线。
- 将 SVG 作为唯一真源。修改应发生在图源，随后重新导出 PNG；不要仅修补 PNG。
- 保持 SVG 的画布尺寸、`viewBox`、字体和颜色规则一致。导出 PNG 后确认实际尺寸符合文档版面需求。
- 文件名按文档图号和主题命名，例如 `图04-运行控制状态机.svg` 与同名 PNG；避免含糊的 `final`、`new`、`v2` 名称。

## 布局规则

- 先划分状态、模块、注释与图题的区域，再连线。箭头必须在标签和方框之外留有走线空间。
- 文本要么完整位于方框内部并留出明显内边距，要么完全位于两框之间的留白中；不得压住边框、其他文字或箭头。
- 当相邻方框之间容不下标签时，缩短术语、分成两行、移动标签或调整布局。不要让长标签从间隙伸入两侧方框。
- 状态名、模块名和字段名必须适配方框宽度；长英文标识可缩小字号或改为更短的状态名，但不得裁切或贴边。
- 图中命令、信号和寄存器名保持原文，例如 `haltreq`、`sbdata0`、`postexec`；普通解释文字使用文档指定的语言风格。

## 箭头与端点

- 每一条状态转换或数据通路都必须有可见的起点、连续路径、箭头头部和明确终点。文字标签不是连线的替代品。
- 箭头应接到方框的直边，而不是圆角区。对于 `rect(x, y, width, height, rx)`：
  - 左、右边端点的 `y` 应落在 `y + rx` 至 `y + height - rx` 之间。
  - 上、下边端点的 `x` 应落在 `x + rx` 至 `x + width - rx` 之间。
- 箭头方向必须与状态含义一致：请求从发起状态离开，确认或结果进入目标状态；回环必须重新接入该状态框，不得停在框外。
- SVG 箭头使用固定画布单位，推荐 `markerUnits="userSpaceOnUse"`。令箭头尖端的 `refX` 等于标记宽度、`refY` 位于标记高度中点，使尖端精确落在路径终点。
- 调整箭头大小时，同步调整 `markerWidth`、`markerHeight`、箭头路径坐标和 `refX/refY`。放大后必须再次检查：相邻箭头头部没有合并，箭头没有吞没边框或文字。
- 折线和回环的最后一段应指向目标方框；从下方接入时使用向上的最后一段，从左侧接入时使用向右的最后一段，避免“箭头碰到边框但方向错误”。

## 逐图检查流程

1. 在图源中列出所有有向关系，逐项核对路径起点和终点是否位于对应方框的有效边界。
2. 检查文字边界：标题、框内文字、连线标签、脚注和图题均不得互相重叠，也不得跨越边框。
3. 导出 PNG，并以实际阅读尺寸进行视觉检查。重点查看圆角附近、短间隙、回环、平行箭头以及长英文标识。
4. 发现问题时只修改图源并重新导出；每次修复后复查受影响的整张图，而非只看局部。
5. 将图片嵌入 Markdown/Obsidian 后验证附件存在且路径可解析。优先采用 Obsidian 原生嵌入：`![[相对 Vault 的路径/图.png|宽度]]`。

## 验收清单

- 每个箭头都从源方框有效边界出发，并在目标方框有效边界终止。
- 无悬空箭头、断开的折线、落在圆角外的箭头头部或方向错误的回环。
- 无文字压边、文字压箭头、文字越框、裁切、重叠或难以阅读的小字。
- 字段图的单元格尺寸统一，位号、名称和说明在对应单元格内对齐。
- 图题、图号和正文之间的间距符合文档排版要求；图题本身不与图片内容重叠。
- SVG 图源、PNG 导出文件和 Markdown/Obsidian 嵌入路径三者一致且存在。
