# 技术插图绘制与检查

交付可读、可追溯且可稳定渲染的技术插图。适用于架构图、状态机、数据流、寄存器字段、接口时序和方案对比图；不用于以美术表现为主的示意插画。

## 图源与输出

- 含中文、寄存器名、指令或精确箭头关系的技术图，优先使用 Draw.io、SVG、HTML/CSS 或其他可编辑矢量图源。不要依赖图像生成模型生成文字或关键连线。
- 将可编辑矢量文件作为唯一真源。修改应发生在图源，随后重新导出 SVG 和 PNG；不要仅修补导出文件。用户指定 Draw.io 时，保留 `.drawio` 源文件，SVG 和 PNG 只作为发布与检查产物。
- 保持 SVG 的画布尺寸、`viewBox`、字体和颜色规则一致。导出 PNG 后确认实际尺寸符合文档版面需求。
- 文件名按文档图号和主题命名，例如 `图04-运行控制状态机.svg` 与同名 PNG；避免含糊的 `final`、`new`、`v2` 名称。

## 布局规则

- 先划分状态、模块、注释与图题的区域，再连线。箭头必须在标签和方框之外留有走线空间。
- 文本要么完整位于方框内部并留出明显内边距，要么完全位于两框之间的留白中；不得压住边框、其他文字或箭头。
- 同一层级、同一语义类别的并列模块默认使用相同宽度和高度，并保持等间距对齐；只有文字量、接口数量或功能层次确有差异时才能采用不同尺寸。
- 方框尺寸必须由文字内容和必要内边距决定。不得用大面积空框承载少量文字，也不得通过过度放大容器或画布制造无效留白；压缩留白时仍须保留清晰的层次间距和独立走线通道。
- 框内文字应在可用内容区内水平、垂直居中。对于圆角矩形，可用内容区必须避开四角圆弧：文字外接框到四条直边均应有稳定内边距，且不得进入圆角切线以内的角部区域。
- 文字应在不破坏边界安全距离的前提下尽量放大并加粗。不得以缩小字号掩盖方框尺寸、换行或布局不合理的问题。
- 当相邻方框之间容不下标签时，缩短术语、分成两行、移动标签或调整布局。不要让长标签从间隙伸入两侧方框。
- 状态名、模块名和字段名必须适配方框宽度；长英文标识可缩小字号或改为更短的状态名，但不得裁切或贴边。
- 图中命令、信号和寄存器名保持原文，例如 `haltreq`、`sbdata0`、`postexec`；普通解释文字使用文档指定的语言风格。

## 颜色与对比度

- 深色背景必须使用白色或其他足够明亮的文字；黑色或深灰文字只能用于浅色背景。这是硬性要求，标题、说明、角标和图例均不得例外。
- 同一语义类别使用稳定的填充色、边框色和连线色。颜色用于辅助分组，不能作为唯一的连接关系或状态编码。
- 对比度必须在最终导出的 PNG/SVG 实际阅读尺寸下检查；编辑器中放大后可见不等于文档中可读。若文字对比不足，应先调整前景色或填充色，不得仅依赖描边、阴影或加粗补救。

## 系统架构图

- 系统架构图的首要信息是**层次、模块归属、连接关系和主数据流**，不是接口逐项清单。不得将系统架构图排成“发起方—接收方”的多行表格，也不得为每一条连接重复绘制同一个模块。
- 默认采用由上至下的层次布局：系统侧主控与存储目标、系统互连、NPU 顶层入口、命令与系统控制、任务调度、执行单元、片上存储。实际数据流若有旁路，应使用专用的侧边走线表示，不能破坏主层次。
- 外部系统、NPU 顶层和 NPU 内部功能组必须用具有标题的圆角容器区分；容器只表示归属，不替代模块方框。外部模块不得画入 NPU 容器。
- 每个主要模块在图中只出现一次。模块框内写模块正式名称和一行职责；寄存器地址、位域、队列深度、状态枚举等细节应留在相应章节或子模块图中，不堆入顶层架构图。
- 连接应能直接追踪：主控配置和命令进入 AXI Slave，命令依次进入命令前端和任务调度器，调度器向执行单元发射任务，执行单元访问 L1BUF；DMA 经系统存储接口和 SoC 互连访问系统存储。完成与状态返回必须有独立且方向明确的连接。
- 控制、状态和张量数据使用稳定且有说明的颜色。双向数据访问可以使用一条两端带箭头的连接；若请求和返回必须分别展示，应使用彼此分离的平行走线，禁止重叠。
- 总线互连只能作为明确命名的汇聚模块出现一次。不得为排版方便把同一总线画成两个互不相连的方框，也不得让总线方框成为遮挡其他连接的背景。
- 架构图应优先提高模块框的面积和文字字号；图例仅在颜色含义无法从图题和正文明确得到时保留，并置于主图留白区，不得挤压层次结构。

## 箭头与端点

- **箭头不得与其他元素重叠，这是硬性验收要求。** 箭身、箭头头部和转移条件的整体外接区域不得覆盖文字、方框、图例、注释、分区标题、其他箭头或其他连接线。除源节点和目标节点的边界接触点外，箭头路径不得进入任何图形元素的外接框。
- **禁止连接线互相交叉、共线重合或共用无法区分的转折段。** 若当前版面无法为每条关系提供独立走线，应重新排列节点、扩大画布、使用有明确定义的汇聚节点或拆分插图；不得用交叉桥、颜色差异或线型差异替代无重叠走线。
- 平行连接线之间必须保留可见间距，箭头头部之间也必须留白。不得让一条线沿另一方框边界行进，使读者误认为该方框是连接目标。
- **禁止小幅度连续弯折、微小折返和锯齿状走线。** 两个端点可以直接对齐时必须使用直线；端点的轻微偏差若会触发短折线，应调整锚点、模块位置或改用明确的直线连接，不能接受自动路由产生的小弯折。
- 正交连接中的每一段都必须承担清晰的绕行或对齐作用。相邻两个转折点之间的可见线段建议不短于 32 个绘图单位，并至少大于两个箭头头部长度或一行正文高度；未达到该尺度的短段应通过对齐端点、减少转折或重新布局消除。
- 一条连接应优先采用零个或一个方向明确的绕行通道。确需多次转向时，各段应形成长而清楚的水平/垂直路线；不得在端点附近连续插入两个或更多小折角。
- 每一条状态转换或数据通路都必须有可见的起点、连续路径、箭头头部和明确终点。文字标签不是连线的替代品。
- 箭头应接到方框的直边，而不是圆角区。对于 `rect(x, y, width, height, rx)`：
  - 左、右边端点的 `y` 应落在 `y + rx` 至 `y + height - rx` 之间。
  - 上、下边端点的 `x` 应落在 `x + rx` 至 `x + width - rx` 之间。
- 箭头方向必须与状态含义一致：请求从发起状态离开，确认或结果进入目标状态；回环必须重新接入该状态框，不得停在框外。
- SVG 箭头使用固定画布单位，推荐 `markerUnits="userSpaceOnUse"`。令箭头尖端的 `refX` 等于标记宽度、`refY` 位于标记高度中点，使尖端精确落在路径终点。
- 调整箭头大小时，同步调整 `markerWidth`、`markerHeight`、箭头路径坐标和 `refX/refY`。放大后必须再次检查：相邻箭头头部没有合并，箭头没有吞没边框或文字。
- 折线和回环的最后一段应指向目标方框；从下方接入时使用向上的最后一段，从左侧接入时使用向右的最后一段，避免“箭头碰到边框但方向错误”。
- 状态转移条件必须放在该箭头独占的直线段旁。若条件居中覆盖连线，必须使用与背景一致的不透明标签底色，在标签宽度内断开或遮蔽连线；标签不得进入任一状态框，也不得与另一条件、箭头或转折点重叠。

## 逐图检查流程

1. 在图源中列出所有有向关系，逐项核对路径起点和终点是否位于对应方框的有效边界。
2. 检查走线占用：逐条确认箭身和箭头头部没有穿过、覆盖或贴附任何非目标元素；确认不同连接线没有交叉、共线或共享箭头头部。
3. 检查走线形态：放大检查每个转折点和端点，消除短折线、小幅连续弯折、局部折返和无意义的锯齿；能直连的关系不得保留自动正交路由产生的微小偏移。
4. 检查文字边界：标题、框内文字、连线标签、脚注和图题均不得互相重叠，也不得跨越边框；重点检查圆角区域的文字外接框与边界安全距离，转移条件所在的保留区不得被其他连接线占用。
5. 检查版面与颜色：同层方框尺寸和间距应对称，方框大小与文字量匹配，画布和容器没有大块无效空白；逐项确认深色背景使用浅色文字、深色文字仅位于浅色背景。
6. 导出 PNG，并以实际阅读尺寸和放大尺寸分别进行视觉检查。重点查看圆角附近、短间隙、回环、平行箭头、密集汇聚区以及长英文标识。
7. 发现问题时只修改图源并重新导出；每次修复后复查受影响的整张图，而非只看局部。存在任一箭头重叠时，该图不得交付。
8. 将图片嵌入 Markdown/Obsidian 后验证附件存在且路径可解析。优先采用 Obsidian 原生嵌入：`![[相对 Vault 的路径/图.png|宽度]]`。
9. 对系统架构图，从读者视角逐条追踪主控配置、命令提交、任务发射、DMA 存储访问、执行单元与 L1BUF 访问、完成通知六类路径；任一路径的起点、终点或方向无法一眼确认时，重新布局。

## 验收清单

- 每个箭头都从源方框有效边界出发，并在目标方框有效边界终止。
- 无悬空箭头、断开的折线、落在圆角外的箭头头部或方向错误的回环。
- 无箭头穿框、压字、压图例、穿过分区标题、与其他连接线交叉或共线重合；源节点和目标节点之外的所有元素均与箭头保持可见间距。
- 无小幅连续弯折、端点附近微小折返或锯齿状路径；可直连的端点已经直连，保留的正交线段均具有清晰且足够长的绕行距离。
- 每个状态转移条件只对应一条箭头，位于独占的直线段保留区内，不与状态框、其他条件、箭头头部或转折点重叠。
- 无文字压边、文字压箭头、文字越框、裁切、重叠或难以阅读的小字；圆角框内文字没有进入圆角区域。
- 同层并列模块尺寸对称、间距一致；方框与文字量匹配，图内无大块无效空白，文字已在安全边距允许范围内尽量放大并加粗。
- 深色背景全部使用浅色文字，黑色或深灰文字只出现在浅色背景，最终导出尺寸下对比清晰。
- 字段图的单元格尺寸统一，位号、名称和说明在对应单元格内对齐。
- 图题、图号和正文之间的间距符合文档排版要求；图题本身不与图片内容重叠。
- SVG 图源、PNG 导出文件和 Markdown/Obsidian 嵌入路径三者一致且存在。
- 系统架构图按层次自上而下展开；所有主要模块仅出现一次，NPU 内外归属清楚，主控、命令、任务、数据与完成路径均可连续追踪。
