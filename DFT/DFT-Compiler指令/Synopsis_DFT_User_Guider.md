# Synopsys DFT Compiler 用户指南

术语参照：[[术语与翻译规范]]。

## 使用说明

本文将扫描插入、测试协议、DFT 设计规则检查（DFT DRC）、ATPG 和交付等主题组织为中文索引。遇到版本相关参数时，应以当前安装版本的 `-help` 和官方文档为准。

## 1. 功能地图

| 主题 | 解决的问题 | 关键输出 |
| --- | --- | --- |
| 测试协议 | 工具如何驱动时钟、复位和测试模式 | 测试属性、SPF/STIL |
| 扫描架构 | 触发器如何替换、分链和连接 | 扫描网表、扫描路径报告 |
| DFT 设计规则检查（DFT DRC） | 测试模式下哪些路径不满足可测性 | DRC 报告 |
| 测试模型 | 黑盒、内核、层次块如何被抽象 | test model |
| ATPG 接口 | 如何把 DFT 结构交给向量生成工具 | 协议、网表、约束 |
| 层次化流程 | 子模块与顶层如何分别插入并交接 | block/top 级测试数据 |
| 优化 | 如何降低链长不均、运行时间和内存 | 平衡链、压缩和统计报告 |

## 2. 测试协议的定义

测试协议不是一串孤立命令，而是对测试时序的约束集合。至少应覆盖四类信号：

### 2.1 时钟

- 测试时钟来源和端口。
- 移位期间的时钟边沿。
- 捕获期间的时钟边沿。
- 多时钟域之间的关系和禁止组合。

### 2.2 扫描控制

- 扫描使能的有效电平。
- 扫描输入、扫描输出及链编号。
- 链分组、链长度和压缩/解压缩逻辑。

### 2.3 复位和初始化

- 复位极性和同步属性。
- 进入扫描模式前是否必须先初始化测试模式寄存器。
- 扫描移位和捕获时复位必须保持的值。

### 2.4 双向与三态

双向端口必须说明输入/输出方向切换时刻，避免测试过程中总线争用或观测到高阻态。

## 3. 扫描风格选择

常见扫描风格是多路选择型扫描触发器（multiplexed flip-flop）。选择时要比较：

| 维度 | 需要关注的内容 |
| --- | --- |
| 面积 | 扫描 MUX、测试点和压缩逻辑带来的门数 |
| 时序 | 功能路径增加的 MUX 延迟、测试模式的时序约束 |
| 功耗 | 移位功耗、捕获功耗、峰值 IR drop |
| 覆盖率 | 可控性、可观测性和 ATPG 处理难度 |
| 兼容性 | 工艺库、门级仿真模型、后端和 ATE 格式 |

## 4. DFT 设计规则检查（DFT DRC）思维框架

![DFT 设计流程](../.assets/dft-流程.svg)

遇到 DRC 违规时，按以下问题逐层定位：

1. 违规发生在功能模式还是测试模式？
2. 工具是否认识该时钟、复位或测试模式端口？
3. 在违规时刻，故障节点是否可以被驱动？
4. 故障响应是否有路径到扫描输出或观察点？
5. 约束是否过严，或者设计中确实缺少旁路/测试点？

## 5. 层次化 DFT

推荐把层次化设计分为三个阶段：

```text
子模块：定义本地测试协议并插入 block 级扫描
   ↓
子模块交付：网表 + test model + chain information
   ↓
顶层：连接模块、拼接/重组扫描链并做 top-level DRC
```

层次化交接时不可只交一个 Verilog 网表，还要交付扫描链信息、测试模式关系、时钟域说明、黑盒模型和版本化报告。

## 6. 测试点和不可检测故障

测试点的目的不是“让报告更好看”，而是降低 ATPG 求解难度：

- **控制点**：帮助测试设备把内部节点设置为 0/1。
- **观察点**：把难以传播的内部响应送到可观察位置。
- **隔离点/旁路**：在测试模式下绕开不可控的门控、黑盒或复杂协议。

插入测试点前，要同时评估面积、时序、功耗和后端布线影响。

## 7. 常见命令分类

```tcl
# 设计和库
read_verilog ./rtl/top.v
current_design top
link
check_design

# 测试协议和扫描
preview_dft
compile -scan
insert_dft
report_scan_path

# DRC 与覆盖率
dft_drc

# 输出
write -format verilog -hier -output ./out/top_scan.v
write_test_protocol -format stil -output ./out/top.stil
```

## 8. 版本差异与安全使用

- 不同版本可能变更命令名、属性名和协议格式。
- 先用 `command -help` 或 `man command` 确认参数，再写入正式脚本。
- 对自动修复（AutoFix）产生的结构必须做网表、时序和 DFT 设计规则检查（DFT DRC）复核。
- 不要把实验目录中的绝对路径、旧工艺库名和旧版本选项直接复制到新项目。
