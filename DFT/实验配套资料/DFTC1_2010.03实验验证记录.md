## 本次脚本调整

### 读取 DDC

当前工具不能直接从 `/media/6` 读取 DDC，会报 `UID-58`。将 DDC 临时复制到容器内的 `/tmp` 后，`read_file -format ddc` 可以稳定完成读取。

```tcl
set local_ddc "/tmp/dftc_[pid]_design.ddc"
file copy -force mapped/ORCA.ddc $local_ddc
read_file -format ddc $local_ddc
current_design ORCA
link
file delete -force $local_ddc
```

旧脚本中的 `read_ddc` 在当前版本中不可用，已改为 `read_file -format ddc`。

### VHDL 有限状态机

默认的有限状态机处理会使 `PRGRM_FSM` 产生 `ELAB-1094`，并使后续 DFT 检查出现黑盒提示。读取 RTL 前加入下列设置后，Lab 4A、Lab 5、Lab 6 和 Lab 7 可以正常编译。

```tcl
set_app_var hdlin_always_fsm_complete false
```

### 多扫描时钟定义

旧脚本把三个时钟放在一个 `-port` 参数中。当前版本要求每条 `set_dft_signal` 只指定一个端口，因此改为三条命令。

```tcl
set_dft_signal -view existing_dft -type ScanClock -timing {45 55} -port pclk
set_dft_signal -view existing_dft -type ScanClock -timing {45 55} -port sdr_clk
set_dft_signal -view existing_dft -type ScanClock -timing {45 55} -port sys_clk
```

### VHDL 总线位端口

当前 VHDL 读取器会以转义形式保存总线位名称。直接写 `Instrn[0]`、`pad[0]` 等文字会导致端口查找失败。脚本改为从端口集合中取得位 0，再传给 DFT 命令。

```tcl
set scan_in_port  [index_collection [get_ports {Instrn*}] 31]
set scan_out_port [index_collection [get_ports {Xecutng_Instrn*}] 31]
set_dft_signal -view spec -port $scan_in_port -type ScanDataIn
set_dft_signal -view spec -port $scan_out_port -type ScanDataOut
```

Lab 8 与 Lab 9 使用同一方式取得 `pad[0]` 至 `pad[5]`、`sd_A[0]` 至 `sd_A[5]`。运行报告已确认扫描端口、hookup pin 和链名正确。

### Lab 7 的 AutoFix

`lab7_fixing/scripts/autofix.tcl` 原来只保留空命令。已补充时钟、复位和置位的 AutoFix 设置，并在预览前重建测试协议。

```tcl
set_dft_configuration -fix_set enable -fix_reset enable -fix_clock enable
set_dft_signal -view spec -type TestMode -active_state 1 -port TEST_MODE
set_dft_signal -view spec -port Clk -type TestData
set_autofix_configuration -type clock -control TEST_MODE -test_data Clk
set_dft_signal -view spec -port Reset -type TestData
set_autofix_configuration -type reset -method mux -control TEST_MODE -test_data Reset
set_autofix_configuration -type set -method mux -control TEST_MODE -test_data Reset
```

预览报告确认生成 2 个 AutoFix test point；插入后 DFT DRC 为 0。

### Lab 9 的交付脚本

`lab9_export/scripts/7handoff.tcl` 已补充测试协议、SCANDEF 和一致性检查：

```tcl
write -format verilog -hierarchy -output tmax/ORCA_scan.v

write_scan_def -output mapped_scan/ORCA.scandef
```

`check_scan_def` 的结果为 9 个 SCANCHAINS 已检查、9 个有效、0 个失败。导出的 Verilog 还通过了下列语法检查：

```sh

```

## 主要问题与处理方式

| 现象 | 原因 | 处理方式 |
| --- | --- | --- |
| `ELAB-1094` | 当前有限状态机默认处理与旧 RTL 不兼容 | RTL 读入前设置 `hdlin_always_fsm_complete false` |
| `UID-58` 读取 DDC 失败 | 容器中的工具不能直接读取 `/media/6` 上的 DDC | 临时复制到 `/tmp` 后用 `read_file -format ddc` |
| `read_ddc` 未找到 | 当前版本不提供该命令 | 改用 `read_file -format ddc` |
| 总线端口找不到 | 方括号的转义方式不同 | 用 `get_ports` 和 `index_collection` 传递端口集合 |
| Lab 7 无法执行修复 | AutoFix 脚本只有占位命令 | 写入时钟、复位、置位的完整 AutoFix 设置 |
| Lab 9 未输出完整交付物 | 原 handoff 脚本缺少 SPF、SCANDEF 和检查命令 | 写入 `write_test_protocol`、`write_scan_def`、`check_scan_def` |
| TetraMAX 命令未在默认 PATH 中 | 容器的环境文件未加入 TestMAX 目录 | 使用 `/home/yusen/synopsys_2024/syn/V-2023.12-SP3/linux64/syn/bin/tmax64` 运行 `orca_tmax.tcl` |
| Verilog 输出提示总线命名 | 当前名称格式与 Verilog 建议格式不同 | 使用 `iverilog` 完成语法检查；项目使用时仍应按下游工具要求统一命名规则 |
