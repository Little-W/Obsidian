| 检查类型 | 回答的问题 | 程序与结果 |

## 3. 逐操作故障检测算例

### 3.1 运行方法

以下命令在资料根目录执行，使用 Python 标准库。

```bash
python src/validate_march_sequences.py
python src/fault_detection_examples.py
python src/validate_static_fault_models.py
```

`validate_march_sequences.py` 读取章节内可直接解析的完整 March 表达式，在多个小容量和 `⇕` 的两种方向选择下执行。每个地址必须先建立期望状态，随后读值与前序操作保持一致。重复读参数、多背景函数和多端口原子操作由专用程序处理。

### 3.2 单个故障的状态轨迹

`fault_detection_examples.py` 保存 14 个具体执行例子，并对其中 9 个单单元例子交换 0、1 再检查。每一步输出地址、读写操作、执行前后状态、期望值、实际返回值及是否发生不一致。

| 例子 | 完整局部序列 | 最早错误读取 |
|---|---|---|
| 固定为 0 | `w1; r1` | 第 2 步 |
| 0→1 转换失败 | `w0; w1; r1` | 第 3 步 |
| 重复写 0 造成破坏 | `w1; w0; w0; r0` | 第 4 步 |
| 读 0 当次返回错误并破坏状态 | `w0; r0` | 第 2 步 |
| 读 0 当次返回正确随后破坏状态 | `w0; r0; r0` | 第 3 步 |
| 连续第二次读 0 后破坏状态 | `w0; r0; r0; r0` | 第 4 步 |
| 激励单元上升转换使受害单元反转 | `w0(a); w0(v); w1(a); r0(v)` | 第 4 步 |

代码同时执行观测条件不足的例子：DRDF 只读一次、动态模型只读两次、在观测前重新写入，以及两个耦合反转后才读取。其输出用于说明具体的掩盖机制。第 02 章给出这些模型的正式定义与逐步说明。

### 3.3 完整 March 的小容量枚举

同一程序还对正文中可解析的完整序列执行三地址试验。每个故障单独注入，枚举 8 种初始位型、全部目标地址、相异激励与受害地址，以及 `⇕` 的可选方向。模型包括 SAF、TF、WDF、IRF、RDF、DRDF、连续两次读取后的破坏模型，以及指定 CFin、CFid、CFst。

输出中的 `detected_in_all_tested_settings` 仅在该原型的全部受测设置都出现错误读取时增加；`missed_examples` 保存可复算的未检出设置。由此可以直接检查某个相同长度的序列为什么得到不同结果。

### 3.4 36 个静态原型的指定集合

`validate_static_fault_models.py` 定义六类单单元故障的双极性实例，以及 CFtr、CFdrd、CFwd 的受害值、激励值和两种地址关系，共 36 个原型。该程序令单元在首写之前为未知值，状态相关激活要求前置值已经由写入建立，并将原型定义与初始化规则写入结果 JSON。对故障从首写即生效的全部初始位型，另用第 3.3 节的枚举程序检查。

在此集合中，March AZ1 的逐元素版本检出 29/36，March AZ 为 30/36，March AZ2 为 30/36，March SS、MSS 与 AB 为 36/36。第 04 章结合各自的完整操作顺序解释这些结果。该集合、三地址枚举集合与论文中的其他故障集合分别报告，计算覆盖率时使用各自分母。

### 3.5 双端口与存内计算算例

```bash
python src/port_imc_examples.py
```

程序执行第 11 章的双端口完整枚举教学算法，以及 March IMC-8T 的七阶段逻辑模型。三地址模型检测 48 个双激励故障与 24 个并发受阻故障；四地址模型分别检测 192 个和 48 个实例。对列深 2、4、6、8 的 IMC 模型，分别执行 26、51、76、101 次操作，与 $12.5N_c+1$ 一致；40 个明确的计算选择故障全部被检测。对跨端口地址对应关系，程序还检查 2、3、4 地址下共 29 个非恒等排列，逐个使用第 11 章的单个地址写 1、其余地址写 0 的序列检测。完整结果见 [port_imc_results.json](examples/port_imc_results.json)。

### 3.6 地址译码器的 March iC− 算例

```bash
python src/validate_march_ic.py
```

程序以固定地址背景函数展开第 04 章的六元素序列，检查正反遍历时的期望值和 `10N` 操作数。16 次无故障运行均通过；对连续地址转换后旧字线继续有效的指定模型，160 个独立实例均产生确定的错误读值。四地址示例在第 5 次访问检测到初始化阶段双选写入留下的错误。

16 地址的专用次序还检查低两位子译码器的全部 8 种有向单比特转换。程序将双选读取不同值时的结果记为 `X`，不把该不确定返回单独计入已检测的二进制错误。结果保存于 [march_ic_results.json](examples/march_ic_results.json)。

### 3.7 双地址透明测试算例

```bash
python src/transparent_march_examples.py
```

程序执行第 08 章的 `March_2A_1` 与 `March_2A_2`。容量 2、4、8 的全部初态，结合计数器和 Gray 码的不同地址位删除方式，共形成 4,320 次无故障运行；操作数、局部互补比较、各基本阶段的数据恢复均通过检查。另有 512 个 SAF/TF 实例全部被局部比较检出。

程序保存四单元完整操作轨迹，以及通过初末签名差异检测 CFid、通过反向阶段检测指定邻域图案故障的例子。CRC-4 的多项式和更新方式是本手册明确给定的实现选择。结果保存于 [transparent_march_results.json](examples/transparent_march_results.json)。

## 4. 多背景序列与局部故障注入

```bash
python src/validate_multirun_sequences.py
python src/validate_multirun_faults.py
```

### 4.1 背景与操作的确定性展开

`validate_multirun_sequences.py` 把第 04 章给出的背景函数转换为 16×16 单元的实际读写序列。它逐次检查无故障期望值、背景切换、最后读取和总访问次数，并遍历不同物理位置类别的局部状态图。

| 算法 | 实际访问次数 | 每单元系数 | 局部几何类别 | 每类转换边数 |
|---|---:|---:|---:|---:|
| MT-R3CCF | 5,376 | 21N | 16 | 24 |
| MT-3CCF | 9,472 | 37N | 16 | 24 |
| MT-4CCF | 18,688 | 73N | 4 | 64 |
| MT-NPSF | 20,736 | 81N | 16 | 160 |
| MT-ENPSF | 45,312 | 177N | 16 | 160 |

表中 $N=256$。统计转换边时仅计入测试阶段，背景切换单独计数。扩展的读、非转换写和转换写操作集合，三单元为每类 72 条边，四单元为 192 条，五单元为 480 条。程序同时检查边的唯一性和读取期望。

### 4.2 从经过操作边到发现错误

`validate_multirun_faults.py` 对局部故障逐个执行以下过程：

1. 指定完整局部位型、激励单元、一次读或写事件，以及受害单元。
2. 从全零状态开始，执行实际背景初始化和全部测试操作。
3. 当前状态与激励条件相符时，使受害单元相对正常操作后的值发生反转。
4. 如果激励事件就是受害单元读取，当次仍返回破坏前的正确值，再改变内部状态；后续读取负责发现异常。
5. 使用预定的期望读值比较实际返回值，保存最早不一致的位置。

三、四单元模型分别枚举各单元作为受害单元；五单元邻域固定中心作为受害单元。结果如下。

| 算法 | 独立故障场景 | 检出场景 |
|---|---:|---:|
| MT-R3CCF | 1,152 | 1,152 |
| MT-3CCF | 3,456 | 3,456 |
| MT-4CCF | 3,072 | 3,072 |
| MT-NPSF | 2,560 | 2,560 |
| MT-ENPSF | 7,680 | 7,680 |
| 合计 | 17,920 | 17,920 |

此表对应源码中定义的单个局部静态错误模型，包含当次读出正确、随后破坏内部值的情况。动态历史、多个同时存在的故障、模拟电压与概率性写入需要各自的扩展状态和执行规则。

## 5. 序列搜索与最短性检查

```bash
python src/sequence_generation_examples.py
```

该程序执行第 05 章的两个教学构造。

**两单元欧拉回路。** 记录 8 条有向转换边的完整顺序。初始写入 2 次，每条边包含 1 次翻转写和 2 次读取，总访问次数为 26。程序同时执行逐边读取和末尾集中读取，以检查观测位置对故障检出的影响。

**单单元序列优化。** 对 12 个明确的数字故障原型及两种初始值，共 24 种设置运行模拟退火。另用独立广度优先搜索求解同一有限状态问题，验证获得的 11 次操作序列达到该问题的最短长度。具体序列、随机种子、搜索次数和各步骤信息见第 05 章及结果 JSON。

教学搜索采用单单元操作语法。论文的 11N 互补 March 测试具有另一个故障集合、地址方向和状态分析方法，两者分别解释和验证。

### 7.2 连接点定义

节点四边以 `N`、`S`、`W`、`E` 表示上、下、左、右。连接点由节点位置、边与比例计算；路径的水平、垂直转折由 `via` 明确给出。箭头尖端与目标连接点使用同一坐标。

```python
from svg_geometry import Figure

figure = Figure("example", "连接点示例", "测试命令由控制器发送至存储器。", 850)
figure.node("controller", 160, 240, 880, "测试控制器", ["产生测试命令"])
figure.node("memory", 160, 580, 880, "存储器", ["执行读写操作"])
figure.connect("command", "controller", "memory", meaning="发送测试命令")
figure.save("example.svg")
```

修改图形后，应从相应源码重新生成并检查。直接修改 SVG 时，后续运行生成程序会采用源码中的内容。图中采用 Noto Sans CJK SC，并提供常见中文字体回退设置；PNG 保存相应的渲染结果。

## 8. 网页公式与文件检查

```bash
python src/validate_handbook.py

# 安装网页生成依赖
python -m pip install 'mistune>=3,<4'
npm install mathjax-full@3

# 检查公式并生成离线阅读页面
node src/check_mathjax.js
python src/render_html.py

# 静态检查全部网页引用
python src/check_html.py --static-only

# 具有可用 Chromium 时检查页面布局
python src/check_html.py
```

`validate_handbook.py` 检查本地文档和图片引用、标题目标、文献引用、代码块及数学公式分隔。MathJax 将正文 LaTeX 转换为 SVG 数学内容，生成后的网页无需联网加载公式库。

`check_html.py --static-only` 检查 HTML 标题目标、相对链接、插图引用、重复标识符、公式错误标记和未替换内容。同时核对正文与 HTML 导出时保存的文件校验值，检查阅读副本是否对应当前正文。完整浏览器模式另外检查两种页面宽度下的图片加载与页面宽度。

程序将每类检查的实际执行结果写入 `checks/`。编辑正文后需要重新生成 HTML，Markdown 与 HTML 才会具有一致内容。

## 9. 导出逐访问测试序列

`src/export_march_traces.py` 将算法展开为逐访问 CSV，给出每一步的地址、读写操作、读取期望、写入值以及状态变化。工具直接使用现有定义：21 套固定序列由 `validate_march_sequences.extract()` 从第 03、04 章读取，March iC− 调用 `validate_march_ic.expanded()`，两套双地址透明测试调用 `transparent_march_examples.run()`。

导出前执行无故障仿真，检查读期望和访问次数；写出 CSV 后重新读取文件，逐字段比较并再次执行状态检查。透明测试还会检查局部互补比较、初末签名及原数据恢复。

### 9.1 使用方法

以下命令从文档包根目录执行，只需 Python 标准库。

```bash
# 列出全部 24 种算法、简写名称、长度系数和容量要求
python3 src/export_march_traces.py --list

# 导出 4 个地址的 March C−
python3 src/export_march_traces.py --algorithm "C-" --size 4 --output examples/traces/c_minus.csv

# 导出 16 个地址的 March SS
python3 src/export_march_traces.py --algorithm "SS" --size 16 --output examples/traces/ss_16.csv

# 导出采用 Gray 码顺序的 March iC−
python3 src/export_march_traces.py --algorithm "iC-" --size 8 --output examples/traces/ic_8.csv

# 指定透明测试的原数据，位串从左到右对应地址 0、1、2、3
python3 src/export_march_traces.py --algorithm "2A_2" --size 4 --initial 1100 --output examples/traces/transparent_4.csv

# 重新生成六个预设示例及算法目录，并执行检查
python3 src/export_march_traces.py --examples
```

`--algorithm` 同时接受完整名称与列出的简写，例如 `March C-`、`C-`、`March SS`、`SS`、`March_2A_2`、`2A_2`。名称中的 `−` 和 `-` 均可使用。`--output` 可指定所需 CSV 路径；省略时，文件写入 `examples/traces/`，文件名包含算法和地址数。`--size` 默认值为 4。

`--initial` 接受一个重复使用的位，或恰好包含 N 位的数据串。例如 `--initial 1` 表示全部地址初值为 1，`--initial 1100` 表示四个地址依次为 1、1、0、0。固定测试与 iC− 默认从未知值开始，并由算法中的初始化写入建立数据。透明测试默认采用地址 0 开始的交替初值 `0101…`。

### 9.2 导出字段

| 字段 | 含义 |
|---|---|
| `algorithm` | 算法的完整名称 |
| `stage` | March 元素 `M0`、`M1` 等，或透明测试的 `initial_signature`、`base_1`、`base_2`、`final_signature` |
| `step` | 从 1 开始的全局访问编号 |
| `address` | 从 0 开始的逻辑地址 |
| `operation` | `w0`、`w1`、`r0`、`r1`；没有逐位比较期望的采集或签名读取记为 `r` |
| `expected_read` | 本次直接比较的期望值；写入、透明采集读取和签名读取为空 |
| `write_value` | 写入的数据；读操作为空 |
| `observed_read` | 无故障执行返回的数据；写操作为空 |
| `cell_before`、`cell_after` | 被访问单元在操作前后的值，`x` 表示尚未初始化 |
| `state_before`、`state_after` | 全部地址按升序排列的状态串；N≤16 时提供，较大容量留空 |
| `direction` | 实际使用的地址顺序，例如 `ascending`、`descending`、`gray_forward`、`gray_reverse`、`double_forward`、`double_reverse` |
| `background` | iC− 的地址背景值，或透明测试的原始数据；普通固定序列为空 |
| `observation` | `direct_compare` 为固定期望比较，`capture_data` 为暂存读取数据，`local_compare` 为透明互补检查，`signature_reference`、`signature_result` 为初末签名读取，`write` 为写操作 |

CSV 使用带 UTF-8 标记的编码，方便表格软件识别。状态串中的前导零有实际含义，导入表格软件时应把两个完整状态字段设为文本类型。

透明测试的首条块内读取决定后续写入反值，所以该行的 `expected_read` 为空。随后的 `local_compare` 行才填写互补值期望。初末扫描的结果由签名比较检查，目录中给出两次签名及所使用的教学 CRC-4 规则。仿真中的完整状态记录用于检查恢复情况。

### 9.3 地址与容量要求

| 算法类别 | 容量与具体展开方式 |
|---|---|
| 21 套固定序列 | N 为正整数；`⇕` 元素具体选择升序，其余元素保持定义中的升降序 |
| March iC− | N 为不小于 2 的 2 的整数次幂；地址顺序为反射 Gray 码 `i XOR (i >> 1)`，背景相位为 0，末尾读取采用正向 Gray 顺序 |
| March_2A_1、March_2A_2 | N 为 2 至 256 之间的 2 的整数次幂；双地址顺序为两次完整升序扫描，第二基本阶段采用该序列的逆序；初末签名扫描均为升序 |

透明测试的导出容量上限为 256，因为被复用的仿真程序会为每次访问保存完整状态。该上限属于当前导出实现的资源控制。算法本身的容量关系由对应章节说明。

输入未知算法名、非正容量、iC− 或透明测试不支持的容量，或者长度不匹配的原数据时，程序会给出明确错误并以状态码 2 结束。没有生成失败算法的 CSV。

## 10. 统一检查与补充操作算例

运行全部数字模型、逐访问 CSV 导出和文档静态检查：

```bash
python3 src/run_checks.py
```

已安装本章所列网页依赖时，使用 `python3 src/run_checks.py --rebuild-html` 同时检查公式并重新生成所有离线页面；只运行数字模型时使用 `--models-only`。程序按顺序执行，每项记录实际退出状态和用时；遇到失败时停止。完整结果写入 [run_checks_results.json](checks/run_checks_results.json)。

`validate_read_disturb_and_pause.py` 检查第 04、08、11 章的补充操作例子：128 个读后破坏场景、192 次透明测试运行中的 2,304 个完整操作块结束位置，以及八位字的转换耦合实例。透明测试检查访问次数的奇偶性与数据恢复之间的关系，并演示应用正常写入后重新计算初始签名的过程。

```bash
python3 src/validate_read_disturb_and_pause.py
```

该程序分别保存实际读返回值和内部状态，因此能够明确区分本次已经读出的错误与最后一次操作后才形成的变化。结果见 [read_disturb_and_pause_results.json](examples/read_disturb_and_pause_results.json)。
