本资料库以 MBIST 的设计架构为主线。 March 算法规定怎样读写和比较；完整系统还必须决定谁执行、访问是否正确、哪些存储器同时工作、功率是否允许、怎样保存故障信息，以及能否用备用资源恢复可用容量。先建立这些模块之间的关系，再进入单独专题。

资料主要面向片上静态随机存取存储器（Static Random-Access Memory，SRAM），并扩展到多端口存储器、高带宽存储器、三维集成与新型存储技术。原文的论文范围与证据说明保留，资料检索截止仍为 2026 年 10 月 17 日；本轮只进行结构重编、合并和交叉引用整理。

1. MBIST 是完整测试系统，March 只是其中的算法

存储器内建自测试（Memory Built-In Self-Test，MBIST）是在芯片内部设置测试控制、访问和结果检查能力，对指定存储器执行规定操作。March 是其中一类规律遍历地址并检查读写结果的算法，不是 MBIST 的全部硬件，也不是“所有缺陷都能检测”的保证。123

必须把三个功能分开：MBIST 检测故障；内建冗余分析（Built-In Redundancy Analysis，BIRA）决定如何使用备用资源；内建自修复（Built-In Self-Repair，BISR）把修复决定落实到访问电路并进行复测。 纠错码保护正常运行中的数据错误，但不能替代上述全部工作。23

2. 沿着命令和结果理解硬件架构

模块 接收什么 完成什么工作 交出什么
顶层测试管理 启动请求、模式、时钟电源状态 决定哪些任务允许运行、何时结束 合法启动、状态汇总、故障响应
算法执行单元 算法与数据图案配置 产生地址、读写命令和等待 满足算法要求的命令序列
存储器接口适配 测试命令与宏接口条件 切换正常和测试访问，处理使能和延迟 被存储器正确接受的访问
期望结果与比较 读数据、对应的期望值与请求信息 检查有效读响应的错误位 不一致标志及准确的地址、位和阶段
故障记录与诊断 比较结果和运行条件 保存、压缩或进一步区分故障现象 可用于定位和修复的故障信息
冗余分析 故障集合与备用资源规则 求出合法的行列替换等方案 修复配置或无法修复结论
修复执行与复测 允许装载的修复配置 让访问使用备用资源并检查效果 修复后可用性及可靠状态
测试访问与调试接口 外部或片上配置请求 配置模式、读取状态与故障信息 可追踪的测试结果；配置时钟与测试执行时钟分开处理

这是对两份原报告的架构归纳；具体产品可能合并其中某些单元，或把它们分散到多个接口附近。共享功能总线的测试方案还要计入总线仲裁和带宽，而不能仅看控制器数量。234

读请求与读响应之间存在时间关系。比较器不能把“刚返回的数据”与“现在正在产生的地址”直接组合；应使用发出原读请求时保存的信息。这个问题连接了控制器、故障定位和修复，完整例子见存储器接口与测试控制器。

3. 将设计问题分成五个相互依赖的层次

层次 核心问题 对应专题
测试目标 需要触发和观察哪些故障？怎样定义覆盖？ 故障模型与检测原理
操作算法 地址如何遍历，读写怎样排列，是否需要专用图案？ March基础与经典算法、增强March与复杂故障测试、测试算法生成与选择
硬件执行 宏接口怎样适配，控制器能否表达这些操作？ 存储器接口与测试控制器、多端口与新型存储器扩展
芯片级组织 哪些实例共享硬件，何时启动，电气条件是否允许？ 存储器分组与功耗分析、并发调度与联合优化、自适应与运行期间测试
结果与验证 失败信息是否正确，能否修复，实际工具是否实现设计？ 故障诊断与结果记录、冗余分析自修复与纠错码、设计验证与工具接入

这五层不是互相独立的优化题。例如，增加动态故障测试的连续读取次数，会改变测试时间和功率曲线；把多个存储器放进广播式控制器，会限制独立启动；增加诊断记录能力会改变面积与输出带宽。优化任一层，都需要说明其他层是否保持不变。

4. 一次测试怎样从启动走到完成

首先确认目标存储器的时钟、电源、复位、测试权限和正常访问状态，再装载算法与实例配置。进入测试后，控制器产生合法命令，比较器处理读结果，记录单元收集需要的信息。停止发命令不等于测试已经完成：仍需等最后的读结果返回并处理完毕。

若只进行筛选，结束条件可能是完成规定测试并汇总状态；若还要修复，则需要收集足够故障信息、执行冗余分析、暂时装载修复配置，再运行修复后的检查。永久保存修复信息必须遵循产品授权条件，不能当作普通调试参数写入。23

运行期间测试还要保护应用数据、阻止冲突访问并正确恢复系统状态。透明算法只保证在相应条件下恢复数据，不表示测试过程中没有占用存储器，也不表示可以让其他模块随时读写。567

4.1 不同生命周期阶段的目标不同

制造测试寻找制造过程形成的缺陷，是否允许破坏数据、使用何种电压和测试多久，应由产品测试计划规定。启动测试需要在软件使用目标存储器前完成初始化与检查。运行期间测试必须同时保护数据、处理正常访问和实时性要求。硅后表征通常扫描电压、频率与温度，以分析工作裕量，而不只给出通过或失败。

这些用途可以共享硬件，但不能自动共用停止条件。已确定不合格的生产筛选可以按计划提前结束；故障诊断可能需要继续收集其他故障；运行期间发现故障后则应先按系统策略隔离受影响区域。用途的区别不构成满足任一特定安全标准的证明。

5. 四个最容易混淆的设计结论

组数不等于完成时间。 分组决定共享硬件的方式，调度决定真正的执行时刻；同样三个控制器组，也可能得到不同完成时间。六存储器算例在并发调度与联合优化，程序在教学算例与源码说明。

操作计数不等于时钟周期。 表示按约定粒度计算的读写操作数；读延迟、流水执行、端口切换、等待和结果排空会改变真实时间。详见存储器接口与测试控制器与March基础与经典算法。

全局功率合法不等于局部电压与温度合法。 必须区分功率、能量、电流、空间位置和时间历史；组内依次执行也不能机械使用组内功率之和。详见存储器分组与功耗分析与并发调度与联合优化。

报失败不等于定位正确，更不等于修复完成。 故障记录器满不一定证明不可修复；纠错后的数据正确不一定证明阵列没有缺陷。详见故障诊断与结果记录与冗余分析自修复与纠错码。

6. 推荐的设计过程与交付内容

设计阶段 至少应形成的结果 进入下一阶段前应检查
建立需求和实例清单 宏接口、位置、工作条件、测试用途 未知字段不能默认为零或相容
定义故障与选择算法 完整序列、图案、等待及覆盖要求 名称、操作计数和状态一致性
确定控制器与候选分组 硬件共享能力、候选组及代价 独立启动和同步操作是否真的受支持
建立功率模型并安排时间 时间表、功率曲线、区域与带宽限制 运行全过程是否满足资源要求
设计结果处理与修复 记录格式、溢出处理、备用规则 地址对应、资源预算和复测条件
工具生成与独立验证 实际结构、执行周期、故障及物理结果 预测方案与实际生成结构是否一致

以上是资料库采用的教学组织方式，不是某一家工具的固定命令顺序。真实工具的版本、许可证和宏能力需要以目标环境为准；配置示例见设计验证与工具接入，不要把教学 JSON 直接当作厂商原生命令。

7. 专题总目录

编号 独立文档 要解决的核心问题
01 存储器接口与测试控制器 明确怎样把测试操作转成合法的存储器访问，并准确回收读结果。
02 故障模型与检测原理 说明一个故障为什么被触发、怎样被观察，以及“覆盖”究竟覆盖了什么。
03 March基础与经典算法 从 March 符号和地址遍历入手，逐步推导 March C−，再比较经典算法。
04 增强March与复杂故障测试 把读写干扰、关联故障、动态故障与邻近图案条件分别对应到测试序列。
05 测试算法生成与选择 在必要覆盖要求下选择或生成测试，不把操作次数当作唯一优化目标。
06 存储器分组与功耗分析 把共享控制器的分组方法与功率、局部电源和温度模型放在同一专题分析。
07 并发调度与联合优化 确定哪些测试何时运行，并以完整时间区间检查资源与功率。
08 自适应与运行期间测试 区分调整顺序、提前停止、透明测试、数据保存恢复以及老化预测。
09 故障诊断与结果记录 从“读错了”得到可用于定位和修复的记录，并分析记录资源对并发的限制。
10 冗余分析自修复与纠错码 解释怎样选择备用行列、装载修复配置、复测，并与纠错码协同。
11 多端口与新型存储器扩展 说明多端口、堆叠、磁性与存储器内部计算结构为什么不能只换容量参数。
12 设计验证与工具接入 把前面各层的决定转换成实际硬件，并分开验证算法、执行、定位及电气条件。
13 教学算例与源码说明 算例位于哪里，怎样运行程序、重新生成图片和检查文档？

8. 三条阅读路线

从头学习： 本总览 → 存储器接口 → 故障模型 → March 基础 → 增强算法 → 算法选择 → 分组功耗 → 并发调度 → 自适应测试 → 诊断 → 修复 → 技术扩展 → 工具验证。

研究分组与调度： 本总览 → 存储器接口与测试控制器 → 存储器分组与功耗分析 → 并发调度与联合优化 → 故障诊断与结果记录 → 设计验证与工具接入。这条路线保留硬件结构和诊断带宽，避免只优化抽象组数。

研究 March 与故障检测： 本总览 → 故障模型与检测原理 → March基础与经典算法 → 增强March与复杂故障测试 → 测试算法生成与选择 → 存储器接口与测试控制器 → 设计验证与工具接入。特殊存储技术再进入多端口与新型存储器扩展，运行期间用途再进入自适应与运行期间测试。
