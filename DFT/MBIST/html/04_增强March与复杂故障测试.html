1. 复杂静态故障序列

1.1 增强序列的动机

较短算法通常存在两类不足。第一类是同一存储单元的操作种类不足：例如没有“存储 0 时再次写 0”，就可能无法触发某些写入干扰故障。第二类是不同单元之间的激励与观测顺序不足：某个耦合故障发生后，受害单元可能在检查之前被其他写入修复，从而使故障无法被发现。

因此，较先进的静态故障算法不仅增加操作次数，还仔细控制每次读取或写入的具体位置。

1.2 March LR

March LR（Linked-fault-oriented March）系列针对某些相互影响的静态故障条件，通过调整遍历方向和读写顺序改善检测能力。它不是笼统地多执行一次 March C−。

一种常见的 版本可写为：

{ ⇕(w0);
  ↓(r0,w1);
  ↑(r1,w0,r0,w1);
  ↑(r1,w0);
  ↑(r0,w1,r1,w0);
  ↑(r0) }

按元素计数为 1+2+4+2+4+1=14N。上述版本特别强调在已经触发一个故障之后、另一个可能使其隐藏的操作之前安排读取。并不是全部关联故障都可以由此版本保证检测。 早期同类工作还包括 March LRD、March LRDD 等针对地址译码器及耦合条件调整的版本，其总复杂度可能含有地址位数 的附加项。1

1.3 March SR

March SR 系列通过增加重复读取和特定非状态转换写入，提高某些静态读写故障的触发和观察能力。其常见 版本为：

{ ↓(w0);
  ↑(r0,w1,r1,w0);
  ↓(r0,r0);
  ↑(w1);
  ↓(r1,w0,r0,w1);
  ↑(r1,r1) }

操作数为 1+4+2+1+4+2=14N。与 March C+ 相比，两者即使同为 ，重复读取的摆放位置、写入相同数值的情形与跨地址顺序也不同，因此必须在相同故障模型下验证后才可比较。

1.4 March SS

Hamdioui 等人在 2002 年提出 March SS，针对列出的、在现实中有代表性的全部非关联静态故障原型，论文给出的测试长度是 。2

一个常见的 表达版本：

{ ⇕(w0);
  ↑(r0,r0,w0,r0,w1);
  ↑(r1,r1,w1,r1,w0);
  ↓(r0,r0,w0,r0,w1);
  ↓(r1,r1,w1,r1,w0);
  ⇕(r0) }

它的设计思想不是单纯使用更复杂的地址遍历，而是补充重复读取、非状态转换写入、读后立即检查等动作，使更多静态故障原型被触发并被看到。适合用作增强覆盖的研究基准。缺点是比 March C− 多 次操作，即测试操作总数为后者的 2.2 倍。

“检测全部非关联静态故障”不等于检测全部动态故障、全部关联故障或全部晶体管级物理缺陷。

1.5 March MSS

March MSS 可视为静态故障完整覆盖方向的重要进一步改进。一个文献常见版本为：

{ ⇕(w0);
  ↑(r0,r0,w1,w1);
  ↑(r1,r1,w0,w0);
  ↓(r0,r0,w1,w1);
  ↓(r1,r1,w0,w0);
  ⇕(r0) }

按操作计数为 1+4+4+4+4+1=18N。这类算法通过删去冗余操作、保留必要的故障激励与观察条件，减少为规定的非关联静态故障集合提供完整检测所需的长度。2026 年的一篇系统综述指出，对于其比较的全部非关联静态故障集合， 是重要的完整覆盖参考长度；而 级算法通常是在长度与覆盖之间折中。3

**对比 March SS：**优势是操作次数更少；限制是应检查具体来源采用的故障原型分类、是否包括相互关联故障，以及是否将某些新工艺故障排除在外。

1.6 March AB

March AB 的代表性工作明确称为 “A 22n March Test for Realistic Static Linked Faults in SRAMs”。它针对特定现实关联静态故障集合设计，作者将其与更长的 March SL 测试进行比较，目标是在保持模型覆盖的情况下缩短操作长度。4

一个常见资料中给出的、读写状态彼此一致的 操作序列如下。由于部分二级资料存在初始化数值、操作顺序及末尾读取值不一致的问题，工程复现仍应回到原始论文逐项核实：

{ ⇕(w0);
  ↓(r0,w1,r1,w1,r1);
  ↓(r1,w0,r0,w0,r0);
  ↑(r0,w1,r1,w1,r1);
  ↑(r1,w0,r0,w0,r0);
  ⇕(r0) }

对每个地址的操作计数为 1+5+5+5+5+1=22。其中连续读取有助于观察先前读写可能造成的变化，连续写入可激励某些非状态转换写入故障。它的优势是特别处理“一个异常可能掩盖另一个异常”的情况；缺点是测试时间超过 March C− 两倍，并且对于其模型以外的动态故障不作通用保证。

**长度标注差异：**一些二级中文论文将上面这个 序列误标成 。判断复杂度时应以每个 March 元素实际包含的读写操作数量重新计算，不能直接复制表格中的标签。参见54。

1.7 March AZ 系列

这一家族采用故障原型分析，对有限长度内的读写操作进行重新安排，而不是单纯增加测试次数：

  • **March AZ1：13N。**较早提出，试图在短测试长度下覆盖较多非关联静态故障模型。
  • **March AZ2：14N。**对 AZ1 的测试操作安排进行调整，换取相应故障集合的更高覆盖程度或不同检测重点。
  • **March AZ（2025）：13N。**通过移动关键写入操作，提升部分状态转换耦合故障的检测，同时仍然保持 。

2025 年的 March AZ 论文报告：对其定义的故障集合，状态转换耦合故障原型的覆盖比例由 62.5% 增加到 75%；综合静态故障覆盖比例达到 83.3%。这些数字来自作者选择的有限故障原型集合，不能直接与其他论文给出的“80.9% 动态故障覆盖率”作高低比较。6

仅调整写入顺序即可改善检测，原因在于：如果异常发生在一次写入之后，而下一次写入恰好把受害单元改回正确状态，后续读取便可能读出正确值。将写入移至其他阶段，可以避免这种故障被掩盖的情况。

2025 年论文的部分表格所列操作数与声明的 长度不完全一致。引用 March AZ 时应以作者的完整控制器实现、逐项元素说明与操作计数为准，不能仅依据扫描表格录入。

2. 动态故障与操作历史

2.1 静态与动态故障

当存储器制造尺寸不断缩小时，一些电阻性开路、较弱的写入驱动电路、读出放大器异常和内部节点充放电问题可能产生操作历史相关的故障：单独执行一次读取能够正常返回，但若紧接着再次读取、读取之后立即写入，或者在短时间内持续访问相邻地址，才会出现错误。

例如，下面的过程仅用于说明动态故障的产生方式：

先写入 1 → 第一次读取 1 → 第二次读取 1 → 再次读取异常

这与“延迟很久后发生的数据保持故障”不同：动态故障往往与操作的组合和先后次序有关，保持故障则需要专门的等待时间条件。并不是全部动态故障都会通过重复读取触发。

2.2 March RAW

March RAW（Read After Write 等相关读写操作的组合）是将测试重点进一步扩展到静态故障与一部分动态故障的重要算法。其常见 序列如下：5

{ ⇕(w0);
  ↑(r0,w0,r0,r0,w1,r1);
  ↑(r1,w1,r1,r1,w0,r0);
  ↓(r0,w0,r0,r0,w1,r1);
  ↓(r1,w1,r1,r1,w0,r0);
  ⇕(r0) }

操作计数为 1+6+6+6+6+1=26N。与 March C− 不同，它包含更多重复读操作和对当前内容再次写入相同值的操作：

  • r0,w0,r0：有机会检查“原本为 0 的单元再次写 0”是否引发错误。
  • r0,r0：有机会检查一次读取之后再进行读取的异常。
  • w1,r1：立即观察写入 1 的结果。
  • 正向与反向遍历：增加不同地址先后关系下触发耦合故障的机会。

**主要优点：**相对 C−，可以触发更多与连续读写有关的故障。**主要不足：**测试长度为 C− 的 2.6 倍，而且对需要更长读写历史、重复多次读取，或更复杂的相邻地址操作组合的故障，仍可能检测不足。

2.2.1 March RAW1

一些研究还列出 March RAW1（13N），其重点是将多种单存储单元读取、写入和重复操作安排在较短序列中，以获得比完整 March RAW 更少的测试操作数。它的故障覆盖目标较窄，不能因名称接近 March RAW 就假设它保持 版本的双单元耦合故障能力。3

对 RAW1 一类低复杂度算法，尤其需要确认其每次地址遍历之间的状态是否一致，以及是否要求对存储器执行特殊的初始化或数据反转；否则纸面上 的测试长度也无法保证硬件可正确执行。

2.3 Dynamic-RAWC

2023 年发表于《电子与信息学报》的《一种基于存储器内建自测试的新型动态March算法设计》提出 Dynamic-RAWC。其主要思想是在 March RAW 基础上加入可以按照目标动态故障调整的连续操作次数，而不是固定只重复两次读取。5

它讨论至少两类增强：

第一类：连续读取增强。 例如在有关的读写元素中，允许用参数 控制某一读取操作的重复次数，使序列可以激励需要三次、四次或更多次相关操作才表现出来的故障。

第二类：连续写入与读写结合增强。 通过在既有的重复读取之外加入重复写入操作，扩大对需要先后执行多个写入或读写组合才能激活的故障的检测能力。

文章还讨论了根据测试需要选择重复次数及组合的做法。实际测试长度必须根据具体 与所启用的元素重新计算；不能把同一个名称下的所有参数配置都视为固定 。

论文以定义的 282 个动态故障原型作为统计对象，报告如下结果：

算法 检测的动态故障原型数量 同一论文故障集合中的比例
MATS++ 6 / 282 2.1%
March C− 18 / 282 6.4%
March C+ 58 / 282 20.6%
March AB 112 / 282 39.7%
March RAW 140 / 282 49.6%
Dynamic-RAWC 228 / 282 80.9%

这些数字非常有参考价值，但必须明确：80.9% 是作者对其选取的 282 个动态故障原型执行功能故障分析得出的比例，不是实际量产芯片的物理缺陷覆盖率。 此外，Dynamic-RAWC 依然没能覆盖全部动态状态转换耦合故障等复杂模型。5

在真实宏中采用 Dynamic-RAWC 时，应先确定该宏可能出现的操作历史相关缺陷，再选择重复次数。在没有故障物理证据时，单纯把重复次数调得很高只会显著增加测试时间及动态功耗。

2.4 多操作动态故障

如果一个故障的激活需要按照顺序完成 r0, r0, w1，那么仅统计该测试有没有分别执行过 r0 和 w1 不够。必须检查：

  1. 三次操作是否针对正确的地址或正确的相关地址组合；
  2. 操作发生的先后次序是否一致；
  3. 操作之间是否允许插入别的地址访问；
  4. 两次操作之间的时间间隔是否满足缺陷出现的条件；
  5. 异常结果是否有机会被读取，并且不会提前被写入修复。

因此，针对动态故障优化 March 序列时，需要记录操作历史，而不是只记录某个地址当前是 0 还是 1。这也是 2026 年数字化上下文监测研究的核心动机。7

3. 地址译码器与邻近图案

3.1 地址译码器故障

地址译码器的作用是把输入地址转换为存储器内部的字线或列选择信号。电路故障可能导致：

  • 某个地址对应的单元始终无法被访问；
  • 一个地址访问了两个存储位置；
  • 两个逻辑地址错误地选择了同一个物理位置；
  • 当连续访问的地址位出现特定变化时，译码器不能及时切换；
  • 电阻性开路使异常只在某些先后访问顺序或时间条件下发生。

完整测试地址译码器不仅要读写存储数据，还需要安排适当的地址变化顺序。对这一类故障，地址生成方法和操作数据图案的重要性可能不低于单个地址上执行多少次 r0/w1。

3.1.1 March iC−

March iC− 是面向某些地址译码器开路缺陷所研究的 March 变体，其基本思想是保留紧凑的 March 测试框架，同时采用更有针对性的地址访问顺序和交替数据图案。部分研究采用 Gray 编码的地址遍历：相邻地址变化时只有一个地址位翻转，便于隔离某些译码条件。78

优点是可将特定译码缺陷检测纳入常规 March 风格控制器。局限是覆盖依赖译码器电路结构和目标故障模型；Gray 编码不是普遍最佳地址顺序，有些缺陷反而需要两个或更多地址位同时改变才能被激活。

3.1.2 March LA 与 LRD 系列

这些专用版本考虑某些地址译码器故障或关联故障。部分版本的测试次数还与地址位数 有关，因此会出现例如 、 等形式。这些长度与名称只对相应论文的具体序列成立，不能据此推断所有“March LRD”版本的统一覆盖率。

3.2 相邻单元故障与序列长度

对于两个单元的耦合故障，只需要考虑两个单元之间的状态关系。对于三单元、四单元、五单元故障，目标单元的表现可能取决于周围多个单元共同存储什么数据。

如果中心单元的四个邻近单元分别存储 0 或 1，则周围四个单元就有 种状态组合；如果把中心单元自身的当前数值也考虑进去，就有 种状态。再考虑对哪个单元执行读取、状态转换写入或者非状态转换写入，状态组合与转移要求会进一步增加。

因此，“全部写 0、全部写 1”不能覆盖全部相邻图案敏感故障。

行条纹 data = Ar[0] 使相邻行采用不同数值
列条纹 data = Ac[0] 使相邻列采用不同数值

这些公式假定 Ar[0] 和 Ac[0] 真正对应物理相邻的行列交替关系。如果存储器宏存在地址重新编码或位交织，就需要由物理设计信息推导图案，否则只能声称覆盖逻辑地址上的图案。

3.4 三单元与四单元耦合

Cașcaval 等人在 2024 年研究了相邻三个、四个存储单元构成的复杂故障模型，允许单元受到状态转换写入、非状态转换写入和读取的影响。9

代表性结果如下：

算法 长度 覆盖对象 重要限制
MT-3CCF 37N 特定的三个物理邻近单元组成的“角形”构造，涵盖较完整的静态故障操作 与其他三单元排列及任意位置故障不是同一模型
MT-R3CCF 21N 文中比较的受限三单元故障模型 对读取与非状态转换写入引起的扩展故障不能照搬 37N 的覆盖主张
MT-4CCF 73N 四个物理邻近单元构成的 2×2 方形结构 依赖明确的物理相邻关系与故障原型条件

2024 年论文使用状态转移图与欧拉路径思想分析某些序列接近最短的原因。若模型要求依次检查多种状态变化，理想测试应使每一种必需状态转移仅发生一次，避免重复执行没有新增检测价值的操作。切换数据图案时不可避免的额外写入，使其成为“近最优”而非严格全局最优。

**最重要的限制：**作者明确指出，这些面向五单元邻近模型的算法，虽然完整覆盖各自规定的五单元故障模型，却不能完整覆盖全部两单元耦合故障，也不能保证覆盖另一种四单元方形模型。它们不能作为 March C− 或专门的两单元耦合测试的无条件替代品。这是“覆盖更复杂的故障模型不一定自动覆盖全部简单故障模型”的典型反例。10

4. 序列复现与覆盖偏误

4.1 March AB 长度核验

2006 年原始研究的题目明确指出，March AB 是 22N 的测试。后续文献中存在将它列成 ，但实际仍列出每地址合计 22 次操作的错误。本资料库选用的序列 1+5+5+5+5+1=22N，并已检查没有故障时每个读取步骤的期待值与此前写入结果相符。54

4.2 连续读取与动态故障

有些动态故障需要“先写 1、连续读两次”，有些需要特定地址之间交替访问，有些依赖非常短或非常长的时间间隔。相同的重复读取数量不一定能够激励所有类型，甚至在不同存储器宏上可能表现不同。因此，研究重点必须是故障触发条件与读写序列是否吻合。

4.3 邻近测试与故障覆盖

2025 年 和 算法展示了相反情况：它们专门针对五单元邻近图案敏感故障设计，却不能据此直接推导它们对全部两单元耦合故障的覆盖。故障检测不是可以无条件按“涉及的单元数”递增的等级关系。10
