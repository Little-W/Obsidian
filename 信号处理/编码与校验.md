# 编码与校验

编码与校验通常用于通信、存储和传输链路中，目标大致分成三类：

- 压缩表示：减少冗余数据量
- 检错：发现传输或存储过程中的错误
- 纠错：在一定条件下自动恢复原始数据

## 1. CRC（循环冗余校验）

CRC 本质上是把比特串看成 GF(2) 上的多项式，使用一个生成多项式做模 2 除法，得到余数作为校验位。

### 计算步骤

1. 选定生成多项式 `G(x)`，其二进制表示记为 `g`，长度为 `r + 1`。
2. 在原始数据 `D` 后补 `r` 个 0。
3. 用补零后的比特串对 `g` 做模 2 除法，除法中的减法用 XOR 实现。
4. 得到的余数长度为 `r`，这部分就是 CRC 校验位。
5. 发送端把校验位接到数据尾部；接收端用同一个 `g` 再除一次，若余数为 0，则认为通过校验。

### 计算示例

数据：`11010011101100`

生成多项式：`1011`

`1011` 的阶数是 3，所以先补 3 个 0，再做模 2 除法。

结果余数为：`100`

因此最终 CRC 码字为：`11010011101100100`

### 说明

- CRC 非常适合检错，不适合纠错。
- 生成多项式选得好坏，会显著影响检错能力。
- 实际工程里常见 CRC-8、CRC-16、CRC-32 等。

## 2. 汉明码（Hamming Code）

汉明码是一类能进行单比特纠错的线性分组码。最常见的是 `(7,4)` 汉明码：4 位数据加 3 位校验位，组成 7 位码字。

### 基本规则

校验位放在 2 的幂次位置：`1, 2, 4, 8, ...`

以 `(7,4)` 为例，位置如下：

`1 2 3 4 5 6 7`

`p1 p2 d1 p4 d2 d3 d4`

这里采用偶校验。

### 计算步骤

1. 把数据位填入非 2 的幂次位置。
2. 分别计算每个校验位，使其覆盖范围内的 1 的个数为偶数。
3. 得到完整码字后发送。
4. 接收端重新计算校验位，得到综合校验结果（syndrome）。
5. syndrome 的二进制值就是出错位置；若为 0，则表示未检测到单比特错误。

### 计算示例

假设数据位是 `1011`，按顺序放入：

`1 2 3 4 5 6 7`

`p1 p2 1 p4 0 1 1`

计算各校验位：

- `p1` 覆盖位置 `1, 3, 5, 7`，其中已知位为 `1, 0, 1`，要满足偶校验，所以 `p1 = 0`
- `p2` 覆盖位置 `2, 3, 6, 7`，其中已知位为 `1, 1, 1`，所以 `p2 = 1`
- `p4` 覆盖位置 `4, 5, 6, 7`，其中已知位为 `0, 1, 1`，所以 `p4 = 0`

最终码字为：`0110011`

### syndrome 的含义

接收端常用下面三个校验结果：

- `s1 = b1 xor b3 xor b5 xor b7`
- `s2 = b2 xor b3 xor b6 xor b7`
- `s4 = b4 xor b5 xor b6 xor b7`

把 `s4 s2 s1` 组合成二进制数，就能定位错误位置。例如 `101` 表示第 5 位出错。

### 说明

- 汉明码能纠正单个比特错误。
- 如果再加入一个总体校验位，还可以构成扩展汉明码，用于单错纠正和双错检测。

## 3. RLC 编码（Run-Length Coding）

RLC 通常指运行长度编码，和常见写法 RLE（Run-Length Encoding）基本同义。它的核心思想是：把连续重复的符号压缩成“符号 + 重复次数”。

### 编码规则

对一段连续数据进行扫描：

- 遇到连续相同的符号，就统计它连续出现的次数
- 用一个二元组表示这一段，例如 `(符号, 次数)`

### 编码示例

原始数据：`0000001111000`

RLC 结果：`(0,6)(1,4)(0,3)`

也可以写成更紧凑的形式：`6个0，4个1，3个0`

### 适用场景

- 适合长串重复值很多的数据，例如图像中的大片纯色区域
- 不适合高熵、重复很少的数据，因为压缩效果可能很差，甚至会变大

### 说明

- RLC 是一种无损压缩方法。
- 它的优势在于实现简单、编码速度快。

### 实际内存中的存储方式

RLC 的编码结果在内存里通常不会保存成一串“特殊文本”，而是保存成一组运行段。每个运行段至少包含两部分：

- `value`：这一段重复的符号
- `count`：这一段连续重复的次数

因此，原始数据 `0000001111000` 在内存中的逻辑表示通常会变成：

- `(0, 6)`
- `(1, 4)`
- `(0, 3)`

程序实现时，常见的存储方式有两种：

```text
[{value: 0, count: 6}, {value: 1, count: 4}, {value: 0, count: 3}]
```

或者拆成两个并行数组：

```text
values = [0, 1, 0]
counts = [6, 4, 3]
```

### 实际存储要点

- 如果原始数据是按字节存储的，RLC 后一般也会按字节、整型或结构体存储，不会真的按纯文本保存。
- `value` 和 `count` 占多少字节，取决于实现语言和数据类型选择。
- 由于内存对齐和结构体填充，真实占用空间可能比理论值更大。
- 如果重复段很多但每段都很短，RLC 可能不划算，因为元数据开销会抵消压缩收益。

### 一个简单的内存视角

原始数据：`0000001111000`

压缩后内存里保存的是 3 个运行段。读取时，程序遇到 `(0, 6)` 就展开成 6 个 0，遇到 `(1, 4)` 就展开成 4 个 1。

所以，RLC 的本质不是把数据“变成另一种神秘格式”，而是把连续重复的数据换成更短的运行描述。

## 4. 小结

- CRC 侧重检错，常用于通信和存储完整性检查
- 汉明码侧重纠错，适合单比特错误恢复
- RLC 侧重压缩，适合重复模式明显的数据
