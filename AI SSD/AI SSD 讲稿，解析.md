## 3.4 面向 SSD 特性的训练 I/O 优化方法讲稿

这一小节主要介绍我们如何根据 SSD 的硬件特性，对大模型训练过程中的 I/O 行为进行优化。这里的核心问题是：训练过程中会产生大量参数、梯度、优化器状态、activation、checkpoint、日志和 profile 数据，如果这些数据没有经过组织，直接以零散 Tensor 的形式频繁读写 SSD，就会造成大量小随机写、元数据开销、写放大和训练阻塞。

因此，本节提出的优化方法不是简单地“把数据放到 SSD 上”，而是要让训练侧的数据写入方式更符合 SSD 的工作特性。总体思路可以概括为四点：第一，把小写变成大写；第二，把随机写变成顺序写；第三，让 I/O 和计算尽可能重叠；第四，减少不必要的写入。对应到本节的四个方法，就是大块化写入、顺序化写入、计算与 I/O 重叠，以及写入削减。

在进入具体方法之前，先解释几个关键名词。

首先是 SSD。SSD 底层通常基于 NAND Flash。它和内存不同，不能像 DRAM 一样随意原地覆盖写入。一般来说，SSD 可以按 page 写入，但擦除需要按更大的 erase block 进行。因此，如果上层频繁产生小而随机的写入，SSD 控制器就需要做更多地址映射、数据搬移和垃圾回收，最终导致写放大和性能下降。

第二是小随机写。小随机写指的是写入请求的粒度很小，并且地址不连续。训练中如果每个 Tensor 都单独写入 SSD，就很容易形成大量小随机写。这样不仅请求数量多，而且每次写入都可能带来文件系统元数据更新、SSD 内部映射更新和队列调度开销。

第三是写放大。写放大指的是主机侧实际写入的数据量，和 SSD 内部为了完成这些写入而产生的真实写入量不一致。比如主机只写了 1GB 数据，但由于擦除、搬移、垃圾回收等原因，SSD 内部可能写了更多数据。写放大会降低性能，也会影响 SSD 寿命。

第四是 checkpoint。Checkpoint 是训练过程中的恢复点，通常包括模型参数、优化器状态、学习率调度器状态、随机数状态等。它是可靠性关键数据，不能随意丢弃。但 checkpoint 体积通常很大，如果频繁保存，会给 SSD 带来明显压力。

第五是 activation。Activation 是前向传播中间结果，反向传播时需要用到。它的生命周期通常比较短，但是数据量很大。activation 可以选择保存在显存、CPU 内存或 SSD 上，也可以通过 activation checkpointing 在反向传播时重新计算，从而减少保存量。

第六是 optimizer state。Optimizer state 是优化器维护的状态，例如 Adam 中的一阶矩和二阶矩。对于大模型来说，optimizer state 通常比模型参数本身还大，是 SSD offload 中非常重要的一类数据。

下面具体介绍四类优化方法。

### 3.4.1 大块化写入方法

首先是大块化写入。它的目标是把大量零散的小 Tensor 写入，合并成更大的写入块。

训练过程中，Tensor 的大小和生命周期非常不一致。例如，不同 layer 的 activation 大小不同，不同 rank 的参数分片大小不同，optimizer state 也可能被切成多个 shard。如果按照每个 Tensor 单独写入 SSD，那么请求数量会非常多。请求数量一多，真正消耗的不只是数据传输时间，还包括系统调用、文件系统元数据维护、SSD 队列调度和地址映射管理等额外开销。

所以，大块化写入的基本思路是：不要让 SSD 看到大量零散 Tensor，而是让训练运行时先在 CPU staging buffer 或者 offload buffer 中把同类数据组织起来，再按更大的块写入。例如，optimizer state 可以按照固定 shard 合并；activation 可以按照 ring buffer slot 合并；日志可以按照时间窗口缓冲追加；checkpoint 可以按照 rank 和 shard 组织成较大的文件。

这里的“同类数据”很重要。所谓同类，可以按照 layer、rank、state shard、生命周期或者访问模式划分。比如同一层附近的 activation 往往具有相似的生命周期；同一个 rank 的 checkpoint shard 往往具有相同的保存和恢复逻辑；optimizer state 的访问通常和 optimizer step 相关。因此，把这些数据组织成大块，不仅可以减少请求数量，也可以让每个大块带有更清晰的语义标签。

大块化还有一个额外好处，就是提高元数据表达能力。如果每个小 Tensor 都单独维护元数据，那么训练侧和 SSD 侧都需要处理大量细粒度描述，管理成本很高。相反，如果一个大块可以统一标注为“activation 临时数据”“optimizer state shard”“checkpoint 长期数据”，那么训练调度器更容易恢复和管理，AI SSD 侧也更容易识别数据流的生命周期和访问模式。

但是，大块化不是越大越好。这里存在一个阈值选择问题。阈值太小，合并效果不明显，仍然会产生很多小写；阈值太大，又会增加等待时间，因为数据必须攒到一定大小才能写入。同时，过大的 buffer 还会占用 CPU 内存，甚至影响 GPU 计算等待。因此，大块化的阈值应该结合 SSD 带宽、CPU 内存容量、GPU 等待时间和数据重用距离综合调整。

在实验评估时，不能只看最终训练速度，而应该记录几个关键指标：合并前后的请求数量、平均写入大小、写入等待时间、CPU buffer 占用，以及 GPU 是否因为等待 I/O 而阻塞。如果合并后请求数量明显下降，平均写入大小上升，而且没有引入明显等待，那么大块化才是真正有效的。

### 3.4.2 顺序化写入方法

第二个方法是顺序化写入。大块化解决的是“写入粒度太小”的问题，而顺序化解决的是“写入地址太随机”的问题。

SSD 虽然比机械硬盘更擅长随机访问，但它并不意味着随机写没有代价。对于 NAND Flash 来说，顺序写通常更容易被 SSD 控制器聚合，也更有利于垃圾回收和 wear leveling。如果上层写入高度随机，SSD 内部需要维护更多映射关系，并可能产生更多数据搬移。

因此，我们希望训练数据在写入 SSD 时尽可能形成顺序流。对于 checkpoint，可以采用 append-only 或者分片顺序写。也就是说，每次 checkpoint 不直接覆盖旧文件，而是生成新的版本或新的 shard 文件，再通过版本管理决定保留哪些。这样写入过程更接近顺序追加。

对于 activation 临时数据，可以采用预分配连续区域和 ring buffer slot 顺序复用。ring buffer 的意思是预先划分一组固定 slot，训练过程中按照顺序循环使用。由于 activation 生命周期短，只要确认某个 slot 中的数据已经不再需要，就可以复用这个 slot。这样既避免了频繁创建小文件，也让写入区域更稳定。

对于 optimizer state，可以探索两种方式。第一种是 fixed shard，也就是给每个 optimizer shard 分配稳定位置，每次更新时按照固定 offset 管理。它的优点是索引简单，恢复方便。第二种是 log-structured，也就是把频繁更新转化为顺序日志追加，后续再通过 compaction 整理。它更符合顺序写特性，但实现复杂度更高，需要处理旧版本清理和元数据更新。

对于日志和 profile 数据，更适合缓冲追加。因为这类数据通常不是训练正确性关键数据，优先级较低，可以按时间窗口批量追加，而不是每条记录都立即落盘。

表 10 中列出了几种写入组织方式。每 Tensor 独立写实现最简单，但只适合小型调试数据，不适合作为主要策略。Fixed Shard 适合 optimizer state 和参数分片，因为这些数据结构稳定、便于索引。Ring Buffer 适合 activation，因为 activation 生命周期短、可以按 slot 复用。Append-only 适合 checkpoint 和日志，因为它顺序性好，但需要版本和清理机制。Log-structured 适合频繁更新状态，它对顺序写友好，但需要额外 compaction。

顺序化写入还有一个重要原则，就是避免冷热数据混放。这里的“热数据”是指频繁访问或频繁更新的数据，“冷数据”是指长期保存、很少访问的数据。例如，短生命周期 activation 不应该和长期 checkpoint 放在同一个逻辑区域；读密集的 dataset cache 不应该和写密集的 optimizer state 混在一起；日志和 profile 数据也应该作为低优先级追加流单独处理。

如果 AI SSD 支持主机侧放置提示，或者类似多流写入机制，我们可以进一步把不同语义数据映射到不同放置类别。比如 activation 是短生命周期临时写入，checkpoint 是长期可靠保存，optimizer state 是频繁更新状态，日志是低优先级追加流。SSD 如果能识别这些类别，就有机会在内部做更合理的数据放置和垃圾回收。

### 3.4.3 计算与 I/O 重叠方法

第三个方法是计算与 I/O 重叠。前两个方法主要是在降低 I/O 本身的代价，而计算与 I/O 重叠的目标是把不可避免的 I/O 隐藏到 GPU 计算过程中。

在大模型训练中，GPU 计算通常包括 forward、backward 和 optimizer step。I/O 操作包括参数预取、activation 写回和读取、optimizer state 读写、checkpoint 保存、日志写入等。如果这些 I/O 操作都同步执行，那么 GPU 很容易因为等待数据而空闲，训练吞吐会明显下降。

所以，我们希望 I/O 不要阻塞主计算路径，而是通过异步线程、CUDA stream、DeepSpeed offload buffer 和训练阶段调度实现重叠。

在 forward 阶段，可以预取后续 layer 即将使用的参数或状态。因为模型执行顺序通常是已知的，所以当 GPU 正在计算当前 layer 时，系统可以提前把后面 layer 所需的数据从 SSD 或 CPU 内存读到合适位置。

在 backward 阶段，可以读取即将用于反向传播的 activation，同时把已经不再需要的数据写回或释放。反向传播的顺序和前向传播相反，因此 activation 的重用距离可以被分析和预测。如果调度得当，就可以在 GPU 计算当前梯度时，提前准备下一步需要的数据。

在 optimizer step 阶段，可以批量读写 optimizer state。由于 optimizer state 数据量大，并且更新模式相对规律，非常适合按照 shard 进行批量调度。同时，checkpoint 和日志写入应该尽量与 optimizer state 写入错峰，避免 SSD 带宽在同一时间被多个大流量任务占满。

不过，重叠策略不能静态设定后就不管。它需要基于 profiler 结果动态调整。比如，如果 profiler 显示 SSD 带宽已经被 checkpoint 占满，那么 activation 写回就应该降级、推迟，或者尽量改为 recomputation。再比如，如果 GPU utilization 下降，同时 I/O 队列积压，说明数据预取不及时，或者写入压力过大。又比如，如果 CPU staging buffer 长期满载，说明 CPU 缓存容量不够，或者同时 offload 的对象太多，需要调整策略。

因此，计算与 I/O 重叠的评估不能只看平均 step time。平均时间可能掩盖尾延迟问题。我们还需要拆解等待来源，包括 compute time、prefetch wait、offload write wait、checkpoint stall、data loader wait 和 log/profile overhead。只有当 I/O 等待被真正隐藏在计算过程中，并且没有破坏训练正确性时，重叠策略才算有效。

这里的关键思想是：SSD I/O 不一定必须变得非常快，但它不能让 GPU 等。只要 I/O 能够在正确的时间提前完成，或者在不影响关键路径的时候延后执行，就可以保持训练吞吐。

### 3.4.4 写入削减方法

第四个方法是写入削减。前面三个方法解决的是“怎么写得更好”，而写入削减解决的是“哪些数据可以少写，甚至不写”。

写入削减非常重要，因为 SSD 的压力不仅来自写入方式，也来自写入总量。如果训练过程中所有中间数据都落盘，即使写得再顺序、再大块，SSD 也可能成为瓶颈。因此，我们需要从训练语义出发，识别哪些数据是必须写的，哪些数据可以少写，哪些数据可以用计算替代保存。

第一类方法是可重算数据少写，主要针对 activation。activation 的特点是数据量大，但很多 activation 可以通过重新执行部分前向计算得到。activation checkpointing 就是典型方法：不保存所有中间结果，只保存一部分关键节点，反向传播时重新计算缺失的 activation。这样可以减少显存或 SSD 写入，但代价是增加 GPU 计算量。因此，这是一种“用计算换 I/O 和存储”的策略。

第二类方法是低价值数据少写，主要针对日志和 profile 数据。训练日志、调试信息和 profile 记录对诊断很有用，但并不是每一步、每个事件都必须完整保存。可以采用采样、缓冲和分级记录。例如，在正常训练阶段降低记录频率，在异常阶段提高记录频率。这样可以减少低价值写入，同时保留必要诊断信息。

第三类方法是重复状态少写，主要针对 optimizer state。optimizer state 在每个 step 都会更新，如果每次更新都立即写回 SSD，会产生大量覆盖写和随机写。可以通过 CPU cache、dirty flag 和批量写回减少写入频率。也就是说，近期会继续被使用或更新的状态先保留在 CPU 内存中，等到合适时机再批量写回 SSD。这样可以减少 SSD 写入压力，但代价是增加 CPU 内存占用。

第四类方法是 checkpoint 有策略地写。checkpoint 是可靠性关键数据，不能简单丢弃，但可以控制保存频率和保留版本。例如，不一定每隔很短时间保存一次完整 checkpoint，可以根据训练阶段、loss 稳定性、时间间隔或 step 间隔决定保存频率。对于历史 checkpoint，也可以只保留最近若干版本和关键里程碑版本。进一步还可以探索增量 checkpoint，只保存相对上一个版本发生变化的数据。不过增量策略实现更复杂，需要保证恢复正确性。

表 11 总结了几类写入削减策略。Recomputation 适合 activation，本质是用计算替代保存；Sampling 适合 log 和 profile，本质是降低记录频率；Version Management 适合 checkpoint，本质是控制保留数量；CPU Cache 适合 optimizer state，本质是减少 SSD 写回；Write Coalescing 适合小 Tensor，本质是合并后再写入。

但是，写入削减有一条底线，就是不能牺牲训练正确性和恢复语义。checkpoint、optimizer state 等可靠性关键数据必须保证完整性。activation 重算必须保证反向传播结果一致。日志采样虽然可以降低粒度，但要保留关键诊断信息。所有削减策略都应该记录削减了多少数据、为什么削减、带来了什么代价。这样后续实验分析时，才能判断削减策略到底是有效优化，还是把必要数据省掉了。

### 小结

总结来说，3.4 这一节的核心是面向 SSD 特性的训练 I/O 优化。我们的优化不是单点策略，而是一个组合方案。

大块化写入解决请求过多的问题，把大量小 Tensor 写入合并成更大的块。顺序化写入解决随机性强的问题，让 checkpoint、activation、optimizer state 和日志按照更适合 SSD 的方式组织。计算与 I/O 重叠解决训练阻塞问题，让数据预取、写回和保存尽量隐藏在 GPU 计算过程中。写入削减解决写入总量过大的问题，通过 recomputation、sampling、CPU cache 和 checkpoint version management 减少不必要写入。

这四类方法之间是互补关系。大块化和顺序化提高单次 I/O 效率；重叠方法降低 I/O 对训练关键路径的影响；写入削减从源头减少 SSD 压力。最终目标是让 SSD 不只是被动存储设备，而是能够配合训练运行时的数据生命周期、访问模式和可靠性需求，实现更高效、更稳定、更低写放大的训练数据管理。
