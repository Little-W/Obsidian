## 摘要

近年来，大语言模型（Large Language Models, LLMs）的巨大进展主要由参数数量的增加所推动。这带来了巨大的内存容量需求，以至于仅仅为了满足容量要求就需要使用数十块 GPU。解决这一问题的一种流行方案是存储卸载训练，即将主机内存和存储作为扩展的内存层次结构使用。然而，这显然会以存储带宽瓶颈为代价，因为与 GPU 设备内存相比，存储设备的带宽低了若干个数量级。

我们的工作 Smart-Infinity 使用真实系统上的近存储处理设备，解决了存储卸载 LLM 训练中的存储带宽瓶颈。==**Smart-Infinity 的主要组件是 SmartUpdate，它在定制的近存储加速器上执行参数更新。我们发现，将参数更新移动到存储侧可以消除大部分存储流量**==。此外，我们提出了一种高效的==数据传输处理器结构==，用于解决 Smart-Infinity 的系统集成问题。该处理器通过==复用设备缓冲区，使数据传输能够在固定内存消耗下重叠进行==。最后，我们提出了==由加速器辅助的梯度压缩/解压缩方法，以增强 Smart-Infinity 的可扩展性==。当扩展到多个近存储处理设备时，共享通道上的写入流量会成为瓶颈。为缓解这一问题，我们在 GPU 上压缩梯度，并在加速器上对其进行解压缩。这通过减少流量进一步提升了性能。因此，与基线相比，Smart-Infinity 实现了显著加速。尤其值得注意的是，Smart-Infinity 是一种可直接使用的方法，已在真实系统上完全集成到 PyTorch 中。Smart-Infinity 的实现可在 https://github.com/AIS-SNU/smart-infinity 获取。

## I. 引言

基于 Transformer [118] 的模型目前在自然语言处理（NLP）领域占据主导地位，有效解决了困扰循环神经网络（RNN）的梯度消失问题。基于 Transformer 的模型往往具有大量训练参数，并且仍未表现出对训练语料的过拟合问题 [85]。因此，近几年的基于 Transformer 的模型 [17]、[26]、[85]、[95] 一直在按线性方式扩大模型规模，形成了大语言模型（LLMs）这一类模型。随着模型变得更大，主要限制因素变成了 GPU 内存容量。通常，即使在不需要如此多计算能力的场景下，例如微调 [120]，也需要数十块 GPU 才能将训练数据保存在内存中。

在 GPU 内存受限的环境中，处理这一问题的一种有前景的方法是存储卸载训练 [97]、[113]。对于 LLM 训练而言，已知最消耗内存的因素是优化器状态和梯度 [62]、[92]、[97]、[99]、[113]，其次是模型参数和激活值。利用这一事实，最广泛采用的存储卸载训练形式 [99] 是将优化器状态和梯度存储在存储设备中，而将激活值和模型参数存储在主机内存中。由于这些内存容量通常相差若干个数量级（例如，GPU 内存、主机内存和存储设备分别约为 80G、2TB、100TB），它们本质上为 GPU 提供了一个扩展的内存层次结构。

可以预见，使用大容量存储设备会造成严重的带宽瓶颈，因为 SSD 存储设备通常只提供最高几 GB/s 的带宽。根据我们的研究，超过 88% 的总训练时间都消耗在向存储传输数据或从存储传输数据上。乍看之下，使用 RAID0 方案组合多个存储设备似乎可以缓解这一问题。然而，这种方法从根本上会受到主机处理器 PCIe 通道（或 IO 引脚）数量的限制。此外，当今 CPU 的 PCIe 通道是非常宝贵的资源，它们需要被 GPU、FPGA、NIC，甚至系统内存共享 [30]。

%% RAID0方案是拼接多个SSD，增加带宽，但是收到PCIe接口数量限制，因为数据最终还是需要主机系统互联 %%

在这种情况下，我们旨在使用==计算存储设备（Computational Storage Device, CSD）产品==来解决这些问题。基于数十年的研究 [24]、[35]、[56]、[74]、[117]，目前已有数种商用 CSD 产品可以直接购买 [1]、[6]、[7]、[83]。通过将计算引擎放置在存储附近，它们的目标是卸载主机的计算，并利用存储内部带宽。当加入更多这类设备时，可用的内部带宽会线性增加。

基于这些设备，我们提出了 Smart-Infinity，这是一个使用 CSD 的快速 LLM 训练系统。为解决存储瓶颈问题，我们主要建议将更新任务移动到近存储加速器上。我们发现，优化器状态仅在训练的更新阶段使用，但消耗了总存储带宽的 75%。通过将更新任务移动到 CSD 内部的定制加速器上，只需要传输梯度和模型参数，从而减少 75% 的总流量。

%% 优化器：训练神经网络时用来**更新模型参数**的算法。 %%

在真实系统上实现 Smart-Infinity 面临若干挑战。一个问题是 CSD 内部的数据传输会对系统性能产生有害影响。为解决这一问题，我们提出了内部传输处理器优化，通过缓冲区预分配和交换重叠技术来获得最大吞吐量。

此外，我们提出了 CSD 辅助的梯度压缩/解压缩。当我们使用多个 CSD 扩展系统时，瓶颈出现在通过共享通道从主机到存储发送梯度的流量上。为减少这一流量，我们在 GPU 上压缩梯度，并在 CSD 中的加速器上解压缩。这样可以大幅减少流量，从而获得更好的性能，同时不会损害最终模型精度。

最值得注意的是，Smart-Infinity 已在真实系统上集成到 PyTorch 中，并且是一个可直接使用的框架。我们的评估表明，与基线相比，Smart-Infinity 最高可实现 2.11× 加速。贡献总结如下。

1) 我们提出了 Smart-Infinity，这是一种在定制 CSD 加速器中执行 LLM 训练更新阶段的方法。它显著降低了存储带宽瓶颈。

2) 我们提出了一种高效的数据传输处理器结构，用于利用存储带宽并隐藏 CSD 延迟。

3) 我们提出了一种 CSD 辅助的梯度压缩方法，用于增强 Smart-Infinity 的可扩展性。

4) 我们将 Smart-Infinity 在真实系统上与 PyTorch 集成，在混合精度 LLM 训练中实现最高 2.11× 加速。

## II. 背景

如第 I 节所讨论的，使用聚合的 GPU 内存来进行完整的 LLM 训练是一种昂贵的方法。一个流行的替代方案是卸载解决方案 [97]、[99]、[113]，它们在有限资源下训练 LLM 时利用主机内存或存储。我们将描述这些方案并讨论它们的局限性。

### A. 存储卸载 LLM 训练中的数据流概述

ZeRO [96] 分析了 LLM 训练期间的内存使用，并提出了在多 GPU 分布式 LLM 训练中拆分优化器状态（例如 Adam 的动量和方差）的方法，以最小化内存使用。它指出，在 LLM 训练期间，优化器状态需要相当可观的额外内存。

在混合精度训练 [84] 中，若将 FP16 模型参数大小记为 M，则 FP32 优化器状态会占用 6M 容量（FP32 中的模型参数、动量和方差）。考虑到在混合精度 LLM 训练 [44]、[85]、[88] 中，以 FP32 维护优化器状态几乎是一个必要选项，这提供了一个重要认识：在资源受限环境（例如 GPU 内存不足）中，优化器状态管理是 LLM 训练的关键问题。

受上述认识启发，许多方法 [92]、[97]、[99]、[113] 在 GPU 因内存容量无法容纳完整优化器状态时，尝试将 LLM 训练的优化器状态卸载到主机内存或存储。主机内存卸载训练 [92]、[99] 提供了使用主机内存训练 LLM 的基本概念。

由于更新优化器状态的计算强度（逐元素操作）较低，将优化器状态卸载到主机内存并让主机 CPU 更新参数变得很有吸引力。然而，为了训练模型规模从 345M [94]、[108] 到 530B [17]、[85] 的更大 LLM，即使使用主机内存卸载训练也无法训练的模型，一些工作 [62]、[97] 提供了进一步利用存储设备的解决方案。

在主机内存卸载训练的基础上，存储卸载训练 [97] 建议进一步使用存储（通常是 NVMe）设备，在有限硬件资源下训练 LLM。它们将优化器状态卸载到存储中，并使主机内存仅保存激活值和混合精度参数。这突破了主机内存大小的限制，使得在单台机器上也可以训练更大的模型。

图 1 给出了使用混合精度训练的存储卸载训练方法概述。这些方法将 LLM 模型划分为多个块（例如层），每个块的大小是 GPU（或主机内存）一次能够处理的大小。在训练开始前，模型的全部优化器状态最初存储在存储设备（即 SSD）中，如图 1(b) 和图 1(c) 底部所示。在前向传播中（图 1(a)），GPU 加载某个块的混合精度参数。在 GPU 中完成该块的前向处理后，GPU 将该块的激活值检查点保存到主机内存。对于所有块，主机会迭代执行这些步骤，并对整个模型的所有激活值进行检查点保存。在反向传播中（图 1(b)），对于每个块，GPU 加载混合精度参数和激活值，并在 GPU 中执行该块的反向处理，其产生的梯度会被发送到主机内存。为最小化主机内存空间使用，主机会将生成的梯度卸载到存储设备。

当前向传播和反向传播完成后，主机会以块为单位启动模型参数的更新过程（图 1(c)）。梯度和优化器状态从存储上传到主机内存。随后，CPU 加载上传的梯度和优化器状态，并对其进行更新。在块更新之后，CPU 用更新后的参数替换混合精度参数，并将优化器状态卸载到 NVMe 设备。主机会通过反复执行这些步骤来更新所有块，并在更新完成后开始下一次迭代的前向传播。

借助存储设备，先前工作使得在没有足够 GPU 内存保存完整优化器状态时也能够训练超大规模 LLM。然而，如图 1(b) 和图 1(c) 所示，存储卸载训练在每次迭代中都会承受大量上传/卸载数据传输，包括优化器状态（模型参数、动量和方差，总大小为 6M）以及以 32 位处理的梯度，以使用 [97] 中高度优化的定制 NVMe 卸载引擎（2M）。这些数据传输会通过系统互连（PCIe），在图 1 中以红色箭头表示。Smart-Infinity 的目标是通过计算存储设备（CSD）减少经由系统互连的数据传输。==Smart-Infinity 利用聚合的 CSD 内部带宽，而不是受限的系统互连带宽。为了在多个 CSD 上保持这种带宽，Smart-Infinity 利用 CSD 中的加速器，同时解决真实系统中面向高效训练的一些挑战。==

### B. 计算存储设备

计算存储设备，或近存储处理（near-storage processing, NSP），已经被研究多年 [24]、[35]、[56]、[117]。通过将计算引擎放置在更靠近存储设备的位置，除了减少主机工作负载之外，还可以获得延迟和带宽方面的收益。在众多 CSD 类型 [112] 中，我们专门针对图 2 所示的设备，其中一个轻量级 FPGA 加速器通过产品内部的交换机连接到 SSD；这种结构被广泛用于商用产品 [1]、[7]、[18]、[83]。图 2 给出了一个拥有多个此类 CSD 的主机环境示例。

![[.assets/Pasted image 20260526211022.png]]
【图 2 占位：包含多个 CSD（例如 SmartSSD）的示例环境。】

通常，与普通 NVMe 设备相比，CSD 具有两个独特特征。第一，它有一个加速器（例如轻量级 FPGA），可在靠近存储的位置计算数据。第二，它拥有自己的内部 PCIe 交换机，为 NVMe 设备与加速器之间的直接点对点（P2P）通信提供私有内部路径，而无需通过系统互连产生冗余的存储到主机和主机到存储数据流量。单个 CSD 并不会提供带宽提升，因为 NVMe-FPGA 和 NVMe-主机传输通过相同数量的 PCIe 通道。然而，当系统中存在多个 CSD 设备时（图 2），聚合的内部带宽会随 CSD 数量线性增加，而共享的系统互连带宽保持不变。在 Smart-Infinity 中，我们使用 SmartSSD [83]，这是市场上具有代表性的商用 CSD。

## III. 动机

我们已经讨论了存储卸载 LLM 训练中主机内存与存储设备之间的数据传输瓶颈。在本节中，我们用实际数据直接分析这种开销，并说明为何它难以缓解。

数据传输开销。图 3(a) 展示了使用 ZeRO-Infinity [97] 进行 LLM 训练时的训练时间分解，ZeRO-Infinity 是最先进的存储卸载训练框架。我们在单个 NVMe 设备（SSD）的环境中进行训练。详细实验环境见第 VII-A 节。如第 II 节所述，我们将存储卸载训练分解为前向传播（FW）、反向传播（BW + 梯度卸载）以及更新（Update + 优化器状态上传/卸载）。与传统训练不同，由于存储访问开销，超过 80% 的训练时间花费在更新阶段。无论模型大小如何，数据传输部分都很显著，因此这是存储卸载 LLM 训练中需要解决的关键问题。

系统互连瓶颈。缓解 NVMe 设备数据传输开销的一种方法是使用 RAID 构造更高的通信带宽。图 3(b) 显示了使用 RAID0 增加 SSD 数量时存储卸载训练的归一化加速。不幸的是，在使用超过四块 SSD 后，加速趋于饱和。当使用超过四块 SSD 时，共享系统互连成为新的瓶颈。因此，将 RAID 方案用于存储卸载 LLM 训练存在局限性。

![[.assets/Pasted image 20260526213404.png]]
【图 3 占位：基线训练时间分解以及 RAID0 SSD 数量增加带来的加速。】

该动机研究表明，由于现有系统结构资源有限，存储卸载 LLM 训练中的数据传输开销无法轻易缓解。因此，当我们使用 CSD 作为替代方案时，我们的主要目标是最小化存储设备与主机内存之间经由共享系统互连的数据传输，并且需要充分利用：1）来自多个 CSD 的聚合内部带宽；2）每个 CSD 中加速器的计算能力。

## IV. SMART-INFINITY

![[.assets/Pasted image 20260527103639.png]]
【表 I 占位：使用 Adam 优化器的存储卸载训练中的系统互连流量。】

表 I 概述了应用 Smart-Infinity 后系统互连流量的变化。首先，为了最小化存储设备与主机内存之间的通信，我们将更新计算从 CPU 卸载到 CSD 中的加速器（SmartUpdate）。由此，我们可以受益于 CSD 的快速聚合带宽，将现有存储卸载 LLM 训练方法的通信开销从 (6 + 2)M 降低到 2M。第二，我们提出了一种新的内部数据传输处理器结构，包含缓冲区预分配和交换重叠，可直接应用于 SmartUpdate。当将 CSD 集成到常用主机代码（C++、Python）中时，该处理器结构可以应用，这对于真实系统中 CSD 应用的吞吐量至关重要。第三，我们提出了一种新方法，通过使用 CSD 中 FPGA 的计算能力压缩梯度（SmartComp），将经由共享系统互连的剩余存储写入流量从 2M 进一步减少到 c% × 2M（c：压缩率）。

### A. SmartUpdate：使用 CSD 的近存储更新

如第 II 节所述，在存储卸载 LLM 训练中，更新过程中优化器状态的通信量非常显著。对于传统存储设备，这种经由系统互连（PCIe）的通信是必要的，因为 CPU 执行更新计算。然而，SmartUpdate 将更新过程从 CPU 卸载到 CSD，以减少互连通信量。从存储读取的总数据量相同，但使用的是多个 CSD 的聚合带宽，而不是共享系统互连。

图 4 与基线 [97] 相比，说明了 SmartUpdate 的详细过程。我们以 Adam 优化器 [63] 为例，因为它是现代 LLM 训练 [17]、[34]、[94] 的主要选择。如图 4(a) 所示，基线使用主机 CPU 更新参数。为了使用 CPU 执行更新过程，需要从 SSD 上传梯度和优化器状态。更新完成后，优化器状态被卸载到 SSD。

![[.assets/Pasted image 20260527104225.png]]
【图 4 占位：基线与 SmartUpdate 的存储卸载训练更新过程。】

相反，SmartUpdate 使用 CSD 中的加速器（即 FPGA）更新参数。SmartUpdate 不将梯度和优化器状态上传到主机内存，而是通过直接 P2P 通信将它们直接加载到 FPGA；由于每个 CSD 中存在内部 PCIe 交换机，这种通信是可能的。在加载的梯度和优化器状态存入加速器内存之后，加速器使用更新模块更新参数。我们将在单独的小节（第 V-A 节）中讨论详细架构。基线在更新后会将优化器状态从主机内存卸载到 SSD，而 SmartUpdate 通过内部 P2P 通信直接将更新后的优化器状态发送回 SSD。更新后的权重参数（2M）会从 SSD 传输到主机内存。这一流量在基线中不存在，但与此前上传/卸载优化器状态的流量大小（6M，每个参数三个单精度变量）相比，这一开销较小。此外，这种上行流量可以与其他参数的更新步骤重叠。

当量化总通信量时，基线在读写两方面都需要 8M（梯度 + 三个优化器状态）。SmartUpdate 将更新阶段经由系统互连的总通信量最小化为仅 2M 的读（用于更新后的参数）以及反向传播期间 2M 的写（用于梯度）。

当 SmartUpdate 与单个 CSD 一起使用时，瓶颈只是从系统互连转移到 CSD 内部交换机。然而，真正的优势在扩展 CSD 数量时显现。当 CSD 数量增加时，FPGA 与 SSD 之间的聚合带宽线性增加，而通向主机的系统互连（PCIe）带宽保持不变。虽然 FPGA 数量增加带来的计算能力提升有一定益处，但==聚合内部带宽才是 Smart-Infinity 加速的主要驱动因素。==

### B. SmartUpdate 的内部数据传输处理器

如第 II 节所述，存储卸载训练的一次迭代会将模型划分为多个块，并一次处理一个块。每个块中的参数数量根据估计的内存需求决定。类似地，SmartUpdate 也会根据加速器设备内存容量设置模型参数子组的大小，并用单个 tasklet 处理每个子组。在图 5(a) 所示的朴素实现中，由于每个 tasklet 会占用整个内存空间，tasklet 会顺序执行。幸运的是，我们发现可以==通过在子组之间重叠数据传输来提升吞吐量。==然而，子组之间朴素的数据传输重叠需要额外的设备内存空间以进行直接 P2P 通信，这会导致设备内存中的内存不足（OOM）错误。因此，我们提出了一种内部数据传输处理器优化，在解决设备内存消耗问题的同时，提高 SmartUpdate 的吞吐量。

【图 5 占位：SmartUpdate 的朴素实现以及带内部数据传输处理器优化的 SmartUpdate。】

%%Mmt.：一阶动量，Var.：二阶动量
- **Buffer Init**：给当前 tasklet 分配 FPGA 设备内存 buffer；
- **SSD to FPGA**：从 SSD 把数据读到 FPGA 的 DRAM；
- **Compute**：FPGA 执行 Adam update；
- **FPGA to SSD**：把更新后的数据写回 SSD；

所提出处理器的关键思想是分离变量缓冲区，并延迟传输非紧急变量。在朴素实现中（图 5(a)），过程如下：为当前子组分配缓冲区，从 SSD 读取变量，更新参数（浅蓝色条），并将变量写回 SSD。随后释放缓冲区，以便为下一个子组分配缓冲区。采用我们的优化技术后（图 5(b)），在 SmartUpdate 初始化时，设备内存缓冲区会被预分配，并且为每个优化器状态变量的最大可能大小分别分配。我们使用运行在 CPU 上的两个线程（线程 0 和线程 1）来管理分配的缓冲区。最初，线程 0 拥有这些缓冲区。当它完成更新计算后，会立即将模型参数写回 SSD，因为 GPU 需要这些参数来执行前向/反向传播。然而，其他变量（例如动量和方差）并不急于写回，因为它们只会在下一次训练迭代的更新阶段使用。因此，线程 0 推迟剩余变量的写回，并通知线程 1 开始加载下一个子组的模型参数。由于我们已为最大子组大小预分配了缓冲区，线程 1 可以直接复用相同缓冲区。对于剩余变量，线程 0 的写回与线程 1 的加载也会通过复用缓冲区以类似方式执行，但优先级较低，因为它们对前向/反向阶段并非关键。通过这种优化，我们获得了若干收益：==1）避免重新分配设备内存；2）GPU 可以更早开始前向/反向阶段；3）到 SSD 的数据传输得以重叠。==

### C. SmartComp：CSD 辅助的梯度压缩

SmartUpdate 通过移除优化器状态到主机的传输，减少了大量 SSD 流量。在系统中存在多个 CSD 的情况下，优化器状态（6M）通过 CSD 内部带宽在 CSD 内部传输，而该内部带宽会随 CSD 数量线性扩展。然而，梯度（2M）仍然会通过系统互连，这在 CSD 数量增加时成为新的瓶颈。不幸的是，很难将梯度卸载与更新步骤重叠，因为在开始更新步骤之前，混合精度 LLM 训练存在一些约束。首先，由于半精度的表示范围有限，必须在更新前检查非数（NaN）和无穷值（Inf）以进行损失缩放 [84]。第二，在更新阶段之前，需要整个模型的总梯度范数以进行梯度裁剪。此外，==SSD 的写入带宽通常远低于读取带宽==，这进一步加剧了问题。

%%LLM 训练常用 **mixed precision training**，也就是混合精度训练。通常前向/反向计算是FP16/BF16，优化器状态和参数更新常用FP32。FP16 的好处是省显存、算得快，但缺点是：**能表示的数值范围比 FP32 小很多**。所以训练中可能出现NaN(非法计算结果) Inf（无穷大），所以在update前必须检查。

损失缩放：所以训练时先把 loss 放大，比如乘以一个 scale，这样反向传播得到的梯度也会变大，避免太小的梯度下溢。但如果 scale 太大，又可能导致梯度溢出，变成 Inf 或 NaN。所以系统需要检查：
- 如果没有 NaN/Inf，说明 scale 可能安全；
- 如果出现 NaN/Inf，说明 scale 太大，需要跳过本次 update 或降低 scale。
因此，**在确认所有梯度是否正常之前，不能开始 optimizer update**。

梯度裁剪：防止梯度爆炸，先计算所有梯度总范数，可能需要总体缩小梯度，需要所有层所有块参数。
梯度是由GPU产生，传给CPU---SSD%%

幸运的是，瓶颈由梯度引起这一事实为 Smart-Infinity 提供了一个有趣机会：压缩梯度。众所周知，DNN 训练能够容忍一定程度的误差，尤其是梯度误差。梯度压缩方法 [20]、[21]、[77]、[111]、[119] 被广泛用于缓解神经网络训练中的通信开销，并且在现代大模型的分布式训练中几乎已成为常规做法 [98]、[111]。

借助 CSD 中的加速器，我们提出 SmartComp，将梯度压缩应用在 SmartUpdate 之上：==使用 GPU 压缩梯度，并在 CSD 上更新之前解压缩。==尽管算法有许多变体，我们为 SmartComp 实现了基于幅值的压缩方法 [20]、[77]。在该方法中，首先按梯度幅值排序，并选择较大的梯度。幅值较小的梯度被替换为零，因为与幅值较大的梯度相比，它们对原始梯度方向的影响较小。压缩结果是索引列表和值列表，分别表示高幅值梯度的位置及对应数值。这是一个可行选择，因为相对较重的排序工作可以在强大的 GPU 上完成，而 CSD 中的轻量级 FPGA 执行解压缩部分，解压缩只涉及根据索引散布数值。其他方法，例如低秩分解 [23]、[119]，也可以应用于 SmartComp。然而，调优浮点矩阵乘法性能具有挑战性且并不简单 [28]、[29]、[122]。基于幅值的压缩以较低 DSP 成本提供了可比的模型质量，因此我们采用了基于幅值的压缩。

![[.assets/Pasted image 20260527111921.png]]
【图 6 占位：SmartComp 概述，包括带压缩的反向传播和使用压缩梯度的更新。】

图 6 说明了 SmartComp 的整体过程。在反向传播生成梯度后，GPU 压缩梯度。例如，GPU 通过对每个块排序来选择幅值较高（例如 1%）的元素。不同于将完整梯度向量卸载到 SSD，只有压缩后的梯度被卸载到 SSD。在更新过程中（图 6(b)），通过 CSD 内部 P2P 通信，压缩梯度和优化器状态被加载到 FPGA。由于更新操作（例如 Adam [63]）具有逐元素性质，需要完整矩阵，因此在更新前，我们首先使用索引信息将压缩梯度解压缩为与原始梯度向量相同的大小。为此过程，我们设计了==解压缩模块==，该模块将在单独的小节（第 V-B 节）中描述。解压缩后，SmartComp 遵循第 IV-A 节所示的相同过程。结合 SmartUpdate 和 SmartComp 后，经由系统互连的剩余数据传输变为压缩梯度的卸载量和更新后权重参数的上行传输量，而这些是 GPU 中继续下一次前向和反向传播所必需的信息。结合第 IV-B 节中内部数据传输处理器会更紧急地传递权重参数这一事实，以及 SSD 读取速度更快这一事实，SmartComp 极大地帮助 Smart-Infinity 扩展到更多 CSD。

### D. 到多个 CSD 的工作负载分配

在前几节中，为便于理解，我们使用单个 CSD 描述了 Smart-Infinity 的细节。然而，Smart-Infinity 通过使用多个 CSD 并利用高内部带宽来获得加速。因此，有必要讨论 Smart-Infinity 如何管理这些设备。

分配每个 CSD 工作负载的关键思想是，更新优化器状态中的所有操作均以逐元素方式执行。利用这一点，Smart-Infinity 将模型参数展平并均匀分配给各个 CSD，每个 CSD 负责更新其拥有的参数。随后，优化器状态被分配并初始化在拥有相应参数的 CSD 上。一次反向传播后，生成的梯度被卸载到所有者 CSD，由其通过附加 FPGA 与 SSD 之间的 P2P 通信执行更新计算。

由于使用展平的模型参数，分配过程与模型架构无关。这使得 Smart-Infinity 的采用非常简单，最终用户无需考虑模型架构信息，例如层、隐藏维度或注意力头数量。

在本节中，我们介绍在 FPGA 中实现的加速器架构，用于支持 SmartUpdate 和 SmartComp。图 7 展示了用于 SmartUpdate（第 IV-A 节）的更新器以及用于 SmartComp（第 IV-C 节）的解压缩器微架构。尽管 Smart-Infinity 主要描述了使用 Adam 优化器和基于幅值的压缩方法，但加速器被设计为支持用户选择的多种算法。

![[.assets/Pasted image 20260527115701.png]]
【图 7 占位：Smart-Infinity 微架构。】

总体而言，Smart-Infinity 的更新器和解压缩器以适合加速器 DRAM 大小（D）的子组为单位处理模型。因此，在处理子组 i 时，索引从 i × D 到 (i + 1) × D − 1 的参数是目标参数。S 表示适合加速器内部 BRAM 缓冲区的处理块大小。

### A. 通用更新器

图 7 下半部分展示了 Adam 优化器的示例更新器。对于更新器，Smart-Infinity 使用第 IV-B 节中所示的优化技术加载子组大小（D）的梯度、优化器状态和目标参数。更新器由多个更新器处理单元（PE）组成，它们并行更新目标参数。每个 PE 从加速器内存获取梯度、优化器状态和目标参数。通常，优化器算法需要多种类型的移动平均。因此，我们放置了 SIMD AXPBY 单元，以处理通用平均操作。该单元接收两个输入向量（即 A 和 B），并将指定系数（即 α 和 β）分别乘到它们上。乘法之后，它对两个向量执行逐元素加法。上述过程可以通过改变系数用于多种平均操作。使用 AXPBY 单元，更新器将优化器状态（例如动量和方差）融合到梯度中。在所有优化器状态被应用到梯度之后，更新器使用它们更新目标参数。新的优化器状态和更新后的参数被传递到加速器内存。更新后的数据通过第 IV-B 节的数据传输处理器交换回 CSD 的存储。注意，更新器可以扩展到其他优化器，例如 SGD、AdaGrad [39] 和 AdamW [78]，因为大多数优化器都使用移动平均的变体。我们在第 VII-F 节进一步实现并测试了其他更新器。

### B. 通用解压缩器

作为一种具有代表性的压缩方法，Smart-Infinity 应用了基于幅值（即 Top-K）的算法。图 7 上半部分是 Top-K 压缩示例解压缩器的微架构。1在第一次迭代中，目标参数的梯度缓冲区被初始化为零。2解压缩器从加速器内存获取压缩梯度。典型 Top-K 压缩算法将梯度压缩为两部分：索引和值。因此，解压缩器迭代地加载缓冲区大小（S）的索引和值。3对于每次迭代，解压缩器使用索引值（idx[j]）确定用于映射数值（val[j]）的目标位置。4在输出向量中，本次迭代 j 中选出的目标参数的部分 Top-K 元素被填充为其对应数值，其他元素填充为零。在解压缩完成前，解压缩器会重复这一过程。当所有 Top-K 元素处理完成后，梯度缓冲区包含了一个向量，其中填充有专用于子组 i 目标参数的 Top-K 梯度值。解压缩完成后，解压缩后的梯度值已位于加速器内存中，因此更新器（第 V-A 节）可以使用它们。

图 9 展示了 Smart-Infinity 与基线相比的训练时间分解和加速，并包含消融实验。我们将训练时间分为三部分：前向时间、带梯度卸载的反向时间，以及带优化器状态上传和卸载的更新时间。总体而言，基线训练时间结果受到严重通信开销的影响，正如第 II 节和第 III 节所讨论的。在使用 6 块 SSD 的 GPT-2 8.4B 模型中，带优化器状态通信的更新时间占基线训练时间的 75.57%。即使 SSD 数量增加到 10，由于系统互连瓶颈，训练时间仍保持不变；这一趋势在所有测试用例中都持续存在。SmartUpdate（SU）减少了经由系统互连的通信量，在 6 块 SSD 下提供 1.18×∼1.24× 加速，在 10 块 SSD 下提供 1.54×∼1.60× 加速。进一步应用传输处理器优化（SU+O）后，SmartUpdate 带来的加速在 10 块 SSD 下提升到最高 1.60×∼1.66×。这一结果表明，优化技术成功重叠了 SSD-FPGA 通信。此外，在优化后的 SmartUpdate 之上，SmartComp 相比 SmartUpdate 又提供 1.22×∼1.31× 的额外加速，相对基线实现 1.85×∼1.98× 加速。通过分解结果可以看出，SmartComp 成功进一步减少了优化后 SmartUpdate 中剩余的梯度卸载时间。

对于所有测试模型，加速趋势几乎相同。这是因为现代 LLM 模型都基于 Transformer [118]，只在一些模型设计参数上有所不同。此外，在所有情况下，主要瓶颈都是存储带宽，使得模型大小或结构对训练时间相对不那么重要。这解释了加速趋势的稳定性。

### D. 扩展到更大模型
![[.assets/Pasted image 20260527123508.png]]
【图 10 占位：Smart-Infinity 与基线在更大模型规模上的可扩展性。】

存储卸载训练允许使用有限资源训练更大的模型。因此，检查 Smart-Infinity 是否在各种大模型规模上相对基线带来稳定加速非常重要。图 10 是 Smart-Infinity 在不同大小的大型 GPT 模型上的可扩展性测试，并与基线进行比较。结果显示，Smart-Infinity 在更大模型上实现了稳定加速。即使对于 GPT-2 33.0B 模型，Smart-Infinity 在使用 6 块和 10 块 SSD 时，也分别相对基线提供 1.37× 和 1.88× 加速。由于训练时间中的通信比例保持稳定，因此在大模型上的加速也是稳定的。这很自然，因为在 Transformer 模型训练中，通信量与模型参数数量成正比。此外，使用更多 CSD 仍然会为更大模型带来加速。因此，Smart-Infinity 可扩展到更大模型，而基线则受到巨大上传和卸载开销的影响。

### E. CSD 数量和 GPU 等级实验

Smart-Infinity 受益于 CSD 的聚合带宽，因此检查加速对 CSD 数量的敏感性是必要的。此外，检查 Smart-Infinity 对不同 GPU 等级的敏感性也很有帮助。实验结果表明，随着 CSD 数量增加，Smart-Infinity 可以获得更好的可扩展性，而基线由于系统互连瓶颈难以从更多 SSD 中继续受益。更高等级 GPU 可以减少前向和反向计算时间，但当训练受存储传输限制时，Smart-Infinity 通过减少存储侧传输仍能带来显著收益。低端或内存容量较小的 GPU 场景中，存储卸载更有必要，因此 Smart-Infinity 的优势也更具实用意义。

### F. 对不同模型、优化器与压缩方法的评估

Smart-Infinity 的设计不依赖特定模型架构，因为它展平模型参数并以逐元素方式执行更新。实验结果表明，除 GPT-2 和 BERT 外，它也适用于 BLOOM 和 ViT 等模型，并保持相似的加速趋势。这说明该方法可以应用于解码器、编码器以及视觉 Transformer 等不同模型结构。

Smart-Infinity 的更新器也可扩展到其他优化器。由于许多优化器都可表达为移动平均或逐元素运算的变体，FPGA 更新器能够支持包括 SGD、AdaGrad 和 AdamW 在内的多种优化算法。实验表明，不同优化器下 Smart-Infinity 都能够减少系统互连通信，并带来稳定加速。

### G. 压缩率敏感性与模型质量

为研究 Smart-Infinity 对压缩率的敏感性，作者在表 IV 和图 16 中测试了从 1% 到 10% 的多种压缩率。加速与模型质量之间存在一定权衡。然而，即使压缩程度远高于默认设置，也不会显著损害模型质量，同时加速几乎逐渐增加。这表明梯度压缩能够有效改善 Smart-Infinity 的扩展性，并且在合理范围内不会明显破坏收敛或最终精度。

### H. 稳定性与数值问题

混合精度 LLM 训练中存在数值稳定性问题，例如 softmax 等操作可能引发不稳定。Smart-Infinity 在更新路径上改变了数据移动和执行位置，因此需要验证其不会引入额外的不稳定性。实验结果显示，Smart-Infinity 与基线相比保持了相近的模型质量和训练行为，表明近存储更新与压缩/解压缩过程可以在不损害训练稳定性的情况下运行。

### I. 系统成本效率分析

存储卸载训练的目标之一是在有限 GPU 内存和有限硬件资源下训练大模型。因此，系统成本效率十分重要。Smart-Infinity 通过利用 CSD 的内部带宽和近存储计算能力，在不增加大量 GPU 的情况下提高训练速度。与单纯增加 SSD 并使用 RAID0 相比，Smart-Infinity 更能利用新增设备，因为新增 CSD 不仅提供容量，还提供内部带宽和计算能力。结果表明，在相似存储容量扩展下，Smart-Infinity 具有更好的性能收益和成本效率。

### J. 应用案例研究：微调

LLM 微调通常不需要与预训练相同规模的计算能力，但仍可能受到参数、优化器状态和梯度内存需求的限制。因此，存储卸载训练对微调场景也有意义。Smart-Infinity 适合这种应用场景，因为它可以减少存储卸载训练中的主要瓶颈，使用户能够在有限 GPU 资源下更快地进行大模型微调。作者的应用案例研究表明，Smart-Infinity 在微调任务中也能提供显著加速，同时保持模型质量。

## VIII. 讨论

### A. 另一种场景：多 GPU 拥塞拓扑

当系统的 PCIe 通道更加受限时，GPU 和存储可能安装在共享同一 PCIe 交换机的 PCIe 扩展设备中，因此点对点通信拓扑会发生变化。为测试这种场景，作者额外配置了一个最多含三块 GPU 的拥塞拓扑，如图 17(a) 所示。由于 PCIe 扩展机箱限制，作者将单槽 RTX A4000 GPU 插入扩展设备。图 17(b) 显示了使用 1∼3 块 A4000 GPU 时，Smart-Infinity 相对基线的训练时间和加速。作者采用张量并行作为多 GPU 策略，因为它在单服务器设置中被广泛选择 [108]。梯度计算完成后，每个 GPU 识别拥有对应参数的 CSD，并使用 Smart-Infinity 执行更新。

![[.assets/Pasted image 20260527124036.png]]
【图 17 占位：( a )多GPU拥塞拓扑实例。( b ) Smart - Infinity的训练时间分解和基线在这样的环境下的训练时间分解为1~3 GPUs ( GPT-2 1 .16B)。】

使用张量并行在利用更多 GPU 时略微减少了 “FW” 和 “BW” 时间。然而，在这种替代场景中，远程放置的 GPU 会引入一些额外的模型和激活传输流量，这些流量必须与 CSD 共享同一 PCIe 互连。与默认拓扑相比，这会给 “BW+Grad. Offload” 阶段造成一些开销，但不会显著影响 GPU 空闲的 “Update+Opt. Upload/Offload” 阶段。因此，观察到的加速低于默认设置，这说明性能受 PCIe 拓扑结构影响。然而，在使用 10 个 CSD 时，Smart-Infinity 仍提供 1.66×∼1.86× 加速，表明它可以扩展到 PCIe 通道更加受限且具有多个 GPU 的环境。

### B. 对其他压缩算法的讨论

SmartComp 的当前实现使用基于幅值的梯度稀疏化，因为排序和选择可由 GPU 高效执行，而 FPGA 解压缩只需执行轻量级散布操作。其他压缩方法也可能适用于该框架。例如，低秩分解可以减少通信量，但它依赖浮点矩阵乘法，且在轻量级 FPGA 上高效实现更具挑战。对于这类方法，在真实系统中可能会出现类似的加速器资源和性能调优问题。这表明，压缩算法的选择需要考虑 GPU 端压缩成本、CSD 端解压成本、模型质量以及硬件资源消耗之间的权衡。

### C. 面向未来系统架构的存储扩展

随着模型继续变大，训练系统需要更多存储容量。仅通过交换机扩展存储设备可以增加物理插槽数量，但不会增加到主机的原始链路带宽。当更多设备用于获得更大容量时，链路带宽瓶颈只会更加严重。作者认为 Smart-Infinity 非常适合这种趋势。使用 CSD 的 Smart-Infinity 中，更多容量同时意味着更多内部带宽和可用于利用这些带宽的计算能力。随着系统架构朝着共享更多资源的方向演进，这类解决方案预计会变得越来越普遍。

## IX. 相关工作

### A. 近数据处理

近数据处理的思想已经被广泛研究，范围从 DRAM、SRAM、NVRAM 到存储。早期近数据处理研究在 20 世纪 90 年代由将 DRAM 与逻辑集成的工作推动 [38]、[57]、[64]、[65]、[79]、[90]。后来，随着 3D 堆叠内存 [91] 的兴起，一些工作提出利用与内存芯片堆叠在一起的逻辑芯片来服务各种应用 [8]、[11]、[16]、[32]、[41]、[51]、[60]、[86]、[127]、[128]、[130]。最近，由于 3D 堆叠内存发展出现不连续性，学术界和工业界都开始回到 DDR 变体，有时通过修改芯片内部电路 [33]、[47]、[59]、[68]、[70]、[73]、[75]、[105]、[106]，有时使用 DIMM 上的缓冲芯片 [13]、[40]、[58]、[69]，或二者结合 [61]、[89]。虽然原理相似，这些方法也得到了商业产品支持 [33]、[68]、[73]。

这种趋势也出现在存储设备上。从在 IO 子系统附近放置独立加速器的思想开始 [109]、[123]，早期思路是在数据库或大数据工作负载推动下，利用嵌入式核心进行计算 [35]、[56]、[117]。随后出现了许多针对不同问题的后续方法 [52]、[54]、[55]、[66]、[82]、[124]。然而，对于许多应用而言，嵌入式核心的计算能力通常不足 [24]、[100]、[117]，因此更多方法开始采用专用加速器。ASIC 被用于基因组序列分析 [81]、私有信息检索 [76] 或机器学习查询 [80]。一些方法使用 FPGA 来增强灵活性，并面向类似问题 [53]、[71]、[100]、[104]、[114]、[125]。值得注意的是 GradPIM [61] 和 OptimStore [62]，因为它们都像本文工作一样面向 DNN 训练。然而，它们假设使用专用内存/存储芯片，使这些解决方案较不实用。此外，它们仅在模拟器上实现，并未考虑真实系统集成问题。

最近，若干商业产品出现，它们在 SSD 封装中配备 FPGA 加速器 [1]、[7]、[18]、[83]，用于近存储处理。SmartSSD [83] 是一个代表性产品，尤其被用于数据库工作负载 [72] 和排序 [101]、[102]。一个类似平台被部署到商业云中用于数据库扫描 [18]。有一些工作 [50]、[74]、[110] 利用 CSD 进行近存储处理以加速神经网络训练，但它们主要关注预处理训练数据或嵌入表，以减少存储开销。据我们所知，Smart-Infinity 是第一个使用多个 CSD 来缓解 DNN 训练中系统互连瓶颈的工作。我们的工作建立在 SmartSSD 之上，但不限于特定产品。

### B. DNN 训练加速

随着深度学习模型不断增长、训练时间变得更长 [34]、[85]、[94]、[115]，许多先前工作都旨在减少训练时间。分布式训练是一种利用多个工作节点的有吸引力的方法。数据并行 [27]、[31]、[42]、[129] 复制整个模型，每个工作节点保存模型并独立处理训练批次。然而，当模型大小超过工作节点内存限制时，需要将模型跨工作节点拆分，模型并行 [19]、[22]、[67] 使训练此类大模型成为可能。流水线方法 [48]、[49]、[87]、[126] 被提出以解决模型并行中工作节点利用率低的问题。每个工作节点通过将小批次划分为更小的微批次并将其重叠来并发参与训练。

在这种分布式训练中，服务器之间的通信成为瓶颈。梯度压缩是减少这种通信开销的一种流行方法。即使在大模型中，它也能在达到相近精度的同时有效减少训练时间 [98]、[111]。它大致可以分为两类：梯度稀疏化 [15]、[21]、[77] 和低秩分解 [23]、[119]。前者发送一部分梯度，通常使用幅值准则。其收敛性已在先前工作中得到证明 [12]、[107]，并且表现出可比的精度。低秩分解将梯度矩阵分解为两个小的低秩矩阵，以减少通信量。[119] 使用幂迭代方法减少分解开销。两种方法都使用误差补偿，即记住压缩产生的误差，并在下一步压缩前将其加入梯度。[116] 发现，由于 Adam 优化器的非线性，误差补偿不适用于 Adam。因此，它在预热期后对方差项进行预条件处理，使其等价于动量 SGD。

## X. 结论

我们提出了 Smart-Infinity，这是一个新型的基于 CSD 的框架，用于加速存储卸载 LLM 训练。通过利用每个 CSD 中提出的 FPGA 加速器，LLM 训练中的传输瓶颈得到了有效解决。我们进一步提供了传输优化和 CSD 辅助梯度压缩，以提升所提出系统的加速效果。Smart-Infinity 仅使用现成产品就已完全集成到 PyTorch 中，使其成为一种可直接使用的解决方案。实验结果表明，Smart-Infinity 实现了显著加速，并在系统附加 CSD 数量增加时表现出良好可扩展性。我们的实现可在 https://github.com/AIS-SNU/smart-infinity 获取。
