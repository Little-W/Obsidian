## 摘要

近年来，图神经网络（Graph Neural Networks，GNNs）已经成为强大的数据分析工具，并在多种应用中超过了传统算法。然而，现实世界数据集规模的增长已经超出了集中式 CPU 或 GPU 系统的能力。为应对这一挑战，研究者提出了许多分布式系统。然而，由于网络数据交换缓慢，这些系统存在硬件利用率低的问题。SSD 具有大容量和改进的访问延迟，是一种有前景的替代方案；但在单台计算机上进行基于 SSD 的 GNN 训练会受到 PCIe 总线数据传输缓慢的瓶颈限制。我们的实验也证实，这一瓶颈会导致 CPU 和 GPU 利用率较低。此外，SSD 内 GNN 训练的设计还受到闪存访问缓慢的阻碍。

FlashGNN 是一种提出的解决方案，它克服了 PCIe 瓶颈，充分利用闪存芯片中的 I/O 并行性，并最大化从已取回闪存块中获得的数据复用，从而实现高效的 GNN 训练。我们通过设计 SSD 固件来协调数据移动和硬件单元访问，以实现这一目标。为了解决由缓慢闪存和有限资源带来的设计挑战，我们提出了一种新的逐节点 GNN 训练方法、一种高效的闪存请求调度算法，以及一种高性能子图生成方法。实验结果表明，与最先进的基于 SSD 的 GNN 训练系统 Ginex 相比，FlashGNN 在四个典型真实世界图数据集上取得了 4.89× 到 11.83× 的加速，并实现了 57.14× 到 192.66× 的能耗节省。此外，FlashGNN 的效率最高比增强后的最先进存储内加速器 SmartSAGE+ 高 23.17×。

## I. 引言

深度神经网络（DNN）在学术界和工业界的快速发展，使图神经网络（GNNs）[5], [12], [21], [41], [44], [48] 成为一种强大的工具，其应用已经超越图像和文本领域。GNN 作为一类新的 DNN，已经在图结构数据上的多种任务中证明了有效性 [43], [50], [52]。通过使用嵌入特征捕获图中节点之间丰富的关系信息，GNN 表现出很强的表达能力，非常适合节点分类 [21]、推荐 [32], [48] 和链接预测 [49] 等任务。然而，GNN 训练面临独特挑战，尤其是在数据准备阶段。与传统 DNN 中训练样本相互独立不同，GNN 样本彼此相连，因为它们构成图的一部分。在 GNN 训练期间，需要遍历图，并访问一个批次中节点及其邻居节点的特征，以执行采样和聚合操作。这些操作涉及大量数据访问，但会受到局部性较差 [22], [28], [33] 的影响，从而导致性能不佳。

流行的 GNN 框架 [14], [25], [26], [34], [37], [42], [45]–[47], [53] 通常依赖主存来存储整个图数据集。然而，随着数据集越来越大，达到数十亿节点和边，并超过主存容量（通常为数百 GB 甚至数 TB），这些传统 GNN 训练系统的可扩展性成为问题。为解决这一挑战，研究者设计了并行和分布式 GNN 训练系统，将大型图数据集存储在多个计算节点上 [27], [40], [51]。然而，图的稀疏且不规则结构要求分布式 GNN 训练系统通过缓慢网络频繁进行数据通信，导致 CPU 利用不足。此外，这些分布式 GNN 训练系统往往成本很高。因此，基于 SSD 的 GNN 训练成为一种必要方案 [22], [33]。最先进 NVMe SSD 的大容量和高性能使基于 SSD 的 GNN 训练成为一种有前景的替代方案。

最近，Ginex [33] 探索了在单机上基于 SSD 的大规模图数据集 GNN 训练系统，它通过在主存中缓存数据来实现。为了缓解慢速 SSD 导致的 I/O 瓶颈，Ginex 提出了一种新的特征向量缓存方法，利用 GNN 训练中的确定性数据访问模式。然而，Ginex 仍然受到慢速 SSD 访问的影响。我们的实验表明，Ginex 在为每个训练批次准备并传输数据方面花费了超过 60% 的时间。这一性能限制主要源于狭窄的 PCIe 带宽，它无法利用 SSD 内部闪存提供的大量 I/O 并行性。更近的 SSD 内 GNN 训练加速器 SmartSAGE [22] 将子图生成和输入节点特征聚合卸载到 SSD，利用 SSD 的存储容量，并减少狭窄 PCIe 总线上的数据移动开销。遗憾的是，SmartSAGE 忽略了从慢速闪存获取图结构和输入节点特征时较差局部性的优化，错失了潜在性能提升。此外，SmartSAGE 没有消除通过狭窄 PCIe 总线从 SSD 到主机的数据移动，因此吞吐量较低。

为克服现有 GNN 训练系统的限制，我们提出了一种新的 SSD 内加速器 FlashGNN。该创新加速器直接在 SSD 控制器中执行 GNN 训练，实现两个主要目标：1）它充分利用底层闪存芯片提供的大量 I/O 并行性，消除了主存和 GPU 之间通过 PCIe 总线进行数据通信的需求，从而有效利用可用资源并提升整体效率；2）它通过最大化从取回的闪存块中的数据复用来优化闪存局部性，从而缓解慢速闪存访问的负面影响。凭借这些改进，FlashGNN 为更高效的 GNN 训练提供了有前景的解决方案。

然而，FlashGNN 目前也面临若干挑战。第一，在采用传统逐层 GNN 训练时，慢速闪存会抑制计算单元利用率。第二，DRAM 容量有限会导致 DRAM 和闪存之间频繁的数据交换，这显著影响训练吞吐量。我们的实验结果表明，受限的 DRAM 容量使增强后的 SmartSAGE [22] 不如 Ginex 有效。第三，图结构的稀疏和不规则性质导致闪存页中存储的节点特征利用效率低，需要重复访问闪存块。此外，图结构会在生成 GNN 训练所用子图时引入大量时间开销，从而增加训练过程的复杂性和持续时间。

为解决前两个问题，我们提出了一种新的逐节点 GNN 训练框架，它有效降低内存占用并减少对慢速闪存的访问。该框架在节点依赖数据可用后立即启动计算，从而消除逐层训练中的同步开销。我们在开发该方法时受到了 [3] 的启发。为解决第三个问题，我们提出了一种高效的闪存块请求调度算法。该算法最大化利用一个块中存储的特征向量，而这些特征向量由一个训练批次中的多个子图共享。因此，它消除了重复访问块的需要。此外，我们在闪存芯片处设计了过滤器，以避免通过缓慢闪存通道总线进行不必要的数据传输。为了提高子图生成效率，我们引入了一种数据驱动的子图生成算法。该算法主动最大化利用 DRAM 中已有的边列表来生成子图。一旦主动生成的子图准备就绪，就会立即被使用。为了评估 FlashGNN，我们使用事件驱动的微架构模拟器，并使用 Zsim [36] 测量固件开销。这些评估为 FlashGNN 的性能和有效性提供了有价值的见解。

总之，我们的工作做出了以下关键贡献：

- 我们提出了一种新的用于 GNN 训练的 SSD 内加速器，该加速器利用 SSD 控制器充分挖掘闪存芯片提供的大量 I/O 并行性。该方法最大化取回闪存块内的数据复用，优化性能。
- 我们引入了一种逐节点 GNN 训练框架，有效降低内存占用并减少对慢速闪存的访问。通过在节点依赖数据可用时启动计算，我们消除了同步开销并提高效率。
- 我们提出了一种高效的闪存块请求调度算法，最大化复用一个块中存储的、由同一训练批次中多个子图共享的特征向量。这种方法消除了重复访问慢速闪存的需求，提高了整体性能。
- 我们提出了一种数据驱动的子图生成算法，主动最大化利用 DRAM 中可用的边列表来生成子图。这一优化策略提高了子图生成效率。
- 我们的实验结果证明了 FlashGNN 的有效性。在四个典型真实世界图数据集上，与最先进的基于 SSD 的 GNN 训练系统 Ginex [33] 相比，FlashGNN 实现了 4.89× 到 11.83× 的加速，并实现了 57.14× 到 192.66× 的能耗节省。此外，在效率方面，FlashGNN 最高比增强后的最先进 GNN 训练存储内加速器 SmartSAGE+ 高 23.17×。

### B. 监督式 GNN 训练

[图 2 占位：监督式 GNN 训练过程]

图 2 展示了 GNN 的监督训练过程。开始时，模型用随机权重和偏置初始化。随后训练集被划分为批次，每个批次中的每个节点都有一个标签。

对于每个批次，节点特征通过 Aggregate 和 Combine 函数进行处理。遍历所有 L 层之后，模型为每个节点生成预测标签。损失函数用于量化预测标签与真实标签之间的差异。通过从输出层开始并向输入层反向传播由损失函数计算得到的梯度，模型的权重和偏置会被更新，以最小化损失函数。

这一迭代过程会持续多个 epoch，直到损失函数收敛。模型训练完成后，可用于预测新图中的节点标签。给定新图中节点的特征，模型预测相应标签。

### C. SSD 架构

SSD（solid-state drive，固态硬盘）[2], [17], [24], [29]–[31], [38], [39] 是一种使用闪存进行数据存储的存储设备。它由四个主要组件组成：控制器、DRAM、闪存通道控制器和闪存芯片。控制器管理 SSD 与主机设备之间的数据流，DRAM 作为频繁访问数据的缓存。闪存通道控制器负责与作为存储介质的闪存芯片通信。一个闪存芯片由多个 die 组成，每个 die 包含多个 plane。一个 plane 包含许多 block，一个 block 包含多个闪存 page。闪存 page 通常为 2KB 到 16KB，是闪存芯片上最小的可读或可写单元。

SSD 控制器由两个模块组成：主机接口逻辑（HIL）和闪存转换层（FTL）。HIL 实现存储协议（SATA 或 NVMe）以与主机通信。它通过 HIL 处理主机与 SSD 之间的请求拉取和响应发送。FTL 通过维护逻辑地址和物理地址之间的映射来管理存储资源。物理地址指定闪存芯片上的物理位置。此外，FTL 调度活动事务，并执行垃圾回收和磨损均衡。

SSD 内部存在显著的 I/O 并行性 [29], [31]。例如，考虑一个具有 32 个通道、每个通道包含 4 个芯片、每个芯片包含 4 个 plane 的 SSD。当所有闪存 plane 并行工作时，聚合带宽可达到 57.1GB/s。然而，由于数据布局效率低、通道总线狭窄以及 PCIe 总线带宽较低，实际 I/O 并行性通常受到限制。

### D. SSD 内 GNN 训练的动机

[图 3 占位：Ginex 运行时分解]

为了解决现实世界图数据集超过 DRAM 容量的挑战，现有 GNN 训练系统使用 SSD 作为外部存储设备来存储数据。在 GNN 训练期间，每个批次都需要节点及其邻居节点的特征向量。然而，由于图的稀疏性和较差空间局部性，边列表和节点特征向量分散在 SSD 中，导致访问效率降低。此外，在数据准备阶段，数据从 SSD 读取，经 PCIe 总线传输到 CPU 内存，然后再传送到 GPU 进行计算。这种大量数据移动成为主要性能瓶颈。

图 3 展示了在 Ginex [33] 这一前沿基于 SSD 的 GNN 训练系统中，GNN 训练时间的分解。实验显示，超过 60% 的训练时间用于准备并传输每个批次的数据，这表明存在显著的内存约束。

为应对这些挑战，将 GNN 训练部署在 SSD 内部能够消除昂贵的数据移动。此外，它还能利用 SSD 的潜在高带宽和并行性，而这些能力在仅依赖 PCIe 总线时无法被充分利用。这种方法不仅提高 I/O 效率，还降低能耗。

## III. FlashGNN 设计

在本节中，我们讨论 FlashGNN 的设计。首先，我们介绍一种高效的闪存块请求调度器。其次，我们提出一种新的逐节点 GNN 训练方案。第三，我们描述一种数据驱动的子图生成方法。最后，我们深入说明固件实现。

### A. FlashGNN 架构

[图 4 占位：FlashGNN 架构]

图 4 展示了 FlashGNN 的高层架构，它同时执行邻居采样和消息传递。执行过程由运行在带内存处理器上的固件协调。

**邻居采样。** FlashGNN 从闪存块中检索所需边列表，并使用图结构转换表（GST）对每个节点的邻居进行采样。该过程构造用于消息传递阶段的子图。此外，如 III-D 节所述，FlashGNN 利用已取回块中剩余的边列表，主动采样当前批次之外的节点。

**消息传递。** 消息传递包括两个阶段：前向传播和反向传播。在前向传播期间，FlashGNN 使用 III-B 节描述的请求调度算法，从具有预定义数据布局的闪存中读取采样子图中节点的输入特征。它应用 Aggregate 和 Combine 操作来生成中间特征和输出特征。输出特征可用后，FlashGNN 进入反向传播阶段。它计算梯度，并执行 ∇Aggregate 和 ∇Combine 操作以获得中间梯度。然后，中间梯度继续接受 ∇Aggregate 和 ∇Combine 操作，最终产生输入梯度计算。详细计算过程见 III-C 节。每一层权重在批训练结束时更新。

**聚合器。** 聚合器为节点邻居执行聚合函数，并使用多个 SIMD 核加速操作。为缓解 DRAM 访问延迟，聚合器使用双缓冲。聚合器输出进入输出缓冲区，并在输出缓冲区填满时写入 DRAM。消息传递固件发出命令以激活 SIMD 核，并协调缓冲区、DRAM 和 SIMD 核之间的数据移动。

**组合器。** 组合器由多个权重固定的脉动阵列组成，用于加速矩阵向量乘法（MVM）。与聚合器类似，每个脉动阵列都有输入缓冲区和输出缓冲区。此外，权重缓冲区有助于在不同层之间高效切换权重，并按需将所需权重流式传输到脉动阵列。消息传递固件发出命令以访问脉动阵列，并协调缓冲区、DRAM 和脉动阵列之间的数据移动。

### B. 高效块请求调度

FlashGNN 以块为单位使用闪存。每个块由分布在一个闪存芯片 n 个 plane 上的 n 个 page 组成。这些块存储多个输入节点特征。图 5 展示了闪存块的组织方式，其中 Node i 表示输入特征 h0_i。为提高闪存访问效率，使用 multi-plane read 命令同时读取一个块内所有 page。

[图 5 占位：闪存块组织]

[图 6 占位：高效块请求调度示例]

我们观察到，传统 GNN 训练系统由于反复访问输入特征块而性能较差。具体来说，由于其逐层方案，这些系统难以有效读取当前批次子图所需的输入特征。该限制源于 DRAM 容量不足以容纳所有特征，导致一些特征在计算需要之前被换出内存。例如，输入特征以逐层顺序读取：先访问第 1 层所需的输入特征，再访问第 2 层所需的输入特征，从而导致冗余块访问。图 6 通过图 6(a) 所示子图和图 6(b) 所示数据布局展示了这一观察结果。

我们将块 n 记为 Cn。为了读取第 1 层节点所需的输入特征，Ginex 读取 C2、C5、C11、C10、C2、C10 和 C3，以获取 h0_9、h0_10、h0_22、h0_46、h0_43、h0_8、h0_40、h0_41 和 h0_15。随后，为了读取第 2 层节点所需的输入特征，它访问 C2、C10 和 C5，以读取 h0_11、h0_42 和 h0_20。这种调度导致 C2、C5 和 C10 在两层之间被重复访问，并导致一个块内特征利用不足。此外，芯片冲突会降低芯片级并行性，导致性能较差。例如，读取块 C2、C5、C11、C10、C2、C10 和 C3 需要四轮，而读取 C2、C10 和 C5 只需要两轮。因此，如图 7(a) 所示，读取这些子图的所有输入特征共需六轮。

[图 7 占位：块调度对比]

为解决上述问题，我们提出一种高效块请求调度算法，通过利用当前批次所有子图中的数据依赖关系，最大化一个块内输入特征的利用率。具体而言，我们读取一个块，并检索子图中所有层所需的输入特征，从而消除冗余块访问。由于传统 GNN 训练系统采用逐层方法，该算法在这些系统中不可行。然而，在 FlashGNN 的逐节点处理中，输入特征可以立即被消费，而无需长时间缓冲。为进一步提升所提出逐节点处理的效率，块调度算法优先处理具有更多消费者的块请求，从而更早解决更多数据依赖。

为此，我们记录一个块中所需输入特征的数量，记为 #src，以及依赖这些输入特征的目标节点数量，记为 #tgt。每个块请求表示为一个二元组 (#src, #tgt)。所有块请求按 #src 值降序排列；若相同，则优先处理 #tgt 较小的请求。该排序的依据是，更大的 #src 值可以解决更多数据依赖，而更小的 #tgt 值可以加速这些节点的聚合。块请求排序后，调度器相应发出请求。此外，我们为每个芯片引入一个 chunk-to-read 队列，用于维护与该芯片相关的已排序请求，从而减轻芯片冲突的影响。

我们用图 6 的示例说明调度算法。在分析图 6(a) 所示子图的数据依赖关系后，可以发现 C2 有四个源特征和两个目标特征；C3 有一个源特征和三个目标特征；C5 有两个源特征和四个目标特征；C10 有四个源特征和九个目标特征；C11 有一个源特征和四个目标特征。需要注意的是，一个节点的邻居可以被多次采样，每个采样实例可能有不同邻居。因此，C2 和 C10 的二元组分别为 (4, 2) 和 (4, 9)，C5、C3 和 C11 的二元组分别为 (2, 4)、(1, 3) 和 (1, 4)。块请求排序后，闪存芯片 0 的请求队列为 [C2, C10]，闪存芯片 1 的请求队列为 [C5, C3, C11]。如图 7(b) 所示，调度器第 1 轮发出 C2 和 C5，第 2 轮发出 C10 和 C3，第 3 轮发出 C11。与传统系统中的调度方法相比，这减少了三轮。

**数据过滤器。** 从多个芯片传输数据时，闪存通道总线的有限带宽是瓶颈，妨碍芯片级并行性的充分利用。为克服这一挑战，我们在每个闪存芯片上提出数据过滤器。它只通过共享闪存通道总线选择性地传输被请求的特征。我们通过扩展 ONFI 协议 [17], [24], [38], [39], [54]，并向读命令引入页内地址偏移和所需数据大小等附加字段来实现。为简单起见，我们将闪存读命令表示为元组 (chip, plane, page, offset, size)。例如，收到读命令 (2, 1, 12, 2048, 1024) 后，芯片 2 上的数据过滤器首先检查 plane 1 上的 page register 是否包含 page 12。若该页存在，则将该页传输给数据过滤器；否则，它从闪存阵列中取回 page 12 到 page register，然后再传输给数据过滤器。接收到数据后，数据过滤器提取从偏移 2048 开始的 1024 字节，并将其存储到芯片缓冲区。随后，通道控制器通过通道总线从芯片缓冲区检索数据，最后将其移动到 DRAM。

### C. 逐节点训练

[图 8 占位：逐节点训练流程]

SSD 内训练通过使用 DRAM 存储多种类型数据来实现高训练吞吐量，这些数据包括中间特征、输入特征、梯度、权重、完整子图以及正在增长的子图。然而，不同于 GNN 推理，GNN 训练的反向传播需要访问前向传播期间生成的所有特征，从而增加工作集。当一个批次的工作集超过缓冲区容量时，缓冲区和慢速闪存之间会频繁发生数据交换，导致性能较差。此外，从慢速闪存取数会降低 SIMD 核和脉动阵列等计算部件的利用率。

为解决 SSD 内训练的挑战，我们提出一种逐节点训练方法，它显著降低内存占用并减少对慢速闪存的访问。该方法源于对传统逐层 GNN 训练系统的观察，在这些系统中，前向和反向传播逐层进行。在这类系统中，第 (l+1) 层节点的特征计算会被推迟，直到第 l 层所有节点特征均可用，这会不必要地增加内存占用。例如，图 6(a) 展示了逐层训练系统计算第 1 层节点特征的情况。虽然 h1_11、h1_8 和 h1_43 已经可用，但其他节点特征仍在计算。在这种情况下，h1_11、h1_8 和 h1_43 的可用性允许立即计算 a2_11。我们提出的逐节点训练方法在节点依赖数据一旦可用时就启动节点计算，从而消除逐层训练引入的同步。

逐节点训练依赖于跟踪数据依赖关系，以确保给定节点的依赖数据可用。这由 StoT（Source-to-Target）表支持，该表指出目标特征依赖的源特征。Tag-to-Offset 表将节点特征的标签映射到 Target-Progress 表中对应条目的偏移，其中标签表示为 (layer, node ID)。Target-Progress 表记录给定目标特征尚不可用的源特征数量，每个目标特征对应一个 cnt 字段。cnt 字段的初始值为目标特征依赖的源特征数量。当特征 hl−1_s 可用时，可使用其标签查询 StoT 和 Tprg 表来检索其目标特征 hl_t，并将对应的 Tprg[hl_t].cnt 值减一。cnt 值为零表示相应特征计算完成。StoT 表也用于在反向传播期间跟踪梯度的数据依赖。

一旦目标特征 al_v 的聚合完成，它会被移动到组合器的输入缓冲区。如果 Wl 位于脉动阵列中，al_v 会立即被发送到脉动阵列，以执行组合 hl_v = Combine(al_v) = ReLU(Wl al_v)。否则，al_v 会存储在输入缓冲区中，直到积累了一定数量的聚合特征，从而触发将相关权重加载到脉动阵列。组合过程完成后，所得特征 hl_v 会写入 DRAM，为第 (l+1) 层聚合做准备。该过程持续进行，直到获得输出节点特征 hL_v，其中 L 表示 GNN 模型的总层数。

hl_v 的可用性启动梯度 gl_v 的计算，表示反向传播开始。通过反复查询 StoT 表，前向传播期间生成的输入特征 h0_v 和中间特征 h1_v、h2_v、...、hl−1_v 会参与 g0_v、g1_v、...、gl−1_v 的计算。同时，增量值 ΔW1、ΔW2、...、ΔWl 被累积并存储在 DRAM 中。W1、W2、...、Wl 的更新在每个批训练结束时执行，使用累积的增量值和优化器的更新规则。

虽然逐节点训练降低了内存占用，但它无法完全防止内存溢出。我们观察到，输入特征的内存占用远大于中间特征，而驱逐中间特征会导致昂贵的重计算。因此，当内存已满时，我们只将输入特征从内存驱逐到闪存，并将中间特征保留在内存中。被驱逐的输入特征可在需要时从闪存中取回。

**逐节点训练的流程。** 图 8 概述了所提出逐节点训练的流程。黑色标记的步骤/操作由多线程固件实现，红色标记的步骤/操作由硬件实现。FlashGNN 分析当前批次中的子图，并统计子图中所有节点所需的输入节点特征块。随后，调度算法根据源特征数量（#src）对这些块进行排序，生成块调度，如 III-B 节所述（步骤 1）。根据调度将输入节点特征块 Ci 加载到 DRAM 后（步骤 2），可通过查询 StoT 表获得目标特征的元数据（步骤 3）。随后 FlashGNN 查询 Tag-to-Offset 表，以获得目标特征在 Tprg 中的偏移（步骤 4），并更新 Tprg 中目标特征的进度（步骤 5）。当目标特征所需的所有源特征都可用时，FlashGNN 读取这些特征（步骤 6），并将其发送到计算部件以执行聚合（步骤 7）和组合（步骤 8），生成中间节点特征。当到达最后一层时，FlashGNN 为目标节点生成输出特征（步骤 9）。在反向传播中，梯度向量被计算并存储在 DRAM 中（步骤 10）。此外，梯度向量的可用性会通过查询表来更新节点的目标进度（步骤 11）。

在传统 GPU 中心系统或基于 ASIC 的系统中应用逐节点训练，并不会提高这些系统的吞吐量，因为它们受限于 DRAM 访问 [33], [45]。在这些系统中，逐节点训练仍然需要慢速 DRAM 访问，导致 GPU 流式多处理器和 ASIC 加速器脉动阵列等计算单元利用不足。相反，基于 SSD 内计算的 GNN 训练受限于慢速闪存访问，导致脉动阵列和 DRAM 带宽利用不足。然而，我们提出的逐节点训练能够有效利用存储在 DRAM 中的节点输出特征，从而提高脉动阵列和 DRAM 带宽利用率。与逐层训练不同，它不要求一层中所有节点的输出特征都在 DRAM 中可用。总之，逐节点训练提高了 DRAM 带宽利用率，并因此提高脉动阵列利用率，从而提升 SSD 内加速器的训练吞吐量。

### D. 数据驱动的子图生成

我们的实验表明，邻居采样阶段可占总运行时间的 30% 以上，这说明需要提高邻居采样效率以增强整体性能。为研究子图生成缓慢的原因，我们观察到传统方案对边列表块的利用率较低，而这些块包含许多节点的边列表。在训练一个批次之前，这些方案生成以该批次中带标签节点为根节点的子图，称为按需子图。按需子图生成会取回包含正在发展子图中 frontier 节点边列表的块，该子图在图上执行 BFS 采样。然而，按需子图只使用取回块中的少量边列表，块中剩余边列表未被使用。这种边列表块利用不足导致频繁块访问和缓慢子图生成。

为提高边列表块利用率，FlashGNN 提出一种新的数据驱动子图生成方案，最大化消耗一个块中的边列表。具体而言，它不仅生成按需子图，还同时生成未来训练批次所需的子图。这确保这些子图能够使用从已取回边列表块中获得的更多边列表。与未来批次相关的子图称为主动子图。主动子图一旦生成，就会存储在 ready subgraphs 列表中，并成为下一个训练批次的一部分，从而隐藏子图生成延迟。这种方法与边列表预取显著不同，因为由于边列表的间接访问，边列表预取效率较低。主动子图生成仅在从闪存加载新块时触发，以最小化执行开销。

为支持所提出的子图生成，FlashGNN 引入多个映射表：图结构转换表（GST）、target-to-chunk（TtoC）和 chunk-to-targets（CtoTs）。节点的边列表按节点 ID 顺序依次存储在闪存中。每个闪存块包含具有连续 ID 节点的边列表。GST 将块 Cm 映射到节点 ID Nlo，即边列表存储在该块中的节点中最小的 ID。TtoC 将目标节点 ID Nm 映射到包含 EL[m] 的块 Cn，其中目标节点表示训练集中的节点。CtoTs 将块 Cm 映射到若干目标节点 Na0、Na1、...、Nan−1，这些节点的边列表 EL[a0]、EL[a1]、...、EL[an−1] 存储在 Cm 中。

[图 9 占位：数据驱动子图生成示例]

图 9 展示了批大小为 6 时所提出的子图生成。当前批次由节点 N16、N22、N30、N18、N24 和 N41 组成。为这些节点生成子图称为按需子图生成。例如，生成 SG[N16]（N16 的子图）时，通过使用 N16 查询 TtoC 来取回块 C2，该块存储 N16 所需边列表 EL[16]。一旦 C2 从闪存加载到 DRAM，固件会从 EL[16] 中随机采样两个邻居（N25 和 N26）。采样 EL[16] 后，我们通过查询 CtoTs 检查 C2 是否包含可用于训练集中其他节点子图生成的边列表。结果表明，C2 中的 EL[17] 和 EL[14] 可用于为当前批次之外的 SG(N17) 和 SG(N14) 进行主动子图生成。

我们还为 frontier 节点表中的节点维护两个映射表：CtoFs（chunk-to-frontiers）和 FtoRs（frontier-to-roots）。与 CtoTs 类似，CtoFs 将块 Cm 映射到若干 frontier 节点 Na0、Na1、...、Nan−1，其中它们的边列表 EL[a0]、EL[a1]、...、EL[an−1] 存储在 Cm 中。另一方面，FtoRs 将 frontier 节点 Nm 映射到所有根节点 Na0、Na1、...、Nan−1，其中 Nm 属于这些根节点子图的交集。

实验结果表明，在训练过程中，CtoTs 和 CtoFs 中少于 0.2% 的块会为超过四个节点触发邻居采样。因此，为实现最佳存储和访问效率，我们将这两个映射表的每个条目设计为固定长度为四的数组。一旦数组填满，就不再向其中添加更多节点。

[图 10 占位：采样进度跟踪示例]

为了管理子图生成，FlashGNN 使用 Progress 表和 Goal 表跟踪每个根节点的状态。Goal[Ni] 条目记录 SG[Ni] 中的节点数量，而 Progress[Ni] 表示 SG[Ni] 中已完成采样的节点数量。当 Progress[Ni] 等于 Goal[Ni] 时，SG[Ni] 的生成被视为完成。图 10 展示了使用 2 层模型为 SG[N0] 生成子图的进度。在第 1 轮，对 N0 执行邻居采样，得到总共 4 个邻居。因此，Progress[N0] 增加到 1，Goal[N0] 设置为 5。在第 2 轮，对 N1 执行邻居采样。然而，由于 N1 没有邻居，Progress[N0] 增加 1，达到 2，而 Goal[N0] 仍为 5。在第 3 轮，对 N4 执行邻居采样，得到 3 个邻居。对这些 2 跳邻居不再需要进一步采样。因此，Progress[N0] 增加 4，达到 6，Goal[N0] 更新为 8。一旦 N2 和 N3 的邻居采样完成，Progress[N0] 将等于 Goal[N0]，表示 SG[N0] 成功构建。

**应用主动采样的批次范围。** 根据实验结果，很明显，训练集中的大多数节点无法仅通过主动采样构建完整子图。因此，该方法的主要目标不是构建足够数量的完整子图，而是在训练过程消费相应批次之前，提前构建节点的部分子图。这有助于减少主动采样的工作量。通过主动采样获得的部分子图通常会在达到一定大小后停止更新，因为所需块不可用。为了防止长时间占用 eDRAM 并降低成本，有必要尽早将这些子图转换为主动采样。此外，维护从块 ID 到训练集中每个节点的映射会产生过高成本。

所提出方法在从当前批次开始的 B 个批次范围内应用主动采样。如果 B 值过大，会导致 CtoTs 的维护成本更高，且不再更新的部分子图可能长时间占用 eDRAM，导致边列表利用不足。另一方面，如果 B 太小，由于批次中节点数量较少，将更难触发主动采样。此外，仍可能继续增长的部分子图会更早交给主动采样。为在算法效率和维护成本之间取得平衡，我们将 B 设置为 20。

**进度感知的子图缓存替换。** 所提出的子图生成方案同时存储按需子图和主动子图。按需子图的内存占用保持固定，因为一个批次中的节点数量固定。然而，考虑到训练集中的每个节点都可能关联一个主动子图，主动子图可能比按需子图更多。为简化设计，我们限制主动子图的最大数量。在内存溢出时，新进入的主动子图会覆盖已有主动子图。

为最小化缓存驱逐造成的开销，我们引入进度感知的子图缓存替换算法。该算法根据进度值在缓存中保留主动子图，保留那些高于阈值 THprogress 的子图。这些子图称为深子图，而进度值低于 THprogress 的子图称为浅子图。如果缓存中的浅子图很长时间没有采样其邻居，则可使用 LRU 策略驱逐并换出到闪存。深子图则允许留在缓存中形成完整子图，而不会被替换。如果缓存不包含任何浅子图，则当缓存已满时不再容纳新的主动子图。此外，为防止过度抖动，当加载一个边列表块产生多个子图且缓存已满时，只允许其中一个存储到缓存中。如果子图缓存中的主动子图属于当前批次，我们将其移动到 DRAM。

### E. 固件设计

FlashGNN 固件使用多线程实现高吞吐量。它使用 N 个线程在子图生成和消息传递之间交替执行。在每个阶段，固件维护 N 个任务队列，每个活动线程与一个特定任务队列关联以执行任务。随着任务执行，会生成新任务，并分发到不同任务队列中，以平衡每个线程的工作负载。

**子图生成。** 在子图生成阶段，固件为节点执行采样，这些任务称为节点任务。最初，批次中的所有目标节点均匀分布到 N 个任务队列中。线程从其任务队列中选择一个节点任务并为该节点执行采样。如果节点边列表在 DRAM 中可用，线程执行采样，并可能生成新的节点任务，再将其分配给其他任务队列。完成一个任务后，线程继续从其任务队列中获取另一个任务。如果节点边列表不在 DRAM 中，线程会发送请求读取所需闪存块。在等待闪存块返回期间，线程会准备由所请求闪存块触发的主动采样所需信息，然后从队列中获取任务。该过程持续进行，直到挂起闪存请求总数达到 256。当一个闪存块到达时，等待它的线程被唤醒，使线程能够对闪存块中的边列表执行采样。此外，该线程还尝试将主动采样任务分配给空闲线程。

**消息传递。** 在消息传递阶段开始时，固件通过从闪存读取输入特征来聚合这些特征。由于这些闪存块来自不同闪存芯片，每 #c/N 个芯片的请求被分配给同一个任务队列，其中 #c 表示闪存芯片数量。当被请求闪存块可用时，相应线程被激活，使用该块中的特征执行聚合。在聚合期间，线程查询表并可能更新表，这涉及对这些表的锁操作。执行聚合并生成聚合特征 a 的线程成为 a 的所有者。完成聚合特征 a 的组合任务后，会生成中间特征 h，h 的所有权从 a 继承。这种线程所有权传递发生在消息传递阶段。此外，固件将数据依赖分析与子图生成并行实现。构建 StoTs、Tag-to-Offset 和 Tprg 的开销也可被邻居采样操作隐藏。

### D. 优化分析

我们考虑 FlashGNN 中的三种优化：CRS 表示块请求调度，NOD 表示逐节点训练，DSG 表示数据驱动子图生成。变体 C 表示仅启用 CRS 的配置。变体 C+N 结合 CRS 和 NOD，而变体 C+N+D 包含 CRS、NOD 和 DSG。

我们增强了最先进的存储内加速器 SmartSAGE [22]，将其实现为 ASIC，以执行 GNN 训练。该增强版本在评估中称为 SmartSAGE+。增强包括：1）使用 SSD 内 ASIC 脉动阵列执行 GNN 的组合，消除将生成子图和聚合输入特征传输到主机的需求；2）在 SSD 内执行前向和反向处理；3）使用 GLIST [23] 提出的图布局优化。为分析每个批次内数据共享的影响，我们设置两个 SmartSAGE+ 变体：NOSH 表示无数据共享，SH 表示数据共享。SmartSAGE+ 采用与 FlashGNN 相同的硬件配置，其中 NOSH 作为基线。

## V. 相关工作

**基于 SSD 的 GNN 系统。** Ginex [33] 通过在检查阶段采样足够多的批次，并在执行阶段使用缓存，采用一种最优缓存机制。通过这种方式，该系统以消耗一定 DRAM 容量为代价缓解 SSD 低带宽问题。SmartSAGE [22] 将 GNN 训练中的数据密集型任务卸载到具有存储内处理能力的 SSD。SSD 接收不规则且粗粒度访问，在内部将原始数据转换为细粒度结构，并将其返回给主机，从而减少 SSD 和 DRAM 之间的数据移动。GLIST [23] 通过调度请求队列、对同时到达的多个请求进行分组，以及在预处理阶段优化闪存中的数据放置，利用时间和空间局部性。然而，这些系统并未充分利用 SSD 并行性，并且仍需要通过 PCIe 总线向外部 DRAM 传输数据。此外，它们缺乏对节点特征计算的优化。

**以 GPU 为中心的 GNN 系统。** Betty [47] 引入了一种图划分算法和系统实现，以便将大型复杂图装入 GPU 内存，并支持使用微批次的 GNN 训练。NeutronStar [42] 基于依赖缓存机制和依赖通信机制设计了一种混合依赖管理方式，并提出自动梯度反向传播，以优化 GPU 加速和通信。BGL [27] 实现了一种具有邻近性感知排序的动态特征缓存引擎，以实现低开销和高缓存命中率；采用一种新的图划分算法来最小化采样期间的跨分区通信；并使用基于 profiling 的资源隔离来优化数据预处理的资源分配。

**基于 SSD 的 DNN 系统。** Behemoth [20] 根据数据特征采用专门化数据布局，并实现简化固件和写路径硬件自动化，从而提高 SSD 带宽和耐久性。OptimStore [19] 通过向闪存 die 添加逻辑单元，并利用内部寄存器执行高级 DNN 优化器所需的高精度数学操作，增强用于 DNN 训练的 SSD。

## VI. 结论

图神经网络（GNNs）已经成为多种数据分析应用中优于传统算法的替代方案。然而，现实世界数据集规模的增长已经超过了基于 CPU 或 GPU 的系统能力，而分布式系统则存在硬件利用不足的问题。尽管 SSD 很有前景，但单机上基于 SSD 的 GNN 训练会受到慢速 PCIe 总线的影响。本文提出 FlashGNN，以克服 PCIe 瓶颈，并充分利用 SSD 中的 I/O 并行性，从而实现高效 GNN 训练。我们通过设计 SSD 固件来协调数据移动和硬件单元访问以实现这一点。为克服慢速闪存和有限资源带来的挑战，我们引入了一种新的逐节点 GNN 训练方法、一种高效闪存请求调度算法和一种高性能子图生成方法。实验结果表明，FlashGNN 超越了最先进的基于 SSD 的 GNN 训练系统 Ginex，实现了 4.89× 到 11.83× 的加速。此外，在四个典型真实世界图数据集上，FlashGNN 实现了 57.14× 到 192.66× 的能耗节省。而且，在效率方面，FlashGNN 最高比增强后的最先进存储内加速器 SmartSAGE+ 高 23.17×。
