# V93000 测试机硬件架构与信号路径

本章从工作站、测试头、板卡、pogo 和 DUT board 逐级说明硬件。完成后，读者应能追踪一个数字信号和一个电源信号的完整物理路径，并能判断故障更可能位于程序、仪器、接口还是 DUT。

## 1. 测试系统组成

| 组成 | 作用 | 可检查信息 |
| --- | --- | --- |
| Host Workstation | 运行 SmarTest、编译程序、控制执行和保存结果 | OS、SmarTest 版本、workspace、许可 |
| Test Head | 容纳时钟、数字、DC、模拟和 RF 等板卡 | tester class、槽位、冷却、状态灯 |
| Manipulator / Docking | 把测试头对准 handler、prober 或接口机构 | 平整度、锁定状态、机械干涉 |
| DUT Interface | 通过 pogo 把测试头资源送到 DUT board 或 probe card | pogo 编号、接触、磨损、污染 |
| DUT Board / Probe Card | 完成器件连接、去耦、保护、切换和适配 | 原理图、布局、BOM、版本、site 分配 |
| Handler / Prober | 放置器件、管理 site 和温度、接收分档结果 | site enable、接触状态、温度、bin 接口 |

## 2. Tester Class 与槽位

旧 Smart Scale 资料常见 A、C、S、L class。公开的 2014 V93000 硬件培训资料给出 A/C/S/L 对应约 8/16/32/64 个槽位；当前 EXA Scale 产品采用 CX 至 LX 等命名。具体系统必须依据当前 configuration 和 TDC，不要仅凭机台外观判断。[Advantest V93000 产品页](https://www.advantest.com/en/products/semiconductor-test-system/soc/v93000/)

tester class 决定可容纳配置规模，但不直接说明某台机已安装哪些资源。开始项目前应得到一份资源清单：

| 字段 | 示例格式 | 用途 |
| --- | --- | --- |
| Tester class | `C-Class / CTH` | 判断槽位和接口规模 |
| Slot | `<slot-id>` | 定位板卡物理位置 |
| Instrument | `PS1600B`、`DPS128-HC` | 判断功能和范围 |
| Revision | `<board-revision>` | 排查修订差异 |
| Channel count | `<licensed>/<installed>` | 规划 pin 和 site |
| Calibration due | `YYYY-MM-DD` | 确认计量有效状态 |
| License | `<feature-name>` | 确认速度、内存或高级功能可用性 |

## 3. 数字信号路径

以 `CLK` 为例，驱动路径通常可抽象为：

```text
SmarTest level/timing/pattern
  -> 数字板卡 test processor
  -> pin driver 与 50 Ω 前端
  -> pogo 与 DUT board 走线
  -> socket/probe contact
  -> DUT CLK 引脚
```

返回比较路径则为：

```text
DUT 输出
  -> socket/probe contact
  -> DUT board 走线与可选端接
  -> pogo
  -> comparator
  -> 数字 fail memory / result
  -> SmarTest debug 与 datalog
```

数字失败不应直接归因于 pattern。常见物理因素包括端接不合适、走线过长、相邻信号串扰、socket 接触电阻、参考地回流路径和 strobe 位置不当。

## 4. 电源信号路径与 Kelvin Sense

以 `VDD` 为例：

```text
DPS force 端
  -> pogo force
  -> DUT board 电源平面或走线
  -> DUT VDD
  -> DUT 回流
  -> DPS return

DUT 端取样点
  -> 独立 sense 走线
  -> pogo sense
  -> DPS 控制与测量端
```

Force 线承载电流，会产生 `I × R` 压降。Sense 线在 DUT 附近读取电压，使 DPS 能补偿 force 路径压降。Sense 点若接在测试头而不是 DUT 附近，程序显示的电压可能正常，但 DUT 引脚实际电压偏低。

> [!warning] Kelvin 连接不是允许任意补偿
> 远端取样仍受到 DPS compliance、线阻、稳定性、去耦和功率限制。Sense 开路或接错可能导致输出异常，首次上电前必须检查 force/sense 成对连接和保护策略。

## 5. Pogo Block 与通道分组

V93000 的 DUT 接口采用固定 pogo 组织。数字板卡和 DC 板卡通常以一组通道对应一个或多个 pogo block。通道分组会影响：

- 差分信号能否使用指定配对；
- 高压 driver 是否落在具备该资源的通道位置；
- 板级 ADC 或共享资源由哪些通道共用；
- pattern memory 和许可证如何分配；
- 多 site 是否能够保持规则对称；
- DUT board 的走线长度和交叉数量。

设计 pin plan 时应同时查看逻辑信号、物理 pogo、板卡类型、通道号、site 和特殊资源，不能只维护一列 pin 名。

## 6. DUT Board 资源分配表

推荐在画原理图前维护下面的表：

| DUT 信号 | Site | Tester 资源 | Pogo/Channel | 方向 | 额定条件 | 特殊要求 |
| --- | ---: | --- | --- | --- | --- | --- |
| `CLK` | 1 | PS1600 digital | `<pogo>` | tester→DUT | `<VIL/VIH/freq>` | 受控阻抗、短走线 |
| `Q0` | 1 | PS1600 comparator | `<pogo>` | DUT→tester | `<VOL/VOH/strobe>` | 避免强上拉 |
| `VDD` | 1 | DPS128 | `<force/sense>` | 双向 VI | `<V/I/compliance>` | Kelvin、去耦 |
| `VSS` | 1 | DPS return | `<pogo>` | 回流 | `<Imax>` | 低阻、多个接点 |

多 site 设计应为每个 site 保持同样列集合，以便自动检查资源是否对称。

## 7. Direct Probe 与传统接口

传统 wafer probe 可能经过测试头接口、DUT board、连接器和 probe card。Direct Probe 方案减少中间过渡和路径长度，以改善高性能 wafer test 的信号完整性。Advantest 的公开说明强调，Direct Probe 把 V93000 测试头更直接地连接到 probe assembly。[V93000 Direct Probe Solution Overview](https://www3.advantest.com/documents/11348/146007/pdf-direct-probe-solution-overview.pdf/147c9a9b-d96d-41eb-aae0-90f7aba2519e)

## 8. 按现象定位故障层次

| 现象 | 可能原因 | 检查 | 处理 |
| --- | --- | --- | --- |
| 所有 site 同一信号失败 | pattern、level/timing、公共资源或设计问题 | 单独执行 suite，查看 first fail 和设置 | 核对程序对象与公共连接 |
| 只有一个 site 失败 | socket/probe、site 走线、site 资源分配 | 交换 DUT、site 或接触位置 | 清洁或修复 site 相关连接 |
| 电流达到限制且电压偏低 | DUT 短路、force 压降、限流太小 | 查看 DPS 状态和 DUT 端电压 | 立即下电，检查连接与限流 |
| 低频通过、高频失败 | 时序余量、信号完整性、strobe 或 DUT 速度 | 降频、做 timing Shmoo、查看波形 | 调整接口或测试设置 |
| 重复运行漂移 | 温度、接触、去耦、等待时间或校准 | 固定温度和序列，重复测量 | 分离系统因素与 DUT 因素 |
