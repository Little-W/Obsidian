# V93000 DC 测试方法：Continuity、Leakage、VOH／VOL 与 IDD

本章从“测量条件怎样形成”开始，逐步完成 continuity、输入 leakage、输出 VOH／VOL 和电源 IDD 测量，并给出 SmarTest 7 C++ Test Method 教学代码。完成后，读者应能把 DUT 规格转换成 force、range、relay、settling、measure、limits 和 cleanup 动作，并能解释每行代码对 tester 资源产生的影响。

> [!important] 代码适用范围
> 本章的专有 API 写法依据公开的历史 93000 培训资料和 Advantest 官方 HSM3G 应用资料，适合学习 SmarTest 7 Test Method 结构。示例没有在本机 SmarTest SDK 或真实 tester 上编译、执行。函数声明、头文件、单位宏、板卡能力和多 Site 结果类型必须用目标机台的 `Help > Help Contents` 或 TDC 再确认。SmarTest 8 使用 Java Test Method，不应把这些 C++ 类名直接搬过去。

## 1. 先把一次 DC 测量拆成七个动作

任何 DC 参数测试都可以按下面的次序检查：

```mermaid
flowchart LR
    A[建立 DUT 状态] --> B[选择仪器和量程]
    B --> C[设置 clamp 或 compliance]
    C --> D[切换 relay]
    D --> E[等待稳定]
    E --> F[执行并读取结果]
    F --> G[记录数值并恢复资源]
```

| 动作 | 必须回答的问题 | 遗漏后的典型现象 |
| --- | --- | --- |
| 建立 DUT 状态 | 主电源、reset、输入和输出分别处于什么状态？ | 同一 pin 每次测得不同数值 |
| 选择仪器 | 使用 PPMU、HPPMU 还是 DPS？ | 范围、分辨率或通道数不满足要求 |
| 设置 force/range | 施加电压还是电流？量程是多少？ | 饱和、分辨率不足或 DUT 受损 |
| 设置保护 | 异常时允许到达的最大电流或电压是多少？ | 短路时没有及时限制 |
| 切换 relay | 数字 driver、comparator 和 PMU 谁连接到 pin？ | tester 与 DUT 输出对抗 |
| 等待并测量 | relay 和 DUT 需要稳定多久？获取 pass/fail 还是数值？ | 结果偏移或重复性差 |
| 记录并恢复 | 单位、limits、site 和断开动作是否完整？ | Datalog 无数值或下一项被前一项影响 |

### 1.1 四种 Force／Measure 组合

| 模式 | 英文 | 常见用途 | 主要风险 |
| --- | --- | --- | --- |
| 施加电压、测量电流 | FVMI／VFIM | leakage、IDD | 短路时过流 |
| 施加电流、测量电压 | FIMV／IFVM | continuity、VOH、VOL | 开路时电压升到 clamp |
| 施加电压、测量电压 | FVMV | 远端电压或传输检查 | sense 和输入阻抗设置错误 |
| 施加电流、测量电流 | FIMI | 特定受控测量 | 需先确认仪器是否支持 |

不同资料可能把“force”写在前面，也可能把仪器 API 名写成 `PMU_IFVM` 或 `PMU_VFIM`。阅读时先确认第一个字母表示 force 还是 measure，不要只凭缩写猜测。

### 1.2 代码中的单位

历史 SmarTest 7 Test Method 使用 `uA`、`mA`、`mV`、`V`、`ms` 等单位宏：

```cpp
-50 uA
1.70 V
1.0 ms
```

它们不是普通 ISO C++ 数字写法，而是测试方法环境提供的单位机制。若编译器不识别，先检查当前 Test Method 模板的 include 和 TDC，不要把单位删掉后直接使用裸数字。

### 1.3 电流正负方向必须实测确认

`+1 mA` 对具体 pin 表示 tester 向 DUT 送入电流，还是从 DUT 吸收电流，必须以目标板卡、API 和项目约定为准。第一次使用时可以用已知电阻做低风险检查：记录 force 极性、外部表读数和 tester 结果，再填写项目的电流方向表。

### 1.4 PPMU、HPPMU 和 DPS 怎样选择

| 测试需求 | 优先资源 | 选择原因 | 还要检查什么 |
| --- | --- | --- | --- |
| 普通数字 pin continuity | PPMU | 每 pin 均可并行测量 | force 范围、clamp 和 pin 类型 |
| µA 级 input/output leakage | PPMU 或 HPPMU | PPMU 通道多，HPPMU 精度更高 | 量程、路由资源和测试时间 |
| VOH／VOL | PPMU 或有源电流单元 | 能在规定电流下测电压 | 电流方向和板卡合计电流 |
| DUT 主电源 IDD | DPS | 能持续供电并测量电流 | 每 site 是否独立、量程和采样方式 |
| 协议运行期间的 DC 点 | Pattern-controlled PMU／DPS | 测量点可与 pattern 动作配合 | dc-sublabel、anchor point 和板卡支持 |

PS1600 PPMU 的公开范围和误差见 [[12-PS1600硬件参数与配置#3.5 每引脚 PMU（PPMU）]]，DPS128 的量程和分辨率见 [[13-DPS128与供电资源配置#2.3 电流量程]]。

## 2. SmarTest 7 DC API 的最小结构

历史培训资料把 PPMU 的任务分成四类对象：

| 对象 | 作用 | 常用成员 |
| --- | --- | --- |
| `PPMU_SETTING` | 设置 force、range 和 limits | `pin()`、`iRange()`、`iForce()`、`vForce()`、`min()`、`max()`、`limits()` |
| `PPMU_RELAY` | 设置 PMU relay 并加入等待 | `pin()`、`status()`、`wait()` |
| `PPMU_MEASURE` | 选择结果形式并保存测量结果 | `pin()`、`execMode()`、`getValue()`、`getPassFail()` |
| `TASK_LIST` | 按加入顺序执行上述动作 | `add()`、`execute()` |

`execMode()` 常见选择：

| 模式 | 返回内容 | 适用场景 |
| --- | --- | --- |
| `TM::GPF` | 整体 pass/fail | 只关心整组结果 |
| `TM::PPF` | 每 pin pass/fail | 需要定位失败 pin，但不保存参数值 |
| `TM::PVAL` | 每 pin 数值 | DC 参数教学、相关性和量产 Datalog |

下面是最小骨架。实际使用时只把花括号内的内容放进 Workcenter 自动生成的方法体。

```cpp
// 函数声明以目标项目自动生成的 Test Method 模板为准。
HRESULT CDC_tests::dc_example(double _result[4])
{
    PPMU_SETTING setting;
    PPMU_RELAY connectPpmu;
    PPMU_RELAY disconnectPmu;
    PPMU_MEASURE measurement;
    TASK_LIST tasks;

    ON_FIRST_INVOCATION_BEGIN();
        setting.pin("IO0").iRange("10uA");
        setting.pin("IO0")
               .vForce(0.10 V)
               .min(-1.0 uA)
               .max(+1.0 uA);

        connectPpmu.pin("IO0").status("PPMU_ON");
        connectPpmu.wait(1.0 ms);

        measurement.pin("IO0").execMode(TM::PVAL);
        disconnectPmu.pin("IO0").status("ALL_OFF");

        tasks.add(setting)
             .add(connectPpmu)
             .add(measurement)
             .add(disconnectPmu);
        tasks.execute();
    ON_FIRST_INVOCATION_END();

    DOUBLE measuredCurrent = measurement.getValue("IO0");
    TEST("IO0", "DC_EXAMPLE", measuredCurrent);
    return S_OK;
}
```

### 2.1 为什么执行放在 `ON_FIRST_INVOCATION`

在传统多 Site Test Method 中，`ON_FIRST_INVOCATION_BEGIN()` 和 `ON_FIRST_INVOCATION_END()` 之间的 tester 动作由框架统一安排，避免每个 site 重复编程和重复执行硬件。结果处理放在该区域之后，由框架给当前 site 提供相应结果。

这不等于所有项目都返回 `DOUBLE`。高 Site 数项目可能使用数组或专用 Site Result 类型；必须从当前模板复制结果访问方式。

### 2.2 `min/max` 与 `TEST` 的职责

`PPMU_SETTING.min()/max()` 给测量动作提供 limits；`TEST()` 负责把结果与 test name 关联并写入测试结果。若项目统一从 test table 取 limits，可使用该版本支持的 `limits("testName")`，避免代码和 test table 各保存一份不同数值。

> [!warning] Limits 不是电气保护
> `min()/max()` 决定 pass/fail，不等于 voltage clamp 或 current compliance；`iRange()` 也不是短路保护。clamp/compliance 必须用目标板卡和当前 API 提供的设置建立。公开代码片段没有完整列出这些成员，因此示例不虚构函数名。

### 2.3 Test Method 与 test table 的名称必须一致

本章示例使用以下教学记录项：

| Test name | 结果单位 | Low limit | High limit | 说明 |
| --- | ---: | ---: | ---: | --- |
| `CONT_NEG` | V | −1.20 | −0.20 | 负向 continuity |
| `IIL_0P1V` | µA | −1.00 | +1.00 | 输入低端 leakage |
| `IIH_1P7V` | µA | −1.00 | +1.00 | 输入高端 leakage |
| `VOH_AT_IOH` | V | 1.35 | 2.20 | 高电平输出参数 |
| `VOL_AT_IOL` | V | −0.20 | 0.45 | 低电平输出参数 |
| `IDD_STANDBY` | mA | 0.00 | 80.00 | 待机电源电流 |

这些仍是教学值。正式项目还要分配唯一 test number，并明确 API 返回的是 A、mA 还是 µA；不要只修改表格显示单位而不转换代码提交的数值。

### 2.4 `PMU_IFVM／PMU_VFIM` 与 Flex DC 的区别

传统便捷 API 可以把 setup、执行和结果对象写在同一个 pin 名下。下面是历史培训资料所示结构的 continuity 教学写法：

```cpp
PMU_IFVM("IO0", TM::PPMU)
    .iForce(-50 uA)
    .settling(1.0 ms)
    .limits("CONT_NEG")
    .mode("NS");

PMU_IFVM("IO0").execute();
TEST(PMU_IFVM("IO0"));
```

`PMU_VFIM` 用于施加电压、测量电流，`PMU_IFVM` 用于施加电流、测量电压。历史资料指出，便捷 API 对一组 pin 通常使用相同 force 和 relay 条件；需要让不同 pin 使用不同 force 或希望把多个动作排入同一任务时，改用 `PPMU_SETTING／PPMU_RELAY／PPMU_MEASURE／TASK_LIST`。`mode("NS")` 的 relay 次序和串并行行为必须按当前版本模式表确认。

## 3. Continuity：施加电流、测量保护结构压降

Continuity 通常在 DUT 主电源关闭时进行。以负向测试为例，PPMU 对信号 pin 施加小电流，测量 pin 对地或对电源保护结构形成的电压。

### 3.1 测量条件表

下面数值只用于教学，不是任何产品的正式测试条件：

| 参数 | 教学值 | 正式项目的来源 |
| --- | ---: | --- |
| Pin | `IO0,IO1` | Pin plan |
| Force current | −50 µA | DUT 保护结构和测试规范 |
| PPMU range | 100 µA | 预期值和异常余量 |
| Voltage limits | −1.20 V～−0.20 V | 已知良品、设计和接触实验 |
| Relay settle | 1 ms | DUT board 与重复性实验 |
| DUT power | Off | 测试计划 |

### 3.2 完整教学代码

```cpp
// SmarTest 7 教学模板；函数声明须换成项目自动生成的声明。
HRESULT CDC_tests::continuity_neg(double _result[4])
{
    PPMU_SETTING contSetting;
    PPMU_RELAY connectPpmu;
    PPMU_RELAY disconnectPmu;
    PPMU_MEASURE contMeasure;
    TASK_LIST contTasks;

    ON_FIRST_INVOCATION_BEGIN();
        contSetting.pin("IO0,IO1").iRange("100uA");
        contSetting.pin("IO0,IO1")
                   .iForce(-50 uA)
                   .min(-1.20 V)
                   .max(-0.20 V);

        connectPpmu.pin("IO0,IO1").status("PPMU_ON");
        connectPpmu.wait(1.0 ms);

        contMeasure.pin("IO0,IO1").execMode(TM::PVAL);

        disconnectPmu.pin("IO0,IO1").status("ALL_OFF");

        contTasks.add(contSetting)
                 .add(connectPpmu)
                 .add(contMeasure)
                 .add(disconnectPmu);
        contTasks.execute();
    ON_FIRST_INVOCATION_END();

    DOUBLE vIo0 = contMeasure.getValue("IO0");
    DOUBLE vIo1 = contMeasure.getValue("IO1");

    TEST("IO0", "CONT_NEG", vIo0);
    TEST("IO1", "CONT_NEG", vIo1);
    return S_OK;
}
```

### 3.3 逐段说明

| 代码 | 发生的动作 | 检查点 |
| --- | --- | --- |
| `iRange("100uA")` | 选择 100 µA 电流量程 | 当前 PS1600 是否具有此量程 |
| `iForce(-50 uA)` | 对两个 pin 施加负向小电流 | 极性、DUT 未上电条件 |
| `min/max` | 设置电压通过区间 | 不能照抄教学值 |
| `status("PPMU_ON")` | 把 PPMU 接到 pin | 数字 driver 必须处于批准状态 |
| `wait(1.0 ms)` | relay 动作后等待 | 用重复测量确定是否足够 |
| `TM::PVAL` | 保存每 pin 数值 | Datalog 应保留 V 单位 |
| `status("ALL_OFF")` | 测量后断开 PMU | 异常退出也要有恢复动作 |

### 3.4 预期结果和通过条件

假设教学窗口为 −1.20 V～−0.20 V：

| 测量结果 | 解释示例 | 结果 |
| ---: | --- | --- |
| −0.65 V | 可能为正常保护结压降 | pass |
| −0.03 V | 可能短路、极性错误或外部钳位 | fail |
| 接近负向 clamp | 可能开路、接触不良或保护结构不存在 | fail |

真实器件可能没有传统保护二极管，或者 pin 连接到模拟电路、开漏结构或特殊电源域。必须先按 pin 类型分组，不能把所有 pin 放进同一 limits。

### 3.5 双极性 Continuity

若测试计划要求正、负两个方向，建立两个 setting 和两个 measurement。顺序建议为：

```text
force 0 -> 连接 PPMU -> 负向测量 -> force 0
        -> 正向测量 -> force 0 -> 断开 PPMU
```

每次换向前先回到 0，减少电荷残留。正、负向应使用不同 test name，例如 `CONT_NEG` 和 `CONT_POS`。

## 4. Input Leakage：两点施加电压、测量电流

Input leakage 通常在 DUT 已按规定上电、目标输入没有被数字 driver 驱动时进行。低端与高端必须分别测量，因为两处电流方向和外部器件影响可能不同。

### 4.1 教学条件

| 项目 | 低端 | 高端 |
| --- | ---: | ---: |
| Force voltage | 0.10 V | 1.70 V |
| Current range | 10 µA | 10 µA |
| Limits | −1.0 µA～+1.0 µA | −1.0 µA～+1.0 µA |
| Test name | `IIL_0P1V` | `IIH_1P7V` |

上述电压假设教学 DUT 使用 1.8 V I/O。正式值应取自数据手册对 `IIL`、`IIH` 的测试条件，而不是直接使用 0 V 和 VDD。

### 4.2 完整两点测量代码

```cpp
// SmarTest 7 教学模板；IO_LEAK 是已在 Pin Configuration 定义的 group。
HRESULT CDC_tests::input_leakage(double _result[4])
{
    PPMU_SETTING lowSetting;
    PPMU_SETTING highSetting;
    PPMU_RELAY connectPpmu;
    PPMU_RELAY disconnectPmu;
    PPMU_MEASURE lowMeasure;
    PPMU_MEASURE highMeasure;
    TASK_LIST leakageTasks;

    ON_FIRST_INVOCATION_BEGIN();
        lowSetting.pin("IO_LEAK").iRange("10uA");
        lowSetting.pin("IO_LEAK")
                  .vForce(0.10 V)
                  .min(-1.0 uA)
                  .max(+1.0 uA);

        highSetting.pin("IO_LEAK").iRange("10uA");
        highSetting.pin("IO_LEAK")
                   .vForce(1.70 V)
                   .min(-1.0 uA)
                   .max(+1.0 uA);

        connectPpmu.pin("IO_LEAK").status("PPMU_ON");
        connectPpmu.wait(1.0 ms);

        lowMeasure.pin("IO_LEAK").execMode(TM::PVAL);
        highMeasure.pin("IO_LEAK").execMode(TM::PVAL);

        disconnectPmu.pin("IO_LEAK").status("ALL_OFF");

        leakageTasks.add(lowSetting)
                    .add(connectPpmu)
                    .add(lowMeasure)
                    .add(highSetting)
                    .add(highMeasure)
                    .add(disconnectPmu);
        leakageTasks.execute();
    ON_FIRST_INVOCATION_END();

    DOUBLE iilIo0 = lowMeasure.getValue("IO0");
    DOUBLE iihIo0 = highMeasure.getValue("IO0");

    TEST("IO0", "IIL_0P1V", iilIo0);
    TEST("IO0", "IIH_1P7V", iihIo0);
    return S_OK;
}
```

如果 `IO_LEAK` 包含多个 pin，应按当前项目的 pin 列表工具逐 pin 调用 `getValue()` 和 `TEST()`。不要只读取 `IO0` 后把这个数值写给整组 pin。

### 4.3 代码执行前必须建立的 DUT 状态

1. 按数据手册打开相关电源域，并检查 IDD 没有触发保护。
2. 用短 pattern 或寄存器写入把双向 pin 配成输入或 Hi-Z。
3. 把非目标输入固定到不会引起大电流的批准状态。
4. 确认板上 pull-up、pull-down、ESD 器件和 socket 污染电流是否会进入结果。
5. 断开目标 pin 的数字 driver，再连接 PPMU。

### 4.4 输出 Leakage

输出 leakage 的目标是输出处于 Hi-Z 时的漏电流，因此必须先关闭输出级。测量代码与 input leakage 相似，但前置 pattern 不同。若输出仍在主动驱动，PPMU 测得的是输出级电流，不是 `IOZH` 或 `IOZL`。

### 4.5 预期结果

教学例中，`IO0` 的结果可能为：

```text
IIL_0P1V  IO0  Site1  -0.10 uA  PASS
IIH_1P7V  IO0  Site1  +0.22 uA  PASS
```

这只是期望的 Datalog 形态，不是本机执行日志。正式记录还应包含 test number、program revision、site、temperature、low/high limits 和单位。

## 5. VOH／VOL：先建立输出状态，再施加规定电流

数字 comparator 只能说明输出越过门限。数据手册中的 `VOH @ IOH` 和 `VOL @ IOL` 要求在规定输出电流下测量电压。

### 5.1 Test Suite 分工

建议把 DUT 状态和参数测量写清楚：

| Suite | Pattern 停止状态 | DC 动作 | 结果 |
| --- | --- | --- | --- |
| `ts_voh_dout` | `DOUT=1` | 施加 `IOH`，测量 V | `VOH_AT_IOH` |
| `ts_vol_dout` | `DOUT=0` | 施加 `IOL`，测量 V | `VOL_AT_IOL` |

pattern 的最后状态必须在 PMU 测量期间保持。若当前平台在 pattern 结束后自动恢复 pin 状态，应使用已批准的 stop-cycle、dc-sublabel 或 Operating Sequence 方法，不能依赖偶然保留的最后一个 vector。

### 5.2 VOH 教学代码

下面代码假设 `DOUT` 已由同一 suite 的前置动作稳定为高电平，数字 driver 已断开。`-1 mA` 只是教学方向；目标机台若使用相反约定，应改变符号。

```cpp
// SmarTest 7 教学模板；前置 pattern 不在此代码块内。
HRESULT CDC_tests::measure_voh(double _result[4])
{
    PPMU_SETTING vohSetting;
    PPMU_RELAY connectPpmu;
    PPMU_RELAY disconnectPmu;
    PPMU_MEASURE vohMeasure;
    TASK_LIST vohTasks;

    ON_FIRST_INVOCATION_BEGIN();
        vohSetting.pin("DOUT").iRange("1mA");
        vohSetting.pin("DOUT")
                  .iForce(-1.0 mA)
                  .min(1.35 V)
                  .max(2.20 V);

        connectPpmu.pin("DOUT").status("PPMU_ON");
        connectPpmu.wait(1.0 ms);
        vohMeasure.pin("DOUT").execMode(TM::PVAL);
        disconnectPmu.pin("DOUT").status("ALL_OFF");

        vohTasks.add(vohSetting)
                .add(connectPpmu)
                .add(vohMeasure)
                .add(disconnectPmu);
        vohTasks.execute();
    ON_FIRST_INVOCATION_END();

    DOUBLE voh = vohMeasure.getValue("DOUT");
    TEST("DOUT", "VOH_AT_IOH", voh);
    return S_OK;
}
```

### 5.3 把 VOH 例子改成 VOL

先让 pattern 把 `DOUT` 稳定为低电平，然后修改以下字段：

| 字段 | VOH 教学值 | VOL 教学值 |
| --- | ---: | ---: |
| Force current | −1.0 mA | +1.0 mA |
| Voltage limits | 1.35 V～2.20 V | −0.20 V～0.45 V |
| Result object | `vohMeasure` | `volMeasure` |
| Test name | `VOH_AT_IOH` | `VOL_AT_IOL` |

真实 limits 还要考虑 tester 测量误差、DUT 规格的开闭区间规则以及 DUT board 压降。不要把 comparator 的 `VOH/VOL` 门限直接当成参数测试 limits。

## 6. IDD：DPS 维持电源并测量电流

SmarTest 7 历史培训资料明确说明：DPS 的 force voltage 来自 Level setup，`DPS_VFIM` 用于执行电流测量。也就是说，Test Method 不应偷偷把电源电压改成与当前 Levelset 不一致的值。

### 6.1 Level Eqnset 负责什么

```text
EQNSET 1 "power_levels"
  SPECS
    VDD        [V]
    IDD_LIMIT  [mA]

  DPSPINS VDD
    vout    = VDD
    ilimit  = IDD_LIMIT
    t_ms    = 4
    offcurr = act
```

对应的教学 Specset 可把 `VDD` 设为 1.80 V，把 `IDD_LIMIT` 设为 200 mA。`ilimit` 是否接受带 `[mA]` 单位的 spec，以及 `t_ms/offcurr` 的准确行为，必须查当前 DPS 板卡 TDC。上面只说明电源电压、保护和开关相关字段属于 Level setup；不要把它直接下载到未知 DUT。

### 6.2 Standby IDD 执行顺序

1. 选择正确的 Level Eqnset、Specset 和 Levelset。
2. 按批准次序上电并检查 Measure V。
3. 运行初始化 pattern。
4. 把 DUT 放入 standby 或静态状态。
5. 等待数据手册规定的稳定时间。
6. 使用 `DPS_VFIM` 读取电流。
7. 逐 site 记录数值。
8. 退出 standby，或在 flow 结束时安全下电。

### 6.3 SmarTest 7 教学代码

```cpp
// VDD 的 force voltage 已由当前 Levelset 建立。
HRESULT CDC_tests::idd_standby(double _result[4])
{
    ON_FIRST_INVOCATION_BEGIN();
        DPS_VFIM("VDD").execute(TM::PVAL);
    ON_FIRST_INVOCATION_END();

    DOUBLE idd = DPS_VFIM("VDD").getValue("VDD");
    TEST("VDD", "IDD_STANDBY", idd);
    return S_OK;
}
```

公开历史手册能够确认 `DPS_VFIM(pin).execute()`、`TM::PVAL`、`getValue(pin)` 这一类结果取得方式和 `TEST(DPS_VFIM(pin))` 的判断形式，但不同 SmarTest 7 版本可能返回不同的 Site Result 类型。若上面的 `DOUBLE` 行不能编译，从自动生成的 DPS 示例复制结果类型，不要强制转换。

只需要 pass/fail 和 Datalog、无需自己读取数值时，可以按当前版本支持的形式使用：

```cpp
DPS_VFIM("VDD").execute();
TEST(DPS_VFIM("VDD"));
```

### 6.4 Standby、Static、Dynamic 和 Power-up IDD 的区别

| 项目 | DUT 状态 | 测量设置重点 | 不能混淆的内容 |
| --- | --- | --- | --- |
| Standby IDD | 低活动或休眠 | 小量程、较长等待 | 唤醒电路是否仍运行 |
| Static IDD／IDDQ | 固定逻辑状态 | pattern 停止点一致 | 内部节点是否真的静止 |
| Dynamic IDD | pattern 循环 | 采样时间和平均方式 | 单次稳定读数不等于峰值 |
| Power-up current | 电源上升过程 | ramp、触发和浪涌 | 普通 `DPS_VFIM` 结果未必保留波形峰值 |

若要求观察瞬态波形或浪涌峰值，应使用目标 DPS 板卡支持的采样、触发或 waveform 功能。不要把一次稳定电流读取描述成动态峰值测量。

### 6.5 多 Site 供电

使用共享 DPS 时，测得的可能是多个 DUT 的合计电流。只有每个 site 使用独立电源资源，或软件能明确分离通道结果时，才能把结果作为单颗 DUT 的 IDD。

## 7. 输入门限 VIH／VIL 的搜索方法

VIH／VIL 不是简单的 comparator 设置。参数测试需要改变 DUT 输入电压，同时执行能观察逻辑状态的功能操作，寻找 pass 与 fail 的转折位置。

### 7.1 二分搜索流程

```text
准备 DUT 和功能 pattern
  -> 设置输入电压为区间中点
  -> 执行一次短功能测试
  -> 根据 pass/fail 缩小电压区间
  -> 达到电压步长或最大次数后停止
  -> 恢复 nominal Level Spec
```

### 7.2 与平台 API 分离的 C++ 算法

下面代码只实现二分搜索计算。`runAtVoltage()` 必须由项目使用当前版本的 Level Spec API 和功能测试 API 实现；该函数名不是 Advantest API。

```cpp
// 纯算法教学代码，不直接控制 tester。
double findTransition(double lowV, double highV, double resolutionV)
{
    while ((highV - lowV) > resolutionV) {
        const double midV = 0.5 * (lowV + highV);

        const bool passed = runAtVoltage(midV);
        if (passed) {
            highV = midV;
        } else {
            lowV = midV;
        }
    }

    return highV;
}
```

这个例子适合搜索“电压升高后从 fail 变成 pass”的 VIH。搜索 VIL 时，pass/fail 方向可能相反，应根据 pattern 观察的逻辑状态改写区间更新规则。

> [!warning] 必须恢复 nominal 值
> 搜索正常结束、失败、用户 abort 或异常退出时，都要恢复 nominal Level Spec。否则下一个 Test Suite 可能继续使用最后一次搜索电压。

## 8. Pattern-Controlled DC 测量

当测量必须发生在 pattern 内的准确位置，例如 DDR 输出电阻或协议运行期间的电流，可以使用 pattern-controlled DC 思路。Advantest 官方历史应用资料把它分成三部分：Test Method 建立 PMU 和 relay 动作，pattern 中的 anchor point 调用 dc-sublabel，Test Method 执行 pattern 并读取结果。

下面是依据该结构重新写成的教学骨架：

```cpp
PPMU_SETTING dcSetting;
PPMU_RELAY closePpmu;
PPMU_RELAY openPmu;
PPMU_MEASURE dcMeasure;
PATTERN_CONTROLLER patternCtrl;
DC_RESULT_ACCESSOR dcResult;

ON_FIRST_INVOCATION_BEGIN();
    dcSetting.pin("DQ_MEAS")
             .vForce(0.90 V)
             .iRange("1mA")
             .min(-1.0 mA)
             .max(+1.0 mA);

    closePpmu.pin("DQ_MEAS").status("PPMU_ON");
    closePpmu.wait(0.3 ms);
    openPmu.pin("DQ_MEAS").status("ALL_OFF");
    dcMeasure.pin("DQ_MEAS").execMode(TM::PVAL);

    patternCtrl.label("DC_PRE").add(dcSetting);
    patternCtrl.label("DC_MEASURE").add(closePpmu).add(dcMeasure);
    patternCtrl.label("DC_POST").add(openPmu);

    CONNECT();
    patternCtrl.execute();
    dcResult.uploadResult("DQ_MEAS", TM::RESULT_INDEX);
ON_FIRST_INVOCATION_END();

ARRAY_D values = dcResult.getValues("DQ0");
DOUBLE firstPoint = values[0];
TEST("DQ0", "DC_POINT_0", firstPoint);
```

这段代码说明对象关系，不是完整项目文件。`DC_PRE`、`DC_MEASURE`、`DC_POST` 必须先按当前 Pattern Editor 规则建立；`uploadResult()` 参数、pin list 类型和数组结果应从目标版本示例复制。官方资料中的 1024 个测量点和 250 µs 行为只针对该文档描述的 HSM3G 方法，不能直接推广到 PS1600 或其他板卡。

本地资料：[[参考资料/官方公开资料/V93000_HSM3G_Pattern_Controlled_DC_Measurement_2011.pdf|Advantest／Verigy HSM3G pattern-controlled DC 应用资料]]。

## 9. SmarTest 8 Java 应怎样改写

Advantest 当前培训说明 SmarTest 8 使用 Java Test Method 完成标准数字和 DC 测试，但公开课程页面没有给出能确认包名、类名和方法签名的完整代码。不同 TML 和板卡插件也可能提供不同接口，因此本章不创造一个看似能编译的 Java 仪器 API。

### 9.1 对象职责对照

| SmarTest 7 教学对象 | SmarTest 8 项目中需要找到的对象 |
| --- | --- |
| `PPMU_SETTING` | DC setup 或 PMU action 配置对象 |
| `PPMU_RELAY` | relay／connect action 或 Operating Sequence 动作 |
| `PPMU_MEASURE` | measurement action 和 per-site result 对象 |
| `TASK_LIST.execute()` | setup／Operating Sequence 的执行入口 |
| `getValue(pin)` | 按 site、signal 或 pin 读取数值的接口 |
| `TEST()` | test table／Datalog 提交接口 |

### 9.2 从 Workcenter 建立代码的步骤

1. 在当前 device project 中使用 `New > Test Method` 或公司提供的 generator 建立类。
2. 选择已安装的 DC／PPMU／DPS Test Method Library 示例，不从网页手写 import。
3. 在 `setup` 阶段取得 suite 绑定的 setup、signal group、limits 和等待参数。
4. 在执行阶段调用该库的 connect、force、measure 和 disconnect 动作。
5. 从 result object 按 active site 读取数值。
6. 把值连同 test name 和单位提交到 test table／Datalog。
7. 在异常处理或库规定的 cleanup 阶段恢复 relay 与 force。
8. 用 `Help > Help Contents` 搜索所用类名，逐项核对方法签名和单位类型。

### 9.3 Java 结果处理示例

下面只演示与 tester API 无关、可以单独检查的 limits 逻辑。`measuredAmpere` 应由当前 TML 的 per-site result object 提供。

```java
public final class DcLimitCheck {
    public static boolean withinClosedLimits(
            double measuredAmpere,
            double lowAmpere,
            double highAmpere) {
        if (!Double.isFinite(measuredAmpere)) {
            return false;
        }
        return measuredAmpere >= lowAmpere
                && measuredAmpere <= highAmpere;
    }

    private DcLimitCheck() {
    }
}
```

量产项目应优先让 test table 或批准库执行最终判断。上面的函数适合教学或前置检查，不能替代项目对开区间、闭区间、NaN、overflow 和 datalog 的规定。

## 10. 离线检查与第一次在线运行

### 10.1 离线能检查什么

历史 SmarTest 资料说明 Hardware Response Emulator 可为 `PMU_IFVM`、`PMU_VFIM`、`DPS_VFIM` 和 `PPMU_MEASURE` 提供预先准备的结果。离线阶段可以检查：

- Test Method 是否编译；
- Test Suite 参数和 test name 是否存在；
- pass/fail 分支是否正确；
- 多 Site 结果是否写入各自 site；
- 断开和下电动作是否在流程中出现；
- 假设结果为 NaN、超 limits 或缺少 pin 时，代码是否安全失败。

离线结果不能证明真实电压、电流 limits、接触、relay 稳定时间或 DUT 安全性已经确认。

### 10.2 第一次在线运行顺序

1. 不装 DUT，确认所有 force 关闭并检查 DUT board 短路。
2. 只启用一个 site，使用已批准的低风险样品。
3. 单独运行 continuity，保存每 pin 数值。
4. 上电后立即检查 DPS voltage 和 current。
5. 单独运行低端 leakage，再运行高端 leakage。
6. 单独运行 VOH 或 VOL，并先确认电流方向。
7. 运行 standby IDD；dynamic IDD 在基本功能稳定后再加入。
8. 测量完成后确认 PPMU、HPPMU、DPS 和数字 pin 均回到批准状态。

## 11. 常见失败

| 现象 | 可能原因 | 检查 | 处理 |
| --- | --- | --- | --- |
| 编译器不认识 `uA` 或 `ms` | Test Method 模板 include 或单位机制不同 | 与自动生成示例比较 | 使用当前模板和 TDC 写法 |
| `getValue()` 类型不匹配 | SmarTest 版本或多 Site 容器不同 | 查看函数返回类型 | 复制当前 SDK 示例的结果类型 |
| Continuity 全部接近 clamp | 未接触、force 路径开路或极性错误 | 空板、已知良品和单 pin 对比 | 修复接触或方法极性 |
| Continuity 全部接近 0 V | 板级短路、公共保护器件或 relay 状态错误 | 断电测电阻并分组测试 | 排除硬件问题后再运行 |
| Leakage 整组偏大 | 数字 driver 未断开、板上电阻或污染 | 查看 relay，测空板 | 修正 pin 状态或清洁硬件 |
| VOH／VOL 数值反常且电流很大 | 电流符号错误或输出状态不对 | 立即 force 0，检查 pattern | 用已知电阻确认符号 |
| IDD 达到 current limit | 短路、上电顺序错误或保护值过小 | 立即下电并检查电源域 | 排除原因后按批准值重测 |
| 所有 site 得到同一数值 | 只读取一个 site 或共享 DPS | 查看结果容器和供电结构 | 使用 per-site 访问或标明合计电流 |
| 下一项测试受影响 | force 未回 0 或 relay 未断开 | 查看任务最后动作 | 在正常和异常出口恢复资源 |

## 12. 练习与答案

### 12.1 Continuity 分组

> [!question] 为什么 `VDD`、`GND`、普通数字 I/O 和模拟 pin 不应直接使用同一组 continuity 条件？

> [!note]- 参考答案
> 它们的内部结构、外部连接和可承受 force 不同。电源 pin 可能连接去耦电容，GND 是低阻节点，模拟 pin 可能没有与数字 I/O 相同的保护结构。应按电路类型分别确定电流方向、clamp、settling 和 limits。

### 12.2 Leakage 量程

> [!question] 预计 leakage 不超过 0.8 µA，为什么不应直接选择 40 mA range？

> [!note]- 参考答案
> 40 mA range 虽然不会溢出，但其分辨率和误差不适合观察 µA 级电流。应选择能覆盖正常值和合理异常余量的较小量程，同时检查短路保护。

### 12.3 IDD Site 结果

> [!question] 两个 site 共用一个 DPS，测得 120 mA。可以把每个 site 都记录为 60 mA 吗？

> [!note]- 参考答案
> 不可以。两个 DUT 的电流不一定相同，共享通道只给出合计值。需要独立供电、逐 site 重测或使用能分离各 site 电流的硬件方案。
