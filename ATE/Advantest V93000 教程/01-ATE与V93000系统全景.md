# ATE 与 V93000 系统全景

本章建立最小但完整的自动测试设备模型。完成后，读者应能区分 wafer sort、final test、characterization 和 production test，并能说明 V93000 的可扩展平台为什么同时包含数字、DC、模拟、RF 和高速 I/O 资源。

## 1. ATE 在半导体制造中的位置

ATE（Automatic Test Equipment，自动测试设备）通过测试程序控制激励和测量仪器，对 DUT（Device Under Test，被测器件）执行规定的测试并输出数值、通过/失败结果和分档信息。

测试通常出现在两个制造阶段：

| 阶段 | 接触方式 | 主要目的 | 常见配套设备 |
| --- | --- | --- | --- |
| Wafer Sort / Probe | 探针接触晶圆焊盘或凸点 | 在封装前识别失效 die，收集晶圆位置数据 | prober、probe card、温控设备 |
| Final Test | socket 接触已封装器件 | 检查封装后电气性能、功能和速度 | handler、load board、温控设备 |

工程阶段还会执行 characterization。它通过改变电压、频率、时序或温度观察器件余量，目的是了解器件行为，不应把 characterization 得到的最大工作点直接当作量产测试条件。

## 2. 一次测试真正发生了什么

一次测试可以拆成七个对象：

1. 测试计划规定测试项目、条件、限值和顺序。
2. 测试程序把计划转换成可执行对象。
3. 测试机仪器产生电压、电流和数字波形。
4. DUT board 或 probe card 把仪器连接到 DUT。
5. handler 或 prober 放置器件并报告 site 状态。
6. 测试程序读取测量值或数字比较结果。
7. 数据记录和分档规则决定 soft bin、hard bin 及后续处理。

> [!warning] 通过结果不等于产品已经得到完整证明
> 某个 Test Suite 显示 pass，只说明该次执行的输入、设置、测量和限值组合没有触发失败。还要检查校准、接触、程序版本、测试覆盖范围、相关性和温度条件。

## 3. V93000 的平台思路

Advantest 将 V93000 定位为可扩展 SoC 测试平台。当前产品页将平台分为多种 tester class，板卡、DUT board 和测试程序可在兼容配置间复用；SmarTest 8 是核心软件环境。[Advantest V93000 产品页](https://www.advantest.com/en/products/semiconductor-test-system/soc/v93000/)

从学习角度，可把平台拆成四层：

| 层次 | 典型对象 | 读者首先要问的问题 |
| --- | --- | --- |
| 控制层 | Linux 工作站、SmarTest 8、许可 | 当前软件和许可支持哪些功能？ |
| 测试头层 | tester class、card cage、时钟和基础设施 | 有多少槽位、供电和冷却能力？ |
| 仪器层 | PS1600、DPS128、AVI64、Wave Scale、RF 等 | 每个 DUT 信号需要哪类仪器？ |
| 接口层 | pogo、DUT board、socket、probe card | 信号经过哪些接点和保护器件？ |

## 4. Smart Scale 与 EXA Scale

V93000 经历了多代平台。PS1600 和 DPS128 主要与 Smart Scale 配置相关；当前高端产品则采用 EXA Scale、Pin Scale 5000 和 XPS256 等资源。Advantest 表示现有 Smart Scale 的仪器、DUT board 和测试程序可在兼容条件下向 EXA Scale 过渡，但“平台兼容”不代表每个测试程序可以不经核对直接运行。[Advantest V93000 EXA Scale 概览](https://www.advantest.com/en/products/semiconductor-test-system/soc/v93000/)

迁移时至少核对：

- 仪器型号、通道能力和许可；
- level/timing 的可编程范围与精度；
- pattern 内存和 X-mode 约束；
- DUT board 接口和 pogo 分配；
- Test Method API 与软件版本；
- datalog、test table 和生产接口行为。

## 5. 常见仪器怎样分工

| DUT 需求 | 首选资源类别 | 示例 | 不应混淆的对象 |
| --- | --- | --- | --- |
| 数字驱动与比较 | 通用数字 pin electronics | PS1600 | DPS 不是高速数字驱动器 |
| 小电流引脚参数测量 | 每引脚 PMU / HPPMU | PS1600 PPMU、系统 HPPMU | PPMU 不适合给整颗大电流 DUT 长时间供电 |
| DUT 主电源 | Device Power Supply | DPS128、XPS256 | 数字 pin driver 不是主电源 |
| 精密或高压四象限 VI | 通用模拟/功率仪器 | AVI64、FVI16 | 具体电压和功率依板卡而变 |
| ADC/DAC 波形测试 | AWG / Digitizer | Wave Scale MX 等 | 数字 pattern 不等于模拟采样 |
| RF 测试 | RF source/measure | Wave Scale RF 等 | RF 端口需要专门校准和射频接口 |

## 6. Test Cell 不只有测试机

完整 Test Cell 还包括：

- tester 和工作站；
- DUT interface、load board 或 probe card；
- handler 或 prober；
- 温控设备；
- 外部继电器、外部仪器和安全互锁；
- 生产控制、程序发布、数据保存和设备状态系统。

任何一个组成部分发生变化，都可能改变测量结果。因此，测试程序版本不能脱离板卡配置、DUT board 版本、socket/probe card 批次和温度条件单独解释。

## 7. 一个最小测试计划

下面的表格只表示结构，尖括号内容必须由真实 DUT 资料给出。

| 顺序 | 测试项 | 激励/测量 | 通过条件 | 失败时先检查 |
| ---: | --- | --- | --- | --- |
| 1 | Contact / Continuity | 在未上电状态对信号引脚施加小电流并测压 | `<CONT_LOW>` 至 `<CONT_HIGH>` | socket、probe contact、pin 对应关系 |
| 2 | Power On | DPS 以受控斜率施加 `<VDD_NOM>` | 电压和限流状态正常 | force/sense、短路、上电顺序 |
| 3 | Leakage | PPMU 施加指定电压并测小电流 | `<ILEAK_MIN>` 至 `<ILEAK_MAX>` | 继电器状态、未驱动引脚、等待时间 |
| 4 | Reset Functional | 执行复位 pattern | 所有输出符合期望 | level、timing、pattern 极性 |
| 5 | Counter Functional | 执行计数 pattern | `Q[7:0]` 与期望一致 | strobe 位置、时钟、方向切换 |
| 6 | IDD | DPS 测量静态或动态电流 | `<IDD_MIN>` 至 `<IDD_MAX>` | DUT 状态、采样窗、并联电容 |
| 7 | Power Off | 停止数字驱动并按顺序下电 | 所有资源回到安全初态 | 残余电压、继电器、外部供电 |

## 8. 常见误区

| 现象或说法 | 问题 | 正确检查方式 |
| --- | --- | --- |
| “93K 都一样” | 不同代、tester class、板卡和许可差异很大 | 导出当前 system configuration 并与 TDC 对照 |
| “离线运行通过，所以可以上板” | 离线环境不施加真实电气量 | 先做限制检查、单 site 低风险 bring-up |
| “PS1600 能测电流，所以可以当电源” | PPMU 的用途和功率能力不同于 DPS | 依据电流、功率、动态响应和并行数选择仪器 |
| “Shmoo 最大点就是规格” | 余量图受样品、温度和设备条件影响 | 用产品规格和统计方案确定量产限制 |
