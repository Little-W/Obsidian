## PLIC（Platform-Level Interrupt Controller）硬件设计文档

本节详细介绍了PLIC（Platform-Level Interrupt Controller）模块的硬件设计，包括其寄存器定义、功能操作、各寄存器的作用及其与中断处理流程的关系。本文档结合代码实现细节，旨在为后续软件驱动开发和系统集成提供详实的硬件基础说明。

### 1. 总体架构与功能概述

PLIC模块作为片上系统（SoC）中的中断控制核心，负责管理多个外部中断源的优先级、使能、向量分发等功能。其主要任务是根据外部中断源的状态和优先级，筛选出当前最高优先级且被使能的中断，并将其相关信息（如中断服务函数入口、参数等）提供给处理器。PLIC支持灵活的中断优先级配置和动态的中断向量分配，极大提升了系统的可扩展性和实时响应能力。

### 2. 寄存器定义与功能说明

PLIC模块内部包含多个关键寄存器，分别用于中断使能、优先级配置、中断向量表、参数表以及当前中断状态的保存。下表汇总了主要寄存器的地址、位宽及功能：

| 名称       | 地址范围              | 位宽   | 说明                           |
| -------- | ----------------- | ---- | ---------------------------- |
| int_en   | 0x0000            | N    | 中断使能寄存器，每位对应一个中断源，1为使能，0为屏蔽  |
| mvec     | 0x0100            | 32   | 当前被许可中断源的中断处理函数入口地址          |
| marg     | 0x0104            | 32   | 当前被许可中断源的中断处理函数参数（通常为结构体指针）  |
| int_pri  | 0x1000~0x1000+N-1 | 8*N  | 各中断源优先级，每个8位，0~255，数值越大优先级越高 |
| vectable | 0x2000~0x2000+N-1 | 32*N | 各中断源的中断处理函数入口地址              |
| objtable | 0x3000~0x3000+N-1 | 32*N | 各中断源的中断处理函数参数                |

其中N为中断源数量（`PLIC_NUM_SOURCES`），所有寄存器均支持AXI总线访问，支持按字节写使能。

#### 2.1 int_en（中断使能寄存器）

int_en寄存器用于控制各中断源的使能状态。每一位对应一个中断源，写1表示使能该中断源，写0则屏蔽。该寄存器的写操作支持按字节写入，便于批量或分组配置。其地址为0x0000，位宽为N位（N为中断源数量），高位补零对齐32位。

#### 2.2 int_pri（中断优先级寄存器）

int_pri为每个中断源分配8位优先级，范围0~255。优先级数值越大，优先级越高。该寄存器组的基地址为0x1000，连续分布，每个中断源占用1字节。写操作同样支持按字节写入，便于灵活调整优先级。PLIC内部通过二分查找算法（见`find_max_id`函数）实时选出当前所有被使能且有中断请求的源中优先级最高者。

#### 2.3 vectable（中断向量表）

vectable为每个中断源分配32位空间，用于存储该中断源对应的中断服务函数（ISR）入口地址。基地址为0x2000，连续分布，每个中断源占用4字节。CPU在处理中断时，可通过读取mvec寄存器获得当前最高优先级中断的ISR入口地址，vectable则为其提供静态配置。

#### 2.4 objtable（中断参数表）

objtable为每个中断源分配32位参数空间，通常用于存储ISR的输入参数（如结构体指针）。基地址为0x3000，连续分布，每个中断源占用4字节。CPU在处理中断时，可通过读取marg寄存器获得当前中断的参数，objtable则为其提供静态配置。

#### 2.5 mvec与marg（当前中断状态寄存器）

mvec和marg分别用于保存当前被许可中断源的ISR入口地址和参数。mvec位于0x0100，marg位于0x0104。每当有新的中断被许可时，PLIC会自动将对应vectable和objtable的内容写入mvec和marg，供CPU读取和跳转。

### 3. 中断处理流程与操作机制

PLIC的中断处理流程如下：

1. **中断源输入与使能判断**  
   外部中断源通过`irq_sources`输入，PLIC首先与int_en寄存器进行按位与操作，屏蔽未使能的中断源。

2. **优先级筛选**  
   对所有被使能且有中断请求的中断源，PLIC通过`find_max_id`函数（递归二分查找）选出优先级最高的中断源。若有多个中断源优先级相同，则优先选择编号小者。

3. **中断状态寄存器更新**  
   在时钟上升沿，若有中断被许可（irq_valid为1），PLIC自动将该中断源的vectable和objtable内容分别写入mvec和marg寄存器。irq_id寄存器保存当前最高优先级中断源编号。

4. **CPU读取与响应**  
   CPU通过AXI接口读取mvec和marg，获得ISR入口地址和参数，随后跳转执行对应中断服务函数。中断服务函数执行完毕后，CPU可通过软件方式清除中断请求或调整int_en/int_pri等寄存器，实现中断响应的闭环。

5. **寄存器读写操作**  
   所有寄存器均支持AXI总线访问，写操作支持按字节写使能（wstrb），便于灵活配置。读操作则根据raddr地址自动选择对应寄存器或寄存器组内容返回。

### 4. 代码实现要点与设计细节

- **优先级选择算法**  
  采用递归二分查找（`find_max_id`）实现高效的优先级筛选，保证在中断源数量较多时仍能快速响应。
- **寄存器复位与初始化**  
  所有寄存器在复位时均清零，优先级、向量表、参数表等均初始化为0，保证系统上电后处于安全状态。
- **写操作的字节使能**  
  写操作支持wstrb按字节写入，便于软件批量或分组配置寄存器，提升灵活性。
- **中断状态自动更新**  
  mvec和marg寄存器在有新中断被许可时自动更新，无需软件干预，提升中断响应实时性。
- **寄存器映射与地址解码**  
  所有寄存器均采用统一的地址映射，便于软件驱动开发和调试。地址解码逻辑支持灵活扩展中断源数量。
