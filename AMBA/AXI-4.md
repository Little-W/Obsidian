## 1. 信号说明

### 读地址通道（AR Channel）
- **ARADDR**  
  读请求的地址信号，由主设备在发起读取操作时发送到从设备。

- **ARVALID**  
  主设备用来指示发出的地址有效。当 ARVALID 为高时，表示 ARADDR 信号传输的地址有效。

- **ARREADY**  
  从设备用来应答主设备。若 ARREADY 为高，说明从设备已就绪，接收主设备发送的地址。

### 读数据通道（R Channel）
- **RDATA**  
  从设备返回的数据，数据的具体内容由从设备提供。

- **RVALID**  
  从设备用来标识返回的数据有效。当 RVALID 为高时，表示 RDATA 中的数据有效。

- **RLAST**  
  指示当前数据传输是否为最后一次数据传输。对于多数据传输的读取操作，在最后一个数据传输时拉高 RLAST。

- **RREADY**  
  主设备用来应答从设备，表示自身已准备好接收返回数据。当 RREADY 为高时，配合 RVALID 确保数据传输完成。

## 2. 读取时序过程详解

### 读地址传输阶段
1. 主设备把读地址（ARADDR）放到地址线上，并将 **ARVALID** 置高，表示地址有效。
2. 从设备检测到 **ARVALID** 后，如果已经就绪，则将 **ARREADY** 置高，表示能够接收该地址。
3. 一旦主设备检测到 **ARREADY** 为高，读地址传输阶段完成，双方完成握手。

### 读数据传输阶段
1. 接收到读地址后，从设备开始准备对应数据。
2. 当数据准备就绪后，从设备将数据放在 **RDATA** 上，并将 **RVALID** 置高，表示数据有效。
3. 主设备在检测到 **RVALID** 后将 **RREADY** 置高，响应从设备的数据传输请求。
4. 当传输多于一个数据周期的传输时，**RLAST** 仅在最后一个数据周期拉高，以表明本次传输结束。

## 3. 简单的时序图示例

下面给出一个基于文本的时序图示例，帮助理解各信号随时间的变化（时间从上到下表示时序的进展）。

下面给出一个横向时钟周期的时序图示例，表格中每一列代表一个时钟周期（T0、T1、T2……Tn），每一行表示一个信号的状态变化。

| 信号    | T0                    | T1                    | T2                    | T3                    | …                   | Tn                      |
|---------|-----------------------|-----------------------|-----------------------|-----------------------|---------------------|-------------------------|
| ARADDR  | A（读地址）         | A（保持有效）        | -                     | -                     | …                   | -                       |
| ARVALID | 1（地址有效）       | 1（等待握手）        | 0                     | 0                     | …                   | 0                       |
| ARREADY | 0                     | 1（握手响应）       | -                     | -                     | …                   | -                       |
| RDATA   | -                     | -                     | D1（第一数据）        | D1（保持数据）        | …                   | Dn（最后数据）          |
| RVALID  | -                     | -                     | 1（数有效）          | 1（保持有效）        | …                   | 1                       |
| RREADY  | -                     | -                     | 0（未响应）          | 1（主设备响应）       | …                   | 1                       |
| RLAST   | -                     | -                     | 0（非结束周期）      | 0（非结束周期）      | …                   | 1（传输结束）           |


**说明：**

1. **读地址传输阶段：**  
   - T0 时，主设备将读地址 A 送出，并将 ARVALID 置为 1。  
   - T1 时，从设备检测到 ARVALID，为接收该地址信号，将 ARREADY 置为 1，完成握手。后续时钟周期中，ARADDR、ARVALID 和 ARREADY 恢复空闲/无效状态。

2. **读数据传输阶段：**  
   - 从 T2 开始，从设备送出数据 D1，同时将 RVALID 置为 1，但主设备在 T2 可能还未发出响应（RREADY 为 0）。  
   - 在 T3 时，主设备检测到 RVALID 后，将 RREADY 置为 1，完成数据传输。  
   - 多周期数据传输中，最后一个数据周期（Tn），从设备会同时将 RLAST 置为 1，表示数据传输结束。

该表格横向展示了各时钟周期信号状态的变化，有助于直观理解 AXI 读取时序的过程。

## 4. 总结

- 读取时序过程中，地址通道和数据通道相互独立，通过握手信号（ARVALID/ARREADY 和 RVALID/RREADY）实现数据同步。
- 主设备负责发起读请求并响应数据有效信号，而从设备负责接受地址并按顺序输出数据，最后用 RLAST 标识结束传输。

这个解读和时序图示例有助于理解 AXI 协议中读取操作的时序过程及各个信号的作用。

下面给出一个详细总结 AXI 总线写入时序的说明，并使用横向时钟周期绘制一个简单的时序图示例。

### 1. 信号说明

#### 写地址通道（AW Channel）
- **AWADDR**  
  写请求的地址信号，由主设备在发起写操作时发送到从设备。
- **AWVALID**  
  主设备用来指示写地址有效。当 AWVALID 为高时，表示 AWADDR 信号传输的地址有效。
- **AWREADY**  
  从设备用来应答主设备。若 AWREADY 为高，说明从设备已就绪，接收写地址。

#### 写数据通道（W Channel）
- **WDATA**  
  主设备写入的数据。
- **WVALID**  
  主设备用来标识写数据有效。当 WVALID 为高时，表示 WDATA 中的数据有效。
- **WREADY**  
  从设备用来应答主设备，表示自身已准备好接收写数据。当 WREADY 为高时，数据传输将进行。
- **WLAST**  
  用于指示当前写数据传输是否为最后一次传输。在传输多数据周期中，最后一个周期将 WLAST 拉高。

#### 写响应通道（B Channel）
- **BRESP**  
  从设备返回的写响应码，用于指示写操作结果。
- **BVALID**  
  从设备用来标识写响应有效。当 BVALID 为高时，表示 BRESP 中的响应有效。
- **BREADY**  
  主设备用来应答写响应，表示已准备好接收写响应。

### 2. 写入时序过程详解

AXI 写入操作通常分为三个阶段：
- **写地址传输阶段：**  
  主设备发送写地址并置高 AWVALID，从设备在就绪后置高 AWREADY 完成握手。
- **写数据传输阶段：**  
  在地址阶段握手完成后，主设备沿 WDATA 总线送出数据，同时拉高 WVALID；从设备在就绪时置高 WREADY进行数据传输，多周期传输时在最后一个周期将 WLAST 拉高。
- **写响应阶段：**  
  数据传输完成后，从设备通过 B 信道返回写响应，主设备检测 BVALID 后置高 BREADY，完成写入操作。

### 3. 横向时钟周期时序图示例

下面给出一个简单的时序表，横向表示时钟周期（T0 至 T5），每一行表示不同的信号状态变化：

| 信号    |  T0                      | T1                      | T2                        | T3                        | T4                         | T5                          |
|---------|--------------------------|-------------------------|---------------------------|---------------------------|----------------------------|-----------------------------|
| AWADDR  | A（写地址）            | A（保持有效）           | -                         | -                         | -                          | -                           |
| AWVALID | 1（地址有效）          | 1（等待握手）           | 0                         | 0                         | -                          | -                           |
| AWREADY | 0                       | 1（握手响应）          | -                         | -                         | -                          | -                           |
| WDATA   | -                       | -                       | D1（第一数据）            | D1（保持数据）            | Dn（最后数据）             | Dn（保持）                  |
| WVALID  | -                       | -                       | 1（数据有效）             | 1（等待握手）             | 1（最后数据有效）           | 0                           |
| WREADY  | -                       | -                       | 0（未响应）              | 1（握手响应）             | 1                          | -                           |
| WLAST   | -                       | -                       | 0（非结束周期）          | 0（非结束周期）           | 1（传输结束）              | -                           |
| BRESP   | -                       | -                       | -                         | -                         | -                          | R（写响应）                |
| BVALID  | -                       | -                       | -                         | -                         | -                          | 1（响应有效）              |
| BREADY  | -                       | -                       | -                         | -                         | -                          | 1（主设备响应）            |

**说明：**

1. **写地址传输阶段（T0～T1）：**  
   - T0 时，主设备将写地址 A 送出，并将 AWVALID 置为 1；  
   - T1 时，从设备检测到 AWVALID 后，置高 AWREADY 表示就绪，完成地址通道握手。

2. **写数据传输阶段（T2～T4）：**  
   - T2 时，主设备在 WDATA 送出第一数据 D1，并将 WVALID 置高；  
   - T3 时，从设备检测到 WVALID 后置高 WREADY，完成数据传输；  
   - T4 时，主设备送出最后一个数据，并将 WLAST 同时置高，表明数据传输结束。

3. **写响应阶段（T5）：**  
   - T5 时，从设备通过 B 通道返回写响应 BRESP，同时拉高 BVALID；  
   - 主设备检测响应有效后置高 BREADY，完成写响应握手。
