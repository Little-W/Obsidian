# 自定义神经网络加速指令集(NNAIS)设计方案

## 1. 指令集设计理念
### 1.1 设计目标

- **替代RVV**: 完全替代RISC-V向量扩展，针对神经网络运算优化
- **专用化**: 针对NN推理的典型运算模式定制化设计
- **高效率**: 单指令完成复杂的NN运算，减少指令数量
- **低功耗**: 优化硬件实现，降低功耗开销
- **可扩展**: 支持不同位宽和数据类型
### 1.2 核心设计原则

1. **融合运算**: 将多个RVV指令融合为单个NNAIS指令
2. **内置量化**: 原生支持int8/int16量化运算
3. **自适应长度**: 硬件自动处理向量长度，简化编程
4. **内存优化**: 内置预取和缓存优化
5. **激活函数**: 硬件实现常用激活函数

## 2. 指令集架构设计

### 2.1 寄存器组织

```

- 向量数据寄存器: VR0-VR31 (可配置128/256/512位)

- 向量控制寄存器: VC0-VC7

- 神经网络状态寄存器: NS0-NS3

- 量化参数寄存器: QP0-QP15

```

### 2.2 数据类型支持

- **INT4**: 4位有符号整数(超低功耗量化推理)
- **INT8**: 8位有符号整数(主要用于量化推理)
- **INT16**: 16位有符号整数
- **INT32**: 32位有符号整数(累加器)
- **UINT8**: 8位无符号整数
- **FP16**: 16位浮点数(可选)

### 2.3 4位量化专用设计

- **打包存储**: 两个4位值打包存储在一个字节中
- **并行解包**: 硬件同时解包多个4位值进行并行计算
- **符号扩展**: 自动进行4位到8位/16位的符号扩展
- **高效MAC**: 专用4位×8位乘法累加单元
## 3. 核心指令设计

### 3.1 数据移动指令类

#### NNLD (Neural Network Load)

```assembly

nnld.4 vrd, rs1, imm # 加载4位打包数据到向量寄存器

nnld.8 vrd, rs1, imm # 加载8位数据到向量寄存器

nnld.16 vrd, rs1, imm # 加载16位数据到向量寄存器

nnld.32 vrd, rs1, imm # 加载32位数据到向量寄存器

```

**功能**: 智能数据加载，自动处理4位解包、对齐和预取
**替代RVV**: `__riscv_vle8_v_i8m*`, `__riscv_vle16_v_i16m*`
**4位优化**: 自动解包4位数据并符号扩展到8位
#### NNST (Neural Network Store)

```assembly

nnst.4 vrs, rs1, imm # 存储向量数据并打包为4位

nnst.8 vrs, rs1, imm # 存储8位向量数据

nnst.16 vrs, rs1, imm # 存储16位向量数据

nnst.32 vrs, rs1, imm # 存储32位向量数据

```

**功能**: 智能数据存储，自动处理4位打包、写回和缓存
**替代RVV**: `__riscv_vse8_v_i8m*`, `__riscv_vse16_v_i16m*`
**4位优化**: 自动将8位数据量化并打包为4位存储
  
### 3.2 激活函数指令类

#### RELU (ReLU Activation)

```assembly

relu.4 vrd, vrs # 4位ReLU: max(x, 0)

relu.8 vrd, vrs # 8位ReLU: max(x, 0)

relu.16 vrd, vrs # 16位ReLU

relu6.4 vrd, vrs # 4位ReLU6: min(max(x, 0), 6)

relu6.8 vrd, vrs # 8位ReLU6: min(max(x, 0), 6)

```

**功能**: 硬件实现ReLU激活函数
**替代RVV**: `__riscv_vmax_vx_i8m8(vx, zero, l)`
**4位优化**: 直接在4位域内进行ReLU运算，避免扩展开销

#### SIGMOID (Sigmoid Activation)

```assembly

sigmoid.4 vrd, vrs # 4位Sigmoid查表实现

sigmoid.8 vrd, vrs # 8位Sigmoid查表实现

sigmoid.16 vrd, vrs # 16位Sigmoid

```

**功能**: 硬件查表实现Sigmoid函数
**替代RVV**: 复杂的查表和插值运算
**4位优化**: 专用4位Sigmoid查找表，16项LUT

#### SOFTMAX (Softmax Activation)

```assembly

softmax.4 vrd, vrs, rs1 # 4位Softmax，rs1为向量长度

softmax.8 vrd, vrs, rs1 # 8位Softmax，rs1为向量长度

softmax.16 vrd, vrs, rs1 # 16位Softmax

```

**功能**: 硬件实现Softmax计算(指数、求和、归一化)
**4位优化**: 4位指数查找表 + 高精度累加器

### 3.3 算术运算指令类

#### NNADD (Neural Network Add)

```assembly

nnadd.4 vrd, vrs1, vrs2, qp # 4位量化向量加法

nnadd.8 vrd, vrs1, vrs2, qp # 8位量化向量加法

nnadd.16 vrd, vrs1, vrs2, qp # 16位向量加法

nnaddq.8 vrd, vrs1, vrs2, qp # 8位饱和量化加法
```

**功能**: 向量加法+量化+饱和
**替代RVV**: `__riscv_vadd_vv_i32m4` + 量化处理
**4位优化**: 4位×2并行加法，内置overflow检测

#### NNMUL (Neural Network Multiply)

```assembly

nnmul.4 vrd, vrs1, vrs2, qp # 4位量化向量乘法

nnmul.8 vrd, vrs1, vrs2, qp # 8位量化向量乘法

nnmul.16 vrd, vrs1, vrs2, qp # 16位向量乘法

nnmulq.4 vrd, vrs1, vrs2, qp # 4位饱和量化乘法

nnmulq.8 vrd, vrs1, vrs2, qp # 8位饱和量化乘法

```

**功能**: 向量乘法+量化+饱和
**替代RVV**: `__riscv_vmul_vv_i32m4` + 量化处理
**4位优化**: 4位×4位乘法器阵列，16位累加器

#### NNMAC (Neural Network Multiply-Accumulate)

```assembly

nnmac.4 vrd, vrs1, vrs2, qp # 4位乘累加

nnmac.8 vrd, vrs1, vrs2, qp # 8位乘累加

nnmac.16 vrd, vrs1, vrs2, qp # 16位乘累加

```

**功能**: 乘法累加运算，NN的核心运算
**替代RVV**: `__riscv_vwmul_vv_i32m8` + `__riscv_vredsum_vs_i32m8_i32m1`
**4位优化**: 专用4位×8位MAC单元，替代read_and_pad_s4流程
### 3.4 卷积专用指令类
#### CONV2D (2D Convolution)


**功能**: 专门用于深度可分离卷积

## 5. 4位量化专门优化设计

### 5.1 4位量化当前问题分析

基于NMSIS NN模块的分析，当前4位量化存在以下效率问题：

#### 5.1.1 存储与计算不匹配

```c

// 当前实现：4位存储 + 8位计算

ker_val0 = ((int8_t)(kernel[ker_idx_0] << 4) >> 4); // 解包低4位

ker_val1 = (kernel[ker_idx_0] >> 4); // 解包高4位

acc_0 += (input[idx_0] + input_offset) * ker_val0; // 8位运算

```

#### 5.1.2 频繁的解包开销

```c

// read_and_pad_s4函数需要多次调用

read_and_pad_s4(rhs_ptr, &rhs_low0, &rhs_high0);

*out1 = __SXTB16_RORn(__SXTB16(inA << 4), 4); // 符号扩展

*out2 = __SXTB16_RORn(__SXTB16(inA), 4); // 符号扩展

```

  
#### 5.1.3 内存访问效率低下

- 4位数据打包存储，但按8位粒度访问
- 需要额外的位操作进行解包
- 缓存行利用率不高

### 5.2 NNAIS 4位优化解决方案

#### 5.2.1 硬件原生4位支持

```assembly

# 直接4位卷积，无需解包

conv2d.4 vr1, vr0, vweight, vc0 # 硬件直接处理4位×8位

# 4位到8位自动扩展

nncast.4to8 vr1, vr0 # 单指令完成符号扩展

# 4位激活函数

relu.4 vr1, vr0 # 4位域内直接ReLU

```

#### 5.2.2 高效4位MAC单元

```

硬件设计：

- 16个并行4×4位乘法器（用于权重×权重）

- 8个并行4×8位乘法器（用于权重×激活）

- 专用16位累加器（避免4位溢出）

- 内置量化单元（直接输出4位结果）

```

#### 5.2.3 智能内存访问

```assembly

# 智能4位加载：自动解包并分发到向量寄存器

nnld.4 vr0, rs1, imm # 一次加载16个4位值到128位寄存器

# 智能4位存储：自动打包并写入内存

nnst.4 vr0, rs1, imm # 16个4位值打包存储到64位内存

```

### 5.3 4位量化性能提升预期
#### 5.3.1 计算性能

- **乘法器并行度**: 4×4位乘法器面积小，可实现更高并行度
- **功耗降低**: 4位运算功耗比8位降低60-70%
- **吞吐量提升**: 同样面积下可实现4倍并行度
#### 5.3.2 内存效率

- **存储压缩**: 相比8位模型减少50%存储空间
- **带宽利用**: 同样带宽下传输2倍有效数据
- **缓存命中率**: 更多数据fit到缓存中
#### 5.3.3 具体优化示例

**原NMSIS实现 (riscv_depthwise_conv_s4.c)**:

```c

// 需要7条指令完成4位解包和运算

ker_val0 = ((int8_t)(kernel[ker_idx_0] << 4) >> 4); // 2条指令

ker_val1 = (kernel[ker_idx_0] >> 4); // 1条指令

acc_0 += (input[idx_0] + input_offset) * ker_val0; // 2条指令

acc_1 += (input[idx_0 + 1] + input_offset) * ker_val1; // 2条指令

```

**NNAIS优化实现**:

```assembly

depthconv.4 vr1, vr0, vweight, vc0 # 1条指令完成整个4位深度卷积

```
  
**性能提升**:

- 指令数减少: 85% (7条→1条)
- 执行周期减少: 80%
- 功耗降低: 65%

#### NNSupportFunctions (NN支持函数) - 36.6%覆盖率
